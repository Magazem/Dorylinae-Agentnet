## Medium (fixed)

**M1. A nil `SessionOpen` skipped step 7 (fail-open).** `VerifyParams.SessionOpen == nil`
silently disabled the session check. If 2.2c or 2.3a forgets to wire it, a grant keeps
working after its session left `open`. That includes `closed` sessions whose row the
grantor has not yet revoked, and the `awaiting_result`/`quarantined` states, where grant.md
§Session end requires `session_not_open`. Confirmed: the vector verified with a nil
callback.
*Fix* (`internal/capability/verify.go`): a nil callback now rejects at step 7 with
`unknown_session` ("no session lookup configured"). The type's doc comment now says the
callback is required.
*Test:* `TestNilSessionOpenFailsClosed`.

**M2. A `sig` with embedded `\r`/`\n` verified, which gave a second wire form of a valid
token.** `encoding/base64` skips CR and LF even in `Strict()` mode. `"sig":"l3c5wKLJPH\n0B…"`
decoded to the same 64 bytes and Verify accepted it. Anyone holding a token can do this,
because `sig` is not signed. grant.md defines `sig` as base64url of 64 bytes and the wire form
as `canonical(token)`. The mutated token is not canonical. It could reach 2.2c's holder
dedupe ("different token under a known id → `grant.conflict`") and step 9's byte comparison.
Both currently fail closed, but only by luck of the storage path.
*Fix* (`token.go`, `verify.go`): `sigPattern = ^[A-Za-z0-9_-]{86}$`, checked at step 4
(`bad_signature`) before decoding.
*Test:* `TestSigWithNewlineRejected` (covers `\n`, `\r`, `\r\n`, `==` padding and the `+`
alphabet).

## Notes for later tickets

- **N1 (2.2c).** Verify accepts non-canonical input by design. Always store and compare
  `canonical(token)` rebuilt from the parsed token, never the raw bytes. Otherwise step 9's
  byte comparison and the holder's `grant.conflict` rule depend on how the sender formatted
  the JSON.
- **N2 (2.2c/2.3a).** `VerifyError.Err` can quote attacker bytes (the `ParseStrict`
  duplicate-key message). Audit and wire replies must carry only `ReasonOf(err)`, never
  `err.Error()` (grant.md §Audit).
- **N3 (2.2c).** Wire `SessionOpen` on both sides: the holder uses its mirror and the
  grantor its own store. The holder's orphan handling (`grant.orphan`) should key on
  `ReasonOf(err) == unknown_session` at step 7.
