## R55-103 (T12-01): mailbox keys after a forward clock step

Rules (`internal/mailbox/mailbox.go`):

1. **A future-dated current key is unusable.** `usable` returns false when the current key's
   `created` is later than `now + mail.MaxSkew` (10 min): the same bound a peer applies to the
   announcement (mail.md §Announcement check 5), so a key every peer refuses is never kept as
   current. Announcement and the next hourly `Rotate` then create a new key at the true time.
2. **A key is deleted by age only once a successor has been current for 7 days.** The age rule
   becomes: `not_after + 7 d ≤ now` **and** some newer live key has `created + 7 d ≤ now`.
   Peers seal to a key until they accept its successor, and mail sealed to it lives at most the
   7 d queue TTL after that. On a steady clock the successor is created at `t + 7 d`, so the
   second condition holds at `t + 14 d`, before the first (`t + 21 d`): the normal schedule is
   unchanged. In a stepped run the successor is the key just created (`created = now`), so the
   key peers seal to is kept. The `MaxLive = 3` cap is unchanged and still deletes the oldest.
- Backward step: the current key looks future-dated, so rule 1 rotates to a key dated at the
  stepped-back clock. That only happens when the clock is more than 10 min behind, when step 11
  already refuses all honest inbound mail as "from the future"; nothing is deleted by age
  (ages are measured on the stepped-back clock and rule 2 needs a 7-day-old successor), but
  the new key is a 4th live key, so the `MaxLive` cap deletes the oldest retired key (its
  successor has been current for at least 7 days; review 100 corrected the earlier "nothing
  is deleted"). After the correction, a key whose `created` is ≥ 7 d behind is rotated by the
  normal age rule.
- Review 100 (M1, L1) amended rule 2 and the cap: ages are measured at
  `min(now, newest mail_seen stamp)` (the D75 basis, `mail.SeenBasis`), so a forward step
  ages no key, including the one before the current key; with no mail nothing is deleted by
  age and `MaxLive` bounds the keys. The cap never deletes the current key and deletes a
  future-dated retired key first.
- Spec: `Docs/protocol/mail.md` §Lifecycle (two bullets).

## R55-053 (T12-02): `mail_seen` prune basis

Rules (`internal/mail/receiver.go`, `internal/retention/retention.go`):

1. **Stamp.** A new `mail_seen` row stores `received_at = min(now, msg.created + MaxSkew)`
   instead of `now`. Step 11 already gives `created − 10 min ≤ now`, so the stamp is within
   10 min of the signed `created` and never later than the receipt. This is the reviewer's
   "prune by the signed `created`" without a migration (the table has no `created` column).
2. **Cutoff.** Rows are pruned when `received_at < min(now, newest received_at) − 35 d`
   (`mail.SeenCutoff`). The newest stamp is bounded by a peer's signed `created`, i.e. by the
   peers' clocks, so a local forward step does not move the cutoff. Only pruning by `created`
   would not be enough: the reviewer's scenario (rows stored at the true time, one prune at
   `true + 31 d`) deletes them on either basis.
- Why it is safe: a pruned row has `created < basis − 35 d + 10 min ≤ now − 35 d + 10 min`, so a
  replay is refused by step 11 at any later clock that is not itself more than 5 days behind.
- The same cutoff is used by `agentnet prune` (`PruneSeenTx`, and the `mail_seen` cutoff
  `?2` in the plan and dry-run queries), so the two tables stay one dedupe set.
- Residual (documented): a peer whose own clock is stepped the same way, or that signs
  `created` near our stepped clock while our clock is wrong, can move the cutoff; it needs both
  a victim clock step and that peer. On an idle daemon the last 35 days of rows before the
  newest one are kept until new mail arrives (metadata only: peer key and mail id).
- Spec: `Docs/protocol/mail.md` §Dedupe and inbox (prune paragraph) and §Tables (comment on
  `received_at`), `Docs/protocol/retention.md` (the `mail_seen` prune rule).

## R55-151 (T12-03): one daemon clock

Rule: `daemon.Options.Now` (a test option, nil = `time.Now`) is the daemon's wall clock. It is
the default `Now` of the stores the handlers call (team, work-session, capability, debate,
request receive, device and approval when `DeviceNow` / `ApprovalNow` are unset) and is passed
to the IPC handlers and the grant mail kinds that read `time.Now()` today. Durations measured
with the monotonic clock stay on `time.Now()` (uptime, the prune approval TTL, fetch call
timers, the stop deadline). Files: `internal/daemon/daemon.go`, `grant.go`, `grant_kinds.go`,
`session.go`, `team.go`, `trust.go`, `request.go`, `request_lifecycle.go` (O-106), `notify.go`,
`status.go`, `ping.go`, `mail.go`. No spec change.
