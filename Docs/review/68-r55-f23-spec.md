## 1. Summary

The Agent Card verifier checks the Ed25519 signature over the card parsed generically by exact
member name. It then decodes the same bytes a second time with `encoding/json` into a struct,
and that decoder folds member names (ASCII case, U+212A→`k`, U+017F→`s`) and keeps the last
duplicate. So a card signed by K1 can come back as the card of K2 (R55-019). The fix is a spec
rule that implementations can test: **member names are matched exactly, the card has exactly
six members, and a skill has exactly three**. The schema step reads from the same generic object
the signature covered, and no second decode is allowed. Around this rule the spec now also
pins down:

- lone surrogate escapes (refused, not turned into U+FFFD);
- strict base64 in the independent verifier;
- the stored and forwarded card form (canonical `{card, signature}`, v1 and rosters too);
- four smaller peer-input and local-input leniencies: request `""` optional members, the
  `--artifact` JSON, device `at`, and `mail_submit` numbers.

The negative vectors in agent-card.md are byte-exact, and their signatures verify (checked in
a temp dir with a stand-alone canonicaliser; see §7).

## 3. Compatibility

**Honest cards are unaffected.** Every card in existence comes from `agentcard.New` and `Sign`:

- the `Card` and `Skill` structs marshal exactly 6 and 3 members, with `description` always
  present (no `omitempty`);
- keys and signatures use the strict encoder;
- the canonical writer emits no surrogate escapes.

So all of the following still verify:

- our own card, re-verified at every daemon start (`internal/identity/identity.go:185`);
- every v2 `peers.card`, which is stored canonical;
- every roster card sent by an honest owner of any version.

**Stored rows.** `peers.card` is not re-verified when read. It is re-parsed only by
`team.memberEntry` (`internal/team/store.go:658`) to build rosters. The rows that the new
rules affect are:

1. **v1 rows (`trust=relay`)** can hold relay-added top-level members (R55-073). They still
   verify, since top-level extras are ignored. From now on they are stripped when forwarded,
   and the migration of OD-3 rewrites them.
2. **A card that a hostile peer planted through T1-01** (folded members) is stored with its
   folded member (v2 stores the canonical card; roster introductions store the canonical
   entry). New members refuse a roster that carries it (`bad_body`). That is the intended
   effect, but it would also block the owner's honest roster updates to those members, so the
   owner must not send it (OD-3).
3. **Lone surrogate escapes** can only appear in raw v1 rows (canonical rows contain none).
   With rule 7 in `ParseStrict`, `memberEntry` would fail on such a row. The migration
   handles it.

**Mixed versions.**

- An old daemon receiving from a new one sees canonical `{card, signature}`, which it already
  accepts.
- A new daemon receiving from an old owner accepts roster cards with extra top-level members
  (ignored, then stripped before storing). It refuses only folded, surrogate or missing-member
  cards, which no honest old daemon produces.
- Old `mail_submit` callers never put lone surrogates on the wire: the old daemon turned them
  into U+FFFD before signing. So rule 7 in `ParseStrict` refuses nothing an honest peer sends.
- Request senders already omit empty optionals (`internal/request/wire.go:44-53,78-95`).
- Device senders already emit `wireTimeStr(now)` (`internal/daemon/device.go:412,521`).

**Stored mail bodies re-parsed with `ParseStrict`** (`request/view.go:190`, `cancel.go:180`,
`worksession/store.go:243`, `debate/store.go:372`) are canonical outputs, so rule 7 cannot
fail on them. `mail_inbox.signed` (received bytes, O-049) is never read back in production code.

## 4. Implementation plan

Order: after this spec, and before R55-F10 (both touch `agentcard.go`). One PR is fine. It
is peer input, so an Opus implementer and a security re-review are required.

1. **`internal/agentcard/canonical.go`**
   - Add `checkSurrogates(data []byte) error`. It scans the raw bytes and tracks the in-string
     state and escapes: after `\` it consumes one character, or `u` plus 4 hex digits. A high
     surrogate must be followed immediately by `\u` + a low one; any other surrogate is an
     error.
   - Call it from `ParseStrict` after `utf8.Valid`. The error text is `lone surrogate escape
     at byte N`.
   - Duplicate detection stays as it is (on decoded names). Update the comment to say that
     rules 7 and 8 are enforced.
2. **`internal/agentcard/agentcard.go`**
   - Replace the struct decode in `Verify` (`:205-211`) with `cardFromGeneric(card
     map[string]any) (Card, error)`. It requires exactly the 6 names (`len(card) == 6` plus a
     lookup of each exact name) and takes `version` as `json.Number` `"1"`. Each skill is a
     `map[string]any` with exactly `id`, `name` and `description`, all strings. The function
     then calls `c.validate()`.
   - Keep `Signed.Card.PublicKey == card["public_key"]` by construction.
   - Update the `Verify` doc comment.
   - `Canonical(c)` (marshal, then `ParseStrict`) is unchanged.
3. **`tools/verifycard/main.go`**
   - Use `base64.RawURLEncoding.Strict()`.
   - Add its own surrogate scan (the same rule, re-implemented; no shared code).
   - Add a schema step after the signature: the exact 6 and 3 members, version 1, text 1-128
     code points with no control characters (plus `description` 0-128), the created
     round-trip, and a 32-byte key.
   - Exit codes: 2 malformed (steps 1-3), 1 invalid (step 4 or 5, OD-2).
   - Update the doc comment.
4. **`tools/verifyvectors`**
   - Add `agent_card.cases` to `vectors.json`: 13 entries `{name, envelope, fails_at}`,
     transcribed from agent-card.md, with the P1 and N12 placeholders expanded.
   - Add `card.go` with this tool's own reading of Verification steps 1-5, including the
     surrogate scan and strict base64, and check that each case fails at its step (P1: passes).
   - Extend `parseValue` in `main.go` with the surrogate rule, so the existing vectors are
     also parsed under rule 7.
5. **`internal/peers/pairing.go`** `onPeerV1` (`:689-700`): store `canonicalPart(ctl.Card,
   "card")` rather than `ctl.Card`, as `verifyPeer` does.
6. **`internal/team/kinds.go`** `parseRosterMember` (`:349-376`): build `cardRaw` from
   `{card, signature}` only, dropping other entry members, in the same way as
   `canonicalPart`.
7. **`internal/team/store.go`** `memberEntry` (`:645-673`):
   - Forward only `{card, signature}` from the stored row.
   - If the stored card fails `agentcard.Verify` or does not match `m.Key`, return a local
     error naming the member, and do not send a roster that others will refuse (OD-3).
8. **Store migration (OD-3)**, `internal/peers` or `internal/store`, one-shot and idempotent,
   run at open:
   - For each `peers` row, rewrite `card` to its canonical `{card, signature}` when the new
     `Verify` passes.
   - When it fails, leave the row, log once and report it in `agentnet doctor` (a new `peers`
     check line: "peer X has a card that no longer verifies; re-pair or remove").
9. **`internal/request/decode.go`**:
   - `decodeString(…, optional=true)`: a present `""` gives `fieldErr(field, "must not be
     empty when present")`.
   - `decodeArtifactsAt` (`:186-195`): refuse a present `""` member.
   - `requested_grant.note` (`:301-307`): the same.
   - `Validate` stays as it is.
10. **`internal/request/artifact_spec.go`** `ParseArtifactSpec`: refuse empty values in both
    forms. **`cmd/agentnet/request.go`**:
    - Delete `parseArtifactFlag` and call `request.ParseArtifactSpec`, then map the result to
      `daemon.ArtifactParam`, at `request.go:152`, `inbox.go:316` and `session.go:377`.
    - Errors are prefixed `--artifact:` and exit 2.
11. **`internal/daemon/device.go`**:
    - `offerBody.offer` (`:107`) and the unlink handler (`:241`) use a round-trip wire-time
      parse, `bad_body` on failure.
    - Use the package's existing helper if one exists. Otherwise add
      `parseWireTimeStrict` in `internal/daemon`: `time.Parse(time.RFC3339, s)` plus
      `t.UTC().Format(time.RFC3339) == s`.
12. **`internal/daemon/outbox.go`** `mail_submit` (`:89-97`): replace `json.Unmarshal(p.Body,
    &body)` with `agentcard.ParseStrict(p.Body)`. Then call `agentcard.CanonicalValue(body)`
    to refuse numbers that are not canonical integers, before `ob.Submit`. Either failure is
    `bad_request`, with the parser's reason.

Out of scope: a global fold-collision rule in `ParseStrict` (OD-1); C29-03 (verifyvectors
checking production vectors against the card schema), except as the card cases above cover
it; the R55-F10 charset.

## 7. Verification of this spec

- The envelopes were recomputed in a temp dir (`%TEMP%\f23vec`) with a stand-alone Go
  canonicaliser and seed `00…1f`. The base signature equals the published vector
  (`XN3G…PDA`).
- A checker extracted every `{"card":…` line from the edited agent-card.md, expanded the
  placeholders, re-canonicalised the card and verified the signature with lax base64. All 8
  signed envelopes (P1, N1-N5, N11, N12) verify, and each card on the wire is its own
  canonical form. So N1-N5 and N11 pass step 4 and must be refused at the step stated. N12
  and N11 verify only under lax base64, as intended.
- The Go facts behind the spec were checked:
  - `RawURLEncoding` accepts `…Mbh` and `…DB` with the same bytes, and `.Strict()` refuses
    them;
  - the reviewer test's `public_Key` is U+212A (`E2 84 AA`) and `harneſſ` is U+017F.
- No code was changed, no test suite was run, and no git write commands were used.
