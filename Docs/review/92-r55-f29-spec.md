## 3. Design notes

- **R55-116, where the check lives.** `debate.StartParams.Rounds`/`TurnTimeoutS` become
  `*int` (nil = default), so `Start` stays the one validator, and a present 0 fails its range
  check (`debate.rounds: must be 1-5`). The wire request always carries both values, so B's
  side (`debate.Store.ReceivedTx`, the receive validator) is unchanged. `params_hash` already leaves
  out zero values. With pointers it leaves out absent values instead. Every valid submit
  hashes the same bytes as before, so retries across the upgrade still dedupe.
- **R55-127.** `request_cancel` already takes `reason` (1–500 code points, ipc.md). The
  respondent branch (F20) never reaches it.
- **R55-169.** `SweepOne` is cheap when nothing is due: one read in a transaction that never
  writes. `wait` polls `debate_show` about once a second, which is fine. On B it returns at
  once (`role != initiator`). A sweep error in a read method is logged and the view is still
  served. `debate_submit` keeps its current behaviour (a sweep error fails the submit).
- **R55-071, why time-based.** The relay has no end-of-backlog marker (relay-hosted.md), so
  "drained" cannot be observed. Queued mail is sent as soon as the session is ready, so 120 s
  of connection covers a normal drain by a wide margin. Even a 4 MiB backlog at a slow
  50 KiB/s takes about 80 s. Resume detection matters because the relay client has no read
  deadline: after a sleep, `Connected()` can stay true on a dead socket, with a `Since` from
  before the sleep. Forcing a re-dial on resume makes `Since` fresh. The gap test uses wall
  time (`time.Now().Round(0)`), because Go's monotonic clock stops during suspend on Linux
  and macOS. A clock jump that looks like a resume only costs one grace and one re-dial. The
  grace never moves the deadline. It only delays the check, so a late A agent gains at most
  120 s after a reconnect, and B gains nothing. The finding is *suspected* (the order of tick
  and drain was not traced). The test below makes the order explicit instead of relying on
  timing.
- **R55-126, why a new event.** The cause of a refusal (hash, signature, outcome, time, size)
  is a bug or a modified daemon on either side, never the reveal. One event with a neutral
  text needs no change to the adapter signature (`event, sid, peer, requestID`). A per-cause
  text would put the audit's reason into a notification. A user who turned `debate.broken`
  off still gets `debate.refused` (on by default). That is intended: this is a different
  failure.
- **R55-221 (OD-F29-1).** The finding notes there is no security gain either way: a modified
  B can withhold its signature. The value is protecting honest users. "Answered, then
  cancelled" is an easy agent mistake, and it turns a two-signature Decision into a permanent
  `awaiting_peer` on A (A's `wait` keeps timing out). Two escapes keep B's protection:
  - a **held** close (decision.md already names abandon as the way out of a hold);
  - **overdue** silence. A's daemon closes automatically on applying the answer, so silence
    of `turn_timeout_s` after B's answer means A is offline, stuck or modified.

  Before B's answer, B can still leave at once, as today. A has decided nothing B has not
  seen, and the only bad race (A already closing on a timeout) is the documented `Silence`
  case.
- **R55-170/222, reading the Decision.** The Decision already applies the cut (`slot <
  entries`) and rule 8, so reading `final_agreement.decision` and
  `len(remaining_disagreement)` from the canonical bytes this side stored makes the record
  match the Decision by construction. The old answer-only count disagreed with the Decision
  whenever the proposal also listed points. Claims and `rounds_used` need the transcript, so
  they get the same cut through a "covered" filter.
- **`cancelled_by` on B's bad-peer closes (OD-F29-5).** B's daemon ends the debate, so
  `respondent` is what happened. `cause` says why. "initiator" (today) reads as "A
  cancelled", which A did not do.
- **No migration** (the next number would be 26). Nothing here changes a table:
  - B's display deadline after the answer is `debates.turn_deadline`, which B already has
    and today sets to NULL at Done;
  - the held-close test reads `close_body`;
  - the experience record is JSON.

  Existing experience records are not rewritten. Nothing reads them in Phase 3, and they
  are pruned with their sessions.

## 5. Acceptance tests

1. **`--rounds 0`** (IPC `rounds: 0`) is `bad_request` naming `debate.rounds`, and no request
   or debate row exists. `turn_timeout_s: 0` likewise. Absent values give `rounds_max = 2`,
   `turn_timeout_s = 3600`. An explicit `2` stores the same values with a different
   `params_hash` from absent.
2. **CLI durations:** `--turn-timeout 500ms`, `0d`, `-1h` and `300.5s` exit 2 with no IPC call
   (fake daemon). `--turn-timeout 90m` sends 5400. `--rounds` not given sends no `rounds`
   member.
3. **Idempotency across the change:** the `params_hash` of a submit with absent values, and
   of one with `rounds: 3`, equals the value computed by the old code (golden constants).
4. **R55-127:** `debate r-X --cancel --reason "wrong topic"` on the initiator in `invited`:
   the `request.cancel` mail carries `reason`, and B's `in` row shows it. The respondent still
   gets F20's `bad_state`.
5. **R55-169:** with a fake clock past A's deadline (gate ready), `debate_show` returns
   `phase: closed`/`closing`, reason `timeout`, with no sweep tick. `debate_list` likewise for
   two overdue debates. On B, `debate_show` past the display deadline changes nothing.
6. **R55-071 grace:**
   - Gate not ready (client disconnected, or connected for less than 120 s): the deadline passes and `SweepOne` returns false. B's entry, delivered afterwards, is applied normally and the debate stays open.
   - Gate ready with the slot still missing: the debate closes.
   - Resume detection: feed `startDebateSweep`'s tick handler (factor it out) a wall-clock gap of 61 s. `resumeAt` is set, `Reconnect` is called once, and `Ready` is false for 120 s.
   - A gap of 25 s changes nothing.
   - `noRelay`: the plain rule.
7. **`Reconnect`** (relayclient test with a test relay): it drops the connection, the client
   is connected again within the normal dial time, `State().Since` is fresh, and nothing
   happens while disconnected.
8. **R55-126:**
   - B refusing a close with a wrong hash fires `debate.refused` on B. A, on applying B's refusal, fires `debate.refused`. Neither fires `debate.broken`.
   - A bad reveal still fires `debate.broken` on B only.
   - The `debate.refused` title text is checked, and so is the setting default (`notify_get` lists it as on).
9. **R55-221:**
   - B answers `accept: true`, and A's close is not yet delivered. B's `--cancel` is `bad_state` and sends no `ws.cancel` (outbox has no new row). B's view shows `deadline` = answer + timeout. The close then arrives, and both Decisions are `signed`.
   - Same, but with the fake clock past B's deadline and no close: `--cancel` abandons (reason `abandoned`, `debate.abandon` audited, `ws.cancel` queued).
   - Same, but with the close held for a missing A constraint: `--cancel` abandons at once.
   - Before the answer (in `rounds`): `--cancel` abandons at once, as today.
   - `ws_cancel` maps the refusal to `bad_state`, not `internal`.
10. **R55-170:**
    - A modified A closes `escalated/timeout` with `entries` excluding B's answer, which had 2 remaining-disagreement points while the proposal had 1. B's record says `remaining_disagreement_points: 1` (the Decision's count), and `rounds_used`/claims come from covered entries only.
    - With an agreed close, `worked.decision` equals the Decision's `final_agreement.decision`.
11. **R55-222:**
    - Every record has `verification` in the enum: debates `none`, cancelled work `none`, and an accepted work session with `human_accepted` + `verification_by: "requester"`.
    - Debate records carry `team`.
    - B's bad-reveal close: `failed: {cancelled_by: "respondent", cause: "bad_reveal"}`.
    - B's refused close with a derivable record: `cause: "decision_refused"` and `acceptance.decision` = B's own id and hash. With no derivable record, there is no `acceptance.decision`.
    - A work session with 2000 grants and a 16 KiB brief builds a record ≤ 65536 bytes with `truncated: true` and no `approach.grants`.
12. Existing suites stay green: `internal/debate` (lifecycle, reveal, decision, close list,
    experience, session end), `internal/experience`, `internal/worksession` cancel,
    `internal/notify`, `internal/daemon` debate e2e, `cmd/agentnet` debate tests, and F20's
    `idcollision` tests.
