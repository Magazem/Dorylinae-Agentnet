# R-3.3b: security review of the Decision output and Markdown export (ticket 3.3b)

Review (Opus) of `p3/decision-out` at 530397f (3.3b ff8932d + review 47 L7, on main with 3.3a),
against Docs/protocol/decision.md (authoritative), D30 (OD-P3-10 Markdown + `d-….json` sidecar;
OD-P3-14 single-signed exports carry the UNCONFIRMED banner, verify exits 6), review 43 M1/M2,
review 46 H1 (invisible characters), review 47 L7 (no empty signatures) and D32 (goldmark
test-only). Scope: `internal/decision/{markdown,visible}.go` and their tests and goldens,
the `verify.go` additions, `internal/daemon/decision.go`, the `debate_show` `decision` pointer,
`cmd/agentnet/decision.go` and Docs/cli/decision.md. Fixes were made in place, with tests.

**Verdict: pass after fixes.** Critical 0, High 1 (fixed), Medium 4 (3 fixed, 1 open), Low 8
(4 fixed, 4 noted).

## What holds

- **Code spans and fences.** `codeSpan` uses a delimiter one backtick longer than the longest
  run in the escaped text, padded with a space on each side, so text that starts or ends with
  a backtick still closes correctly. `Visible(…, false)` escapes `\n`/`\r`, so a span never
  spans lines. `writeFence` uses at least three backticks and one more than the longest run.
  It never has an info string (so no `mermaid`, `math`, or `diff` renderer), it is always at
  column 0 after a heading or a top-level paragraph (review 43 M2 holds: no fence is inside
  a list item or a block quote), and a `~~~` or indented line inside cannot close it. `\r`
  is escaped, so a CR cannot split a line for a CR-aware parser. Backslash escapes and
  entities (`&lt;script&gt;`, `&#60;`) are literal inside code in CommonMark, GFM, kramdown
  and goldmark.
- **Nothing peer-written sits outside code.** Every string the verifier does not pin to a
  pattern goes through `codeSpan` or `writeFence`. The raw values in the header, the context
  list, the human-decision list and the Verification section are id/session/request/team
  (`x-<32 hex>`), RFC 3339 times, `c-<32 hex>`, the enum `by`, integers, sha256 hex, the hash,
  base64url signatures and fingerprints. `decision.Verify` pins every one of these at step 1
  (`checkSchema`), and the daemon's copy was derived by this daemon. The file starts with `# `
  or `> UNCONFIRMED`, so it has no front matter. It has no tables, no raw HTML, no links and
  no images. The only block quote is the fixed banner, so `> [!NOTE]` alerts cannot be
  forged. GFM's extended autolinks (`www.`, `http://`, e-mail), footnotes, task lists,
  setext underlines and `$…$` math never see peer text. The new AST test checks all of
  these against every field (M1).
- **Banner and signed-by wording.** Complete → no banner. Initiator-signed → "signed by the
  initiator only" and "claimed by the initiator". No signature (review 47 L7, B's own
  `peer_refused` row) → "unsigned … this side's own record", and no empty `Signature` line.
  `peer_refused` adds the refusal sentence. `decision verify --md` never passes
  `refused` (the file cannot say so), as the spec requires.
- **Offline verify.** It does not call `callDaemon`. It exits 0 only when the file is valid
  with both signatures, 6 when it is valid and only the initiator signed, 1 when it is
  invalid and 2 on usage errors. A respondent-only file is invalid at step 1, and an
  unsigned file is invalid (`signatures.initiator is required`). A 60 s run of the new
  `FuzzVerifyAndRender` (64k execs, seeded with the spec vector) found no panic and no valid
  result without the initiator's signature. Every type assertion in `Verify`, `checkInvariants`
  and `Render` is either comma-ok or guarded by an earlier schema check. `--md` renders only
  after `res.Valid`.
- **IPC views.** `decision_show` returns the canonical bytes as a `json.RawMessage`.
  `marshalResult` has HTML escaping off, so they are not inflated (≤ 786432 + hashes,
  signatures, names ≈ 0.79 MB < 1 MiB). `decision_list` rows and the `debate_show` pointer
  carry only ids, state, outcome, `signed_by`, created and the title, never content.
  `debate_list` does not look up Decisions (`ds == nil`). Both new methods are read-only and
  are listed as exempt in the audit inventory.
- **Determinism and goldens.** The output has no time, locale, map order (artifact keys are
  sorted) or float formatting (`json.Number`). The goldens are pinned LF in `.gitattributes`
  and stay LF after the regeneration below.
- **goldmark stays test-only.** It is imported only by `_test.go` files, and
  `TestBinariesDoNotLinkGoldmark` runs `go list -deps` on the three binaries.
- **Sub-bullet layout (the worker's judgement calls).** Evidence as `- kind: ref (note: …)`,
  rejected alternatives as `- option — reason`, and artifacts as `- key: value, …` with
  sorted keys are all sound. Each value is its own code span, the keys and separators are
  daemon text, and the flat lists stay at top level with no nested items, so M2 of review 43
  holds. The one defect was the missing blank line after each list (M2 below).

## High

### H1: static-site template syntax turned peer text into live HTML (fixed)

`internal/decision/markdown.go` `codeSpan`/`writeFence`.

**Problem.** The file is meant to be committed to a repository's decisions folder. Jekyll
(and GitHub Pages, which renders `.md` files without front matter through
`jekyll-optional-front-matter`), Eleventy (Liquid by default for `.md`), Hugo (shortcodes
`{{< >}}`/`{{% %}}`) and Nunjucks all run their template language **before** the Markdown
parser, and they do it inside code spans and fences too. The fence length is computed from
the text as written. So an argument holding a line with `{% for i in (1..9) %}`, one backtick
and `{% endfor %}` has a single literal backtick, gets a three-backtick fence, and expands to
nine backticks, which closes the fence. Every later peer line (`<script>…`, `<img onerror>`,
links, a fake "Signed by: initiator and respondent" block, a fake Verification section) is
then published as live kramdown/HTML on the project's site. `{% include_relative … %}` can
also inline other repository files, and any template syntax error (`{{ x | }}`) fails the
site's build. The rendered GitHub view is not affected. The published site, which readers
treat as the record, is.

**Fix.** `decision.TemplateInert`, applied after `Visible` in both `codeSpan` and
`writeFence`, replaces every `{` that is followed by `{`, `%` or `#` with `\u{7B}` (the same
visible-escape notation). The output then holds no `{{`, `{%` or `{#`. Any `{` that is left
is followed by a character other than `{`, `%` or `#`, and the escape adds no backtick.
Spec §Markdown documents the rule. Tests: `TestTemplateInert`, the template assertions in
`TestRenderEveryPeerFieldIsInert` (Liquid loop, Hugo shortcode, `{% raw %}`/`{% endraw %}`,
`{{{`), and the fuzz target. With `TemplateInert` stubbed to the identity function,
`TestRenderEveryPeerFieldIsInert` fails.

## Medium

### M1: the inertness test could not see raw HTML and covered four fields (fixed)

`internal/decision/markdown_test.go` `tagCounts` / `TestRenderAdversarialIsInert`.

**Problem.** goldmark's default HTML renderer drops raw HTML and writes
`<!-- raw HTML omitted -->`. The test counted `<script` and `<img` in that output, so it
passes even when peer text is emitted raw, which is exactly the regression it exists to
catch. The adversarial Decision also only filled the claim, argument, topic and one
constraint. Evidence, rejected alternatives, challenges, targets, revisions, final positions,
points, remaining disagreement, artifacts, context names, the title and petnames were
unchecked. GFM's `www.` autolinks, footnotes, task lists, setext headings, `> [!NOTE]`,
front matter and math were not in the set.

**Fix.** `tagCounts` renders with `html.WithUnsafe()`. The new `markdown_ast_test.go` fills
every peer-controlled field (and both petnames) with hostile single- and multi-line text that
carries a marker. It parses the output to an AST with CommonMark + GFM + footnotes and
requires three things: the marker occurs only under a `CodeSpan` or an info-less
`FencedCodeBlock`; no raw HTML, HTML block, link, autolink, image, table, task box,
footnote, emphasis, strikethrough, thematic break or indented code node exists; and there is
at most one block quote (the banner). It then renders with raw HTML kept and checks that no
active tag appears. Mutation check: with `codeSpan` returning raw text, the test reports
about 1,500 failures. goldmark versus GitHub: both follow the CommonMark spec plus the GFM
extensions. GitHub additionally has math, alerts, mermaid and emoji, which only apply to
text outside code (or to fences with an info string), so the AST property ("peer text only
in code, no info strings, one block quote") also holds for GitHub. Template engines are not
Markdown and are covered by H1's byte check.

### M2: labels after a list were absorbed into the list (fixed)

`internal/decision/markdown.go` `renderPositionBody`, `renderMove`, `renderFinalAgreement`,
`renderVerification`.

**Problem.** A paragraph line right after a list item is a lazy continuation of that item.
`Assumptions:` / `- a` / `Evidence:` / `- e` therefore rendered as one list: "Evidence:" was
glued to the last assumption and the evidence items joined the assumptions list, and the same
happened to "Rejected alternatives:". "Claim: …" and the next label rendered as one paragraph,
and so did Hash + both signatures + "Verify with". Readers of the rendered file saw evidence
presented as assumptions, which misattributes a signed record.

**Fix.** Every paragraph and list now ends with a blank line, the Verification lines are a
list, and the goldens were regenerated (LF). `TestRenderLabelsAreOwnParagraphs` checks that
each label is its own `<p>` and fails on the old layout.

### M3: no way to write the `d-….json` sidecar without a shell redirect (fixed)

`cmd/agentnet/decision.go` `runDecision`.

**Problem.** OD-P3-10 pairs the Markdown with a `d-….json` sidecar, and the audit table's
`decision.export` has `format: "md"|"json"`, but `--out` was accepted only with `--md`. The
only way to produce the sidecar was `> d-….json`. In Windows PowerShell 5.1 (the owner's
shell), `>` and `Out-File` write UTF-16LE with a BOM, which `decision verify` (strict UTF-8
JSON) rejects at step 1. The committed proof would then not verify for anyone.

**Fix.** `--out FILE [--force]` works with `--json` and writes the same bytes as stdout,
atomically, and refuses to overwrite without `--force`. The spec table and
Docs/cli/decision.md are updated. `TestDecisionCLIRoundTrip` now writes the sidecar with
`--json --out` and checks the bytes, the overwrite refusal, and that verify reads it back.

### M4: `decision.export` is never audited (open)

**Problem.** decision.md §Audit lists `decision.export` (local / `cli`,
`{id, format}`, "only when written to `--out`"). Nothing emits it. The CLI has no database
handle, and the IPC table has no method that could record it.

**Recommendation.** This is not fixed here because it needs a spec change. Either add an IPC
method (for example `decision_exported {id, format}`, called after a successful `--out`
write, audited as `decision.export`, with a scenario in `TestAuditInventory`), or drop the
row from §Audit, since an export is a local file write the daemon cannot observe. **Owner
decision.** Until then the §Audit row is inaccurate.

## Low

- **L1 (noted): `decision_list` is unbounded.** It returns every row, and `DecisionList`
  loads each full canonical Decision (up to 768 KiB) only to read `outcome`. With Decisions
  kept indefinitely, a few thousand rows push the response past the 1 MiB IPC line (about
  300–900 bytes per row, depending on the title) and the daemon's memory grows with them.
  `debate_list` has the same shape. Fix later with a `limit` param and
  `json_extract(decision, '$.outcome')` in SQL.
- **L2 (noted): `agentnet decisions` prints the peer's request title raw to the terminal.**
  `request.ValidateTitle` refuses control characters but not `Cf` (bidi overrides). This is
  the same as `agentnet debates` and `inbox`. Use `termSafe` in all three together.
- **L3 (fixed): `Visible` let review 46 H1's graphic-but-invisible runes through.** These are
  the Hangul fillers, U+034F, variation selectors, `Zs` spaces other than U+0020, and U+2800.
  Debate text is filtered at ingestion, but the title, context file names and petnames are
  not. `Visible` now escapes the same set as `debate.invisibleRune`. Test:
  `TestVisibleEscapesGraphicInvisible`.
- **L4 (fixed): signatures were plain text.** A base64url signature containing `-_x…y_-` is
  emphasis in CommonMark. The rendered (and copied) signature then loses its underscores.
  The hash and signatures are now code spans in the Verification list.
- **L5 (fixed): `decision verify --md --json` mixed JSON and Markdown on stdout, and verify
  read files of any size.** The flag pair is now a usage error (exit 2), and verify reads at
  most 8 MiB (the canonical cap is 768 KiB).
- **L6 (fixed): `--out` without `--force` used `os.Stat`.** A dangling symlink at the path
  therefore counted as absent, and the rename replaced it. It now uses `os.Lstat`. The
  Stat-then-rename window is a TOCTOU the invoking user races only against themselves;
  noted. The temp file is created 0600, so on Unix the exported file is 0600, which git
  ignores; noted.
- **L7 (noted): `\u{…}` is ambiguous with literal text.** A peer can write the six
  characters `\u{202E}` to look like an escaped character. This is harmless (the JSON holds
  the truth, and the escape is a display rule), and escaping `\` would make every Windows
  path in evidence unreadable.
- **L8 (noted): no IPC-level worst-case size test for `decision_show`.** The arithmetic
  holds (0.79 MB), and `TestWorstCaseDecisionSize` pins the canonical side. A daemon test
  that stores the worst case and calls `decision_show` would pin the line limit.
