## Owner summary

**The problem.** `agentnet` prints text that other people chose: peer and team names, request
titles and reasons, debate topics, session summaries, grant branches, file names a grantor
serves, Decision reasons and audit details. Today:
- about 60 print sites put this text on the terminal **raw**. A peer can send escape sequences
  (fake lines, colours, links), a carriage return, or a bidi override that reorders a table
  row. One example: `agentnet peers` could show another device's fingerprint in the row of a
  hostile peer;
- the one sanitiser the CLI has, `termSafe` in `fetch`, misses invisible characters that F5
  already treats as hidden (Hangul fillers, variation selectors, U+2800);
- multi-line fields (a request's `reason` and `output`, a debate `topic`) can print a line
  that looks like one of the command's own field lines;
- `--json` output passes C1 controls and bidi overrides through (`encoding/json` escapes only
  C0, U+2028 and U+2029);
- the Agent Card allows bidi controls and line separators in names, so every other program
  that shows a card (an agent reading `peers --json`, a log viewer) inherits the problem.

**The fix.**
1. **One terminal renderer.** `displaytext.Term` replaces `termSafe` and the raw `%s`. It
   uses F5's `hidden` set and writes every hidden character as a visible `\u{XXXX}`, like
   `decision.Visible`. It also caps stacked combining marks at 2. The value stays readable
   and exact, and it cannot drive the terminal. `displaytext.Block` handles the few
   multi-line fields: each line goes through `Term`, and continuation lines are indented so
   they cannot pose as field lines.
2. **Every print site uses it.** The sweep below lists every site (about 60). `failJSON` also
   uses it for daemon error messages, and `log` uses it instead of the notification cleaner.
3. **`--json` escapes hidden characters** as `\u` escapes, so the value is unchanged and the
   bytes are terminal-safe. One helper replaces the 73 `json.NewEncoder(stdout).Encode`
   calls.
4. **A narrow card rule.** Card text (name, harness, skill id, name and description) may no
   longer hold a bidi control or U+2028/U+2029. Emoji joiners and variation selectors stay
   allowed, because real names use them (`👩‍💻`, `❤️`); they are escaped when printed.
5. **No honest card is blocked.** Cards created before F10 cannot be re-signed by anyone but
   their owner. So the new rule applies only where a card is **new to this daemon**: at
   pairing and at creation. The daemon's own card, stored peer rows, forwarded rosters and
   roster intake use the old text rule (review 76 I3). `doctor` reports such cards as `ok`
   with a count.
6. **The grant branch** may not hold a hidden character (R55-056). Git allows one, but nobody
   could compare it by eye.

Acceptance: invert `zz_review55_T11-04` (U+3164, VS16 and U+2800 are escaped); new vectors
N18 (U+202E in the name: refused at step 5), N19 (U+2028 in a skill description) and P3 (emoji
ZWJ and VS16 in the name: accepted).

Eight ODs, each with a recommended option; see [Open decisions](#open-decisions).

## Design

### Why escape and not remove, and not `displayName`

Three renderings already exist. None of them fits the CLI.
- **`displayName`** (F5) removes invisible runes and **blanks** digit runs and
  fingerprint-shaped text. That is right for an approval window: the fingerprint is printed
  beside the name, and the human decides there. In the CLI, names are also **addresses**:
  `<peer>` is "a peer name or public key". A peer named `build-202610` would show as
  `build-…`, and the user could no longer type its name. The CLI is not the trust channel,
  and `peers` shows the fingerprint in its own column. Once bidi is escaped, a name cannot
  reach that column (OD-F10-3).
- **`displayLine`** (F9) removes and cuts. That is right for diagnostics, where exactness does
  not matter. A file name in `fetch --list` or a branch must stay exact.
- **`displayQuote`** wraps the text in JSON quotes and doubles `\`. It is meant for a single
  value inside a sentence. In tables it would put quotes around every name.

`displayTerm` is `decision.Visible`'s rule, which reviews 43, 46 and 48 have already checked,
plus the stacked-marks cap of `displayQuote`. ASCII text and normal Unicode pass through
unchanged. The output can still be typed back, except where an escape stands in for an
invisible character.

### The API (one package)

`internal/displaytext` gains three functions, all on the one `Hidden` set:

```go
// Escape is decision.md §Markdown's rule (moved from decision.Visible): every
// hidden rune (and U+FFFD) becomes \u{XXXX}; \n and \t are kept when multiLine.
func Escape(s string, multiLine bool) string
// Term is displayTerm: Escape(s, false), and every combining mark (Mn, Me) after
// the 2nd on one base also becomes \u{XXXX}.
func Term(s string) string
// Block is displayBlock: s split at "\n" (one final "\n" dropped), each line
// rendered by Term with '\t' kept, lines after the first prefixed by indent.
func Block(s, indent string) string
// JSON rewrites encoded JSON so that every non-ASCII hidden rune is written as
// \uXXXX (lowercase, a surrogate pair above U+FFFF). It only touches runes
// >= U+0080, which can occur only inside JSON strings, so the decoded value
// is unchanged.
func JSON(b []byte) []byte
```

`decision.Visible(s, multiLine)` becomes `return displaytext.Escape(s, multiLine)`, so its
output does not change (OD-F10-8). `termSafe` and its `strconv`/`unicode` imports go.
`Name`, `Quote` and `Line` do not change.

`cmd/agentnet` gains `writeJSON(w io.Writer, v any)`. It encodes `v` exactly as
`json.NewEncoder(w).Encode(v)` does today, with HTML escaping on and a trailing newline, then
passes the bytes through `displaytext.JSON`. Every human-facing `--json` encode and
`failJSON` use it. Outputs whose bytes are a format of their own are excluded: the Decision
file written by `decision export` (`decision.go:134`, exact signed bytes), `fetch` raw reads
(`fetch.go:235`, file content the user asked for), and the Markdown of `decision --md` (already
`decision.Visible`).

### Card text (R55-055)

`checkText` (`internal/agentcard/agentcard.go:149`) gains the two R55-F10 items. Both are
fixed sets: `unicode.Bidi_Control` is exactly the 12 code points listed in agent-card.md, plus
U+2028 and U+2029. They are refused for `name`, `harness`, and skill `id`, `name` and
`description` alike.

Why so narrow (OD-F10-1)? Refusing all of `Cf`, the variation selectors and the
default-ignorables, as R55-055's first fix direction says, would refuse honest names:
- the ZWJ U+200D in emoji sequences;
- VS16 U+FE0F;
- the tag characters of subdivision flags;
- the soft hyphen.

A daemon whose own card had such a name would then fail its start-up re-verification. Printing
is where the protection must be anyway: the card is far from the only peer text. The card rule
is defence in depth for consumers outside this CLI (an agent reading `--json`, logs, other
A2A tools). Bidi controls and line breaks are the characters that change how surrounding text
reads, and no honest name uses them.

### Stored cards (review 76 I3)

A signed card cannot be repaired by anyone but its key holder, so OD-3's "rewrite on rescue"
does not apply. The rescue is a **verification level**:

| Where | Today | After F10 |
|---|---|---|
| Pairing v1 `onPeerV1`, v2 `verifyPeer` (`internal/peers/pairing.go:717,765`), team join (v2) | `Verify` | `Verify` (text rule): a pre-F10 peer with a bidi name cannot pair with an F10 daemon; the failure is the existing `FailBadCard` path (`rejected the peer's Agent Card: …`), whose message names the field |
| `agentcard.New` / `Sign` (creation) | `validate` | text rule: no new card can break it |
| Own card at start (`internal/identity/identity.go:185` `readCard`) | `Verify` | **`VerifyStored`**, then a `Warn` log `own_card_legacy_text` if `Verify` would refuse it. Without this the daemon would not start ("present, invalid → fails to start") |
| `peers.card` migration (`internal/peers/cardcheck.go` `MigrateCards`, `CheckStoredCards`, via `agentcard.RescueStored`) | `Verify` inside `RescueStored` | `RescueStored` verifies with `VerifyStored`. A row that passes is rewritten as today. A row that passes `VerifyStored` but not `Verify` is returned in a second list, `LegacyText`. It is not a `BadCard`: logged at Info once per start, counted by `doctor` |
| `forwardCard` (`internal/team/store.go:744`) | `Verify` | `VerifyStored`: a pre-F10 member never blocks a roster |
| Roster intake `parseRosterMember` (`internal/team/kinds.go:365`) | `Verify` | `VerifyStored`: an F10 member accepts a roster from an older or F10 owner that carries a pre-F10 member |
| `tools/verifycard`, `tools/verifyvectors` | strict | text rule (N18/N19 refused at 5) |

Consequence: with roster intake lenient, an owner can introduce a **new** member whose card
breaks the rule. Owners are already trusted to introduce keys (team.md), and every print site
escapes the text anyway. The rule binds wherever this daemon meets a key for the first time
by itself. That is enough for a defence-in-depth rule, and it never stops an honest team
(OD-F10-2).

`VerifyStored` differs from `Verify` only in step 5's text check. Implementation:
`verify(data, legacyText bool)` behind both, and `validate(c, legacyText)` passing the flag to
`checkText`. A helper `TextRuleError(c Card) error` (the full rule on an already verified card)
lets `identity`, `MigrateCards` and the `agentnet identity` CLI tell "legacy" apart without a
second parse.

### The grant branch (R55-056, OD-F10-5)

`capability.checkBranch` (`internal/capability/token.go:250`) refuses every `displaytext.Hidden`
rune. The space is already refused, and C0 is already refused by `hasControl`. The new set adds
C1, `Cf`, Zl/Zp, the variation selectors, the default-ignorables, non-ASCII `Zs` and U+2800.
The same function runs:
- at issuance;
- on every received token (`validate`, `token.go:212`);
- in `GitBackend.check` / `BranchTip` (`git.go:232,252`).

So an old grant on such a branch becomes `not_found` at its next fetch. That is acceptable for
a 90-day-at-most capability whose branch nobody could read anyway. The request artifact
`branch` (`internal/request/validate.go:257`) is **not** tightened. It is display-only,
`displayTerm` covers it, and tightening it would make an older peer's whole request
`bad_body`.

## Implementation plan (Opus; code after the spec is approved)

1. **`internal/displaytext/displaytext.go`**: add `Escape`, `Term`, `Block` and `JSON` as in
   [The API](#the-api-one-package). `Escape` is the body of today's `decision.Visible`.
   `Term` reuses `isMark` and `maxMarks`, as `Quote` does. `JSON` walks the bytes; runes below
   U+0080 are copied, so structural characters are untouched. Update the package comment.
2. **`internal/decision/visible.go`**: `Visible` calls `displaytext.Escape`; the comment points
   to approval.md. No output change (existing decision tests are the check).
3. **`internal/agentcard/agentcard.go`**:
   - `checkText(field, s, required, legacy bool)` refuses `unicode.Is(unicode.Bidi_Control, r)`,
     U+2028 and U+2029 unless `legacy`. The error is "`<field>` contains a bidi control or
     line separator".
   - `validate(c, legacy)`; `New` and `Sign` use `legacy=false`.
   - `Verify` → `verify(data, false)`; new `VerifyStored(data)` → `verify(data, true)`.
   - New `TextRuleError(c Card) error`.
   - `RescueStored` verifies with `VerifyStored`.
   - Doc comments cite agent-card.md §Cards stored before R55-F10.
4. **`internal/identity/identity.go`** `readCard`: `VerifyStored`. Then, if
   `TextRuleError(card)` is not nil, return a flag that the daemon logs as `Warn`

| OD-F10-1 | Which characters may card text no longer hold? | (a) Bidi controls (`Bidi_Control`) and U+2028/U+2029 only; every other invisible character is escaped at print (b) The whole `hidden` set (all `Cf`, variation selectors, default-ignorables, non-ASCII `Zs`, U+2800), as R55-055 first suggested (c) Nothing new; print-time escaping only | **(a)**. | OD-F10-2 | How are cards that predate the rule treated (review 76 I3)? | (a) Two levels: `Verify` (full rule) at pairing, creation and in `verifycard`; `VerifyStored` (legacy text rule) for the own card, stored rows, `forwardCard` and roster intake; `doctor` `ok` with a count (b) Full rule everywhere, with OD-3-style reporting: such members block their team's rosters until removed (I3's problem) (c) Store the rule version per `peers` row and check each row under its own version | **(a)**: no honest team or daemon is ever blocked, and the rule still binds at first contact.
