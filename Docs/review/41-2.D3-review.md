# R-2.D3: security review of kill-on-revoke and program ownership (ticket 2.D3)

Review (Opus) of commit bda7b68 on `p2/device-harden` (owner decision D24; review 40 L1 and
L11), against Docs/protocol/device.md (§Program ownership, §Running, §Limits, §Unlink and
expiry) and Docs/cli/device.md. The threat model: another local user (or anyone who can
write somewhere on a program's path) swaps a program the helper's human approved; a
controller whose authority was removed keeps a command running; races between revocation
and a run that is starting or ending. Fixes were made in place, with tests.

**Verdict: pass after fixes.** Critical 0, High 0, Medium 3 (3 fixed; M2 on Linux only),
Low 9 (4 fixed, 5 noted).

## What holds

- **Revocation vs a starting run.** `take(start)` re-checks the job in the same transaction
  that marks it running. A revocation that commits after that but before `execute`
  registers `cur` is caught by the watch's first sweep, which runs at once; `run` is not
  called if `runCtx` has already ended, and `device.Run` kills the tree if it ends later.
- **Revocation vs a finishing run.** A stop that lands after the program exited but before
  `execute` reads the cause reports the run cancelled and drops the result (authority wins,
  as D24 says). A stop after that point is a no-op: the result was earned under the scope.
  `stop` is checked by session id, so an old sweep cannot stop the next run.
- **No double report.** A revoked run gets `finish` + `ws.cancel` + audit and returns
  before `SubmitResult`; `cancel` sends only while the session is `open`.
- **Goroutines.** `watch` ends when `runCtx` ends; `execute` cancels it and waits
  (`<-watched`) before clearing `cur`. `sweep` holds no lock that `execute` needs, and
  `stopRunning` takes only `curMu`: no lock cycle. Daemon shutdown ends `runCtx` (derived
  from the daemon context), so the tree is killed and the job stays marked running for the
  restart.
- **Windows DACL rules.** Owner restricted to self/SYSTEM/Administrators/TrustedInstaller;
  a NULL DACL (present, nil) and a missing DACL (`ERROR_OBJECT_NOT_FOUND`) are both
  refused; an empty DACL grants nobody and is accepted (only the trusted owner can change
  it). Inherit-only ACEs are skipped correctly. Ignoring deny ACEs can only cause a false
  refusal. OWNER RIGHTS maps to the owner; CREATOR OWNER in an effective ACE matches no
  token, so mapping it to the (already trusted) owner is harmless. `S-1-15-*` SIDs are safe
  to ignore: an AppContainer access check also requires the user or group grant. Generic
  rights: GENERIC_WRITE on a directory maps to add file/subdirectory and write attributes,
  with no delete-child, so leaving it out of the ancestor mask matches the design.
- **"Append data" on ancestors is safe for the program itself.** Creating a new entry in a
  directory above the program's folder cannot change what an existing path resolves to
  (NTFS is case-insensitive unless the flag is set, which needs write-attributes).
  DLLs, `.manifest` and `.exe.local` are only looked up in the program's own folder,
  which is checked with add file/add subdirectory. `C:\` grants Authenticated Users only
  `AD` (add subdirectory), not add file. See L9 for tools that search upwards.
- **Reparse points, verified here.** `GetNamedSecurityInfo` on a junction returns the
  junction's own ACL, not the target's (a Users grant made with `icacls /L` on the link was
  refused). `filepath.EvalSymlinks` (Go 1.27) does not follow mount points and fails on a
  file under a junction, so today any path through a junction is refused. 8.3 names: ACLs
  belong to the object, not the name, so short names change nothing.
- **Check vs exec (TOCTOU).** `CheckTarget` checks the same path string that
  `exec.Cmd.Path` runs. After the check, only a trusted principal can change any element
  that decides where that path leads (once M1 is fixed). Bind mounts and FUSE mounts need
  root or a mount point the user owns.
- **testutil.** `MkdirPrivate` uses `MkdirTemp` under a shared base (`MkdirAll` is
  race-safe), so parallel tests and packages never collide; `PrivateDir` removes its
  directory with the TempDir retry. Only the daemon's run-helper directory leaked (L6).

## Medium

### M1: an intermediate symbolic link was not checked (fixed)

- **Location:** `internal/device/perm.go` `CheckProgramOwner`.
- **Problem:** only two chains were checked: the path as given and the path fully
  resolved by `EvalSymlinks`. A link that points to another link is resolved through the
  second link's directory, which is on neither chain. Example: `~/bin/tool → /srv/open/hop
  → ~/real/tool`, where `/srv/open` is world-writable. Both chains are private, so the
  program was accepted, and anyone who can write `/srv/open` can repoint `hop` at any
  program between the check and any later run. The same applies on Windows to symlink
  chains (junction paths are refused today, but only because `EvalSymlinks` fails on them).
- **Fix:** a walk (`ownerWalk`) checks the path as given, element by element. Every
  symbolic link it meets (on Windows also a junction: `ModeIrregular` with a readable
  target) is checked as a link, then followed. Its target, relative targets included, is
  checked the same way at the link's depth, so the program's real folder still gets the
  parent rules. At most 40 links (a loop is refused). On Windows a link's own ACL is judged
  with a `roleLink` mask that adds write data and write attributes (either can rewrite a
  reparse point). The `EvalSymlinks` call stays as a fail-closed existence check. Tests:
  `TestCheckProgramOwnerLinkHops` (Unix: world-writable middle hop, relative target, link
  loop), `TestOwnerWalkJunction` (Windows: target's parent writable by Users; a junction
  Users can rewrite). A mutation that stops following junctions fails the Windows test.

### M2: Linux POSIX ACLs were ignored (fixed on Linux; macOS noted as L4)

- **Location:** `internal/device/perm_unix.go` `checkPathOwner`.
- **Problem:** with an access list, the mode's group bits show the ACL mask. `setfacl -m
  u:mallory:rwx dir` on a directory owned by the user, whose group is the user's private
  group, gives mode `rwxrwx---` with a trusted group, so it was accepted. Yet mallory can
  add or replace files in it. Shared project folders often carry such entries, including
  inherited default ACLs.
- **Fix:** `perm_acl_linux.go` reads `system.posix_acl_access` (`Lgetxattr`; no data or
  no support passes, any other error refuses). `aclWriter` (portable, `perm_acl.go`) refuses
  a named user other than root/self, or a named group that is not trusted, with write
  permission not removed by the mask. A malformed value is refused. The ACL is checked
  before the mode, so the error names it. Tests: `TestACLWriter` (runs everywhere) and
  `TestCheckProgramOwnerLinuxACL` (sets a real ACL; skipped if the filesystem has none).

### M3: the watch re-checked every 10 ms after a scope was replaced with a later expiry (fixed)

- **Location:** `internal/daemon/device_run.go` `watch`.
- **Problem:** the watch waited for `plan.Expires`, the expiry when the run started. After
  the human replaces the scope with the same command and a later expiry (the normal way to
  extend it), the old expiry passes. The sweep finds the run still valid, and every later
  wait was `max(d+1ms, 10ms)` = 10 ms. That meant 100 transactions a second, contending
  on `sweepMu` and the database, for the rest of the run (up to 1 h). A failed sweep near
  the expiry did the same.
- **Fix:** `activeRun` keeps `expires`, updated under `curMu` by every sweep that finds the
  run still valid (`stillRunning`); `watch` reads it (`runExpires`). An expiry already past
  that the sweep did not act on waits `min(every, 1 s)`. Test:
  `TestHelperSweepFollowsReplacedScope` (the expiry moves; fails without the fix).

## Low

### L1: a revoked run cut off by a daemon stop was reported "interrupted" (fixed)

- **Location:** `device_run.go` `execute` (the `ctx.Err()` return) and `recoverAfterRestart`.
- **Problem:** if the daemon stops while a revoked run is being killed, or the scope
  expires or the link ends while the daemon is down, the restart sent a `fail`
  "interrupted" result. The spec says a run that is no longer allowed gets `ws.cancel` and
  no result.
- **Fix:** `recoverAfterRestart` re-checks the running job (`valid`) and sends `ws.cancel`
  when it is no longer allowed. Docs: device.md §Limits. Test:
  `TestHelperRestartReportsRevokedRunCancelled` (e2e; fails without the fix).

### L2: a scope replaced with another command under the same name kept the old one running (fixed)

- **Location:** `device_run.go` `take`.
- **Problem:** the running job is re-checked by name. A new scope whose `test` command now
  has other arguments, environment names or repo was still "valid", so the command the
  human no longer approved ran to its timeout.
- **Fix:** `stillRunning` stops the run when the new plan's `argv`, `env` or repo path
  differ; a changed `timeout_s` alone does not stop it. Docs: device.md §Running,
  cli/device.md. Test: `TestHelperSweepFollowsReplacedScope`.

### L3: an ACCESS_ALLOWED_COMPOUND_ACE was ignored (fixed)

- **Location:** `perm_windows.go` `classifyACE`.
- **Problem:** unknown ACE types fell into `default` and were ignored. The obsolete
  compound allow ACE (type 4) grants access.
- **Fix:** it is refused like an object ACE when it carries a write right.

### L4: macOS/BSD ACLs are not read; the private-group rule trusts every member (noted)

- **Location:** `perm_acl_other.go`, `perm_unix.go` `trustedGroup`.
- **Problem:** `chmod +a "mallory allow add_file"` on macOS leaves the mode unchanged, and
  reading extended ACLs there needs `acl_get_link_np` (cgo). A group named after the user
  with the user's primary gid can still list other members in `/etc/group`.
- **Recommendation:** accept for now (both need the user's own action); documented in
  device.md §Program ownership. A cgo-free option on macOS is to parse `ls -le`. Rejected
  here as fragile.

### L5: network paths trust the file server's owners and administrators (noted)

- **Location:** `perm_windows.go`, `perm_unix.go`.
- **Problem:** on a UNC path or mapped drive (or NFS), the owner and ACL SIDs are the
  server's: `BUILTIN\Administrators` there are the server's administrators, and NFS uids
  are whatever the server reports. Content is not integrity-protected without SMB signing.
- **Recommendation:** documented. Refusing `DRIVE_REMOTE`/UNC paths would break corporate
  setups that run tools from shares; an owner decision if wanted.

### L6: the daemon tests leaked the run helper under the user's cache directory (fixed)

- **Location:** `internal/daemon/device_run_e2e_test.go` `buildRunHelper`.
- **Problem:** `MkdirPrivate` directories are not under `%TEMP%`, and nothing removed the
  daemon's (the device package has a `TestMain`, the daemon package had none). Each run
  of `go test ./internal/daemon` left about 3 MB in `%LOCALAPPDATA%\dorylinae-test`. Six
  were found here.
- **Fix:** a `TestMain` removes `runHelperDir`. Two full test runs afterwards left nothing.
  The six stale directories were deleted.

### L7: kill on revoke has the same reach as the timeout kill (noted)

- **Location:** `runner_unix.go`, `runner_windows.go`.
- **Problem:** on Unix a process that left the group (`setsid`, a daemonising tool) is not
  killed. On Windows anything started outside the job is not killed: a service, a
  scheduled task, a COM out-of-process server. Breakaway is not allowed. This is already in
  device.md §Running for the timeout, and it applies to revocation too.
- **Recommendation:** a cgroup (Linux) remains the full fix (review 40 M2).

### L8: any program reached through a junction is refused, with a confusing error (noted)

- **Location:** `perm.go` `CheckProgramOwner` (`EvalSymlinks`).
- **Problem:** Go's `EvalSymlinks` does not follow mount points and fails ("cannot find the
  path") for a file under a junction. Tools installed behind a junction (Scoop's `current`,
  some SDK managers) are refused with "resolve the program". The refusal is safe, but
  unexplained.
- **Recommendation:** the walk (M1) already handles junctions; the `EvalSymlinks` guard
  could be replaced by an `os.Stat` existence check once junction handling is tested more
  widely. Left fail-closed here.

### L9: tools that search upward from their folder or the repo (noted)

- **Problem:** ancestors may grant "add subdirectory" to others, like `C:\`. That cannot
  replace the program, but a tool that searches upward for a *directory* can pick up one
  planted there, for example Node's `node_modules` resolution from the repo up to
  `C:\node_modules`. This is about the repo and the tool's own behaviour, not about who
  can change the program. It is outside L11, and a scope already lets the controller's
  requested command run repo code.
- **Recommendation:** none now; mention in user docs if it ever matters.
