## Verdict

**Ready to merge after the fix below, with a careful rebase (M3).** There are no Critical or
High findings. The relay-in-the-middle from review 50 is closed:

- A v2 signature names the origin the daemon dialled.
- The relay accepts a v2 signature only for its own canonical origins.
- The daemon never signs v1 for a non-loopback URL.

One Medium is fixed in code with a regression test (M1). A URL counted as "loopback" only
because of its text could reach another machine and get a v1 signature. The other two Mediums
are a spec-mandated upgrade break (M2) and a rebase hazard against 4.0c (M3). Both are listed
for the orchestrator or owner.

## Attack list: what holds (checked in code, no finding)

1. **Signed bytes.** The daemon signs `"dorylinae-relay-auth-v2\n" ‖ nonce(32) ‖ u16be(len) ‖
   origin` (`authv2.go` `AuthMessageV2`). The prefix is distinct from v1 and from every other
   signed structure, the length prefix makes the encoding injective, and the nonce is exactly
   32 bytes. Origin normalisation:
   - scheme lower-cased, ws/wss only;
   - user info and opaque URLs refused, IPv6 zones refused;
   - port parsed as u16, 0 refused, default port dropped after numeric parsing (`:0443` → none);
   - IDN via `idna.Lookup`;
   - path and query dropped.

   The daemon computes the origin from the URL it dials (`c.url = u.String()`), and the relay
   compares it with its own canonical origins. A hostile relay could only collide by
   canonicalising to the real relay's origin, which then means dialling the real relay (L6).
2. **Replay.** The nonce is 32 bytes from `crypto/rand`, fresh per WebSocket (`relay.go:268`).
   It is checked only on the connection that issued it, within the TTL (context deadline plus
   `time.Since(issued) > ttl`). A captured pair is useless on a later session and on another
   relay.
3. **Downgrade.** `envelope.SignAuth` (v1) has exactly one caller (`relayclient.go:257`). It is
   reached only when `authVersion` returns 1, which requires `loopback`. `loopback` comes from
   the configured URL, never from a relay frame, and after M1 it also requires a loopback peer.
   Every other outcome, including every dial, TLS, redirect, read and timeout error, returns
   before any signing (`session` → `handshake`). A public name that resolves to loopback only
   gets the stricter treatment.
4. **Public/AllowAuthV1.**
   - `setAuth` sets `authV1 = !Public || AllowAuthV1`, and a public relay with no origins is an
     `Open` error (library level too).
   - `cmd/relay` refuses non-loopback without TLS mode, and any TLS mode without
     `--public-origin`.
   - A non-loopback `--public-origin` alone makes the relay public.
   - No misconfiguration falls back to permissive, except the undetectable proxy case (L3).
5. **TLS / redirects.** `--relay-ca` is scoped (L1). Redirects: the production dial passes
   `HTTPClient: c.http` (`relayclient.go` `session`). coder/websocket wraps our `CheckRedirect`
   and calls it (`dial.go:88-102`), so a 301 is a dial error in the real path, not only in the
   test. HTTP/2 is off. TLS 1.2 is the minimum on both sides. The server gets an 8 KiB header
   cap and 10 s/60 s timeouts, and the TLS handshake is bounded by `ReadHeaderTimeout` (a
   `tls.NewListener` conn).
6. **Vectors.** `tools/verifyvectors/relayauth.go` re-derives the origin with its own string
   parser (not `net/url`), rebuilds the message, re-signs with the seed and compares, plus
   negatives (other origin, v1). `internal/envelope/authv2_vector_test.go` runs the real
   `Origin`/`AuthMessageV2`/`SignAuthV2`/`VerifyAuthV2` on the same file. To check this, I
   flipped one character of case 0's signature in `vectors.json`: `go run ./tools/verifyvectors`
   exited 1 (`FAIL relay_auth case 0 … signature`, `FAIL relay_auth frame`) and
   `TestAuthV2Vector` failed. The file was then restored byte for byte (`cmp`).
7. **`/healthz`.** See L5. It is unauthenticated by design, and `ServeHTTP` routes it before
   the WebSocket accept.
8. **Author residuals.**
   - (a) The new relay-sourced string ("this relay requires relay auth v2") reaches the daemon
     log through the existing `ErrorFrame` path; no new sink. `cmd/relay` prints only operator
     origins, and `CheckURL` quotes the user's URL with `%q`. H3 stays with 4.2c.
   - (b) See M2: consistent (install never insecure, the URL is baked); the gap is migration,
     not security.
   - (c) See M2: intended by spec, but it breaks upgraded LAN installs and the manual.
9. **Dependency.** `golang.org/x/net v0.58.0` is real: the proxy `.info` gives tag `v0.58.0`,
   2026-08-12, commit `acc78e0d`. It is not retracted (`go list -m -retracted`); `v0.59.0` is
   the newest. It pulls in `golang.org/x/text v0.42.0` (indirect, for `idna`). The other
   `go.sum` changes are checksum lines for newer `x/mod`, `x/sync` and `x/tools` versions.
   `acme/autocert` comes from the existing `x/crypto v0.57.0`. `govulncheck` is not installed
   here, so there was no vulnerability-database scan.
