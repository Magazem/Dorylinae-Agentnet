# R-2.D2: security review of the helper scope and runner (ticket 2.D2)

Review (Opus) of commit 73140ce on `p2/helper-runner`, against Docs/protocol/device.md
(§Link flow, §Scope, §Running, §Limits, §Kinds), ipc.md (§mail_submit), notify.md, D13 and
D22 (HANDOFF §3), OD-P2-10 (a), ticket 2.D2 and review 36 L6–L8. The threat model: a paired
peer that is this device's controller tries to make the helper run anything beyond what its
human approved; a local agent tries to get a misleading scope approved; a relay delays or
reorders mail. Fixes were made in place, with tests.

**Verdict: pass after fixes.** Critical 0, High 0, Medium 2 (1 fixed, 1 fixed on Linux and
documented), Low 11 (5 fixed, 6 noted, of which 2 need an owner decision).

## What holds

- **No request field reaches the command.** `run` is `{"command": name}`, strictly decoded
  and validated (`[a-z0-9._-]{1,64}`); it is only a lookup key into the stored scope. argv,
  path, cwd and environment come from the scope alone. `req.From` is checked against the
  mail sender before routing.
- **argv[0]** is resolved once with `exec.LookPath` (a relative PATH result, `ErrDot` and a
  relative path with a directory part are refused) and stored absolute; the runner uses
  `exec.Cmd{Path, Args}` with no shell. Go's `EscapeArg` builds the Windows command line.
- **Environment:** `cmd.Env` is never nil (no inheritance); only `BaseEnv` plus the scope's
  names; `DORYLINAE_*` is refused at set time and skipped at run time (case-insensitive).
  Tokens, `SSH_AUTH_SOCK` and proxies are dropped unless the human lists them.
- **Windows tree:** `CREATE_SUSPENDED`, assigned to a `KILL_ON_JOB_CLOSE` job before
  `NtResumeProcess`; no `BREAKAWAY_OK`, so `CREATE_BREAKAWAY_FROM_JOB` fails; a daemon crash
  closes the job handle and ends the tree.
- **Output:** a 128 KiB raw tail is kept while running (never unbounded); CSI (ESC [ and
  U+009B), controls, invalid UTF-8 and U+FFFD become `?`; the cut is at a rune boundary; a
  result too large after JSON escaping is shortened from the front until it fits.
- **Queue:** the `device.runs` row is read and written only inside transactions; a restart
  reports a running job `interrupted` and cancels the queued ones; every queued job is
  re-checked against the current scope when it starts; 8 queued, 60 per controller per
  24 h (sliding). An unreadable row resets to empty (only a local writer can do that).
- **Out of scope:** stays `pending` in the normal inbox, no session, and the audit row holds
  request id, peer key and check name only (the e2e test scans every audit row for command
  names, argv, paths and output).
- **Who sets the scope:** `device_scope_set` always needs the human's approval code;
  clearing only narrows. The scope, the pending-approval map and every check are keyed on
  the controller's key (L6 of review 36); `device_scopes.link` is the local link id found
  through that key.
- **mail_submit allowlist** is derived from `daemonKinds` + `withDeviceKinds` (the same
  functions that build the receiver) plus reserved prefixes; `keys`/`ack` included.
- **OnReject** runs exactly once: every path removes the entry from `Store.pending` under
  `s.mu` before calling it, and calls it after unlocking and outside any transaction
  (reject, precondition failure, bad-code rejection, lockout, timer and lazy expiry,
  `RejectSubjects`). A Perform error leaves the approval pending and does not call it.
- **D22:** offers are fresh by the sender's `at`; offers older than the peer's last unlink
  `at` are ignored; `device.linked` uses `notify.Clean` (controls and bidi removed) and is
  never sent to the webhook.

## Medium

### M1: bidi and invisible characters reached the approval summary raw (fixed)

- **Location:** `internal/daemon/device_scope.go` `scopeSummary`.
- **Problem:** the summary JSON-quoted repo paths and argv with `json.Marshal`, which
  escapes quotes and C0 controls but leaves U+202E (right-to-left override), U+2066–2069,
  zero-width characters and other format characters as they are. `device_scope_set` is a
  local IPC call that any agent on the helper can make (for example one steered by a
  controller's request), and the human approves by reading the summary. An argv such as
  `["C:\\…\\tool.exe", "--safe\u202e…"]` can display as something other than what runs, so
  a human can approve a command they did not mean to.
- **Fix:** `device.DisplayQuote`/`DisplayArgv` quote as JSON and then escape as `\uXXXX`
  every non-ASCII rune that is not graphic or is in category Cf (and U+FFFD). Used by the
  summary and the CLI printout (L6). Docs: device.md §Scope. Tests: `TestDisplayQuote`,
  `TestScopeSummaryEscapesInvisibleCharacters`.

### M2: on Unix a daemon crash left the running command alive (fixed on Linux, documented)

- **Location:** `internal/device/runner_unix.go` `startTree`; `device_run.go`
  `recoverAfterRestart`.
- **Problem:** the command runs in its own process group, and nothing ties it to the
  daemon. If the daemon crashes or is killed mid-run, the command keeps running with no
  timeout. The restarted daemon reports it `interrupted` and starts the next queued run, so
  two runs can then execute at once, and the first is no longer bounded by `timeout_s`.
  (Windows is safe: the job closes with the daemon.)
- **Fix:** on Linux the leader gets `Pdeathsig = SIGKILL` (`runner_linux.go`;
  `runner_unix_other.go` is a no-op). Killing the whole group on restart was rejected: once
  the group is gone its id can be reused by an unrelated job-control group, and SIGKILL would
  hit it. What the leader started may still outlive it on Linux, and on macOS nothing is
  killed; device.md §Running now says so. A full fix (cgroup on Linux, recording and
  verifying the group on restart) is left for later.

## Low

### L1: a running command survives scope clear, unlink and scope expiry (owner decision, noted)

- **Location:** `device_run.go` `take`/`execute`.
- **Problem:** only queued runs are dropped. A run already executing finishes, for up to
  its `timeout_s` (at most 1 h), after the human clears the scope or unlinks. This matches
  device.md ("queued runs are then dropped") and `TestHelperQueueClearAndRestart` checks it.
  A human who clears a scope may expect everything to stop.
- **Recommendation:** decide whether clear/unlink should also kill the running tree (keep a
  cancel func for the current run; let the sweep cancel it when `valid` fails, then send
  `ws.cancel`). Not changed here because it changes the spec.

### L2: Unix kill after the leader is reaped can hit a reused group id (noted)

- **Location:** `runner.go` `Run` (the `tree.kill()` after `Wait`), `runner_unix.go`.
- **Problem:** after `Wait` reaps the leader, if no member of the group is left, its id is
  free. A new process could take that pid and make itself a group leader before
  `kill(-pgid)`, which then kills that group. The window is microseconds, and it needs the
  whole group to have exited.
- **Recommendation:** on Linux, use a pidfd or cgroup. Otherwise accept it.

### L3: Windows batch check could be bypassed by a trailing dot or space (fixed)

- **Location:** `internal/device/scope.go` `resolveProgram`.
- **Problem:** Windows drops trailing dots and spaces, so `run.bat.` opens `run.bat`, but
  `filepath.Ext` gave `.`. The rule "never a shell" depended on the extension check alone.
- **Fix:** the extension is judged after trimming trailing dots and spaces, and only `.exe`
  and `.com` are accepted (so `.ps1`, extension-less and other files are refused too).
  Docs: device.md §Scope. Test: `TestValidateScopeRefusesBatchFiles`.

### L4: a program that exited 0 but left a child holding the output reported exit 1 (fixed)

- **Location:** `runner.go` `Run`.
- **Problem:** with `WaitDelay`, `Wait` returns `exec.ErrWaitDelay` when the pipes stay
  open past 5 s after the process ended. That is not an `ExitError`, so the result was
  `fail`, exit 1, for a command that passed.
- **Fix:** on `ErrWaitDelay` the process's own exit code is used. Test:
  `TestRunOrphanHoldingOutput` (the orphan is also killed with the tree).

### L5: the repo path and program were not re-checked when a run starts (fixed)

- **Location:** `device_run.go` `execute`.
- **Problem:** the repo was resolved with `EvalSymlinks` at set time only. If the directory
  is replaced later by a symlink or junction (for example to the config dir, which the scope
  rule forbids), the command runs there.
- **Fix:** `device.CheckTarget` re-resolves the directory and requires the same path, a
  directory, and `argv[0]` still a regular file; otherwise the run is `could not start`.
  Docs: device.md §Running. Test: `TestCheckTarget`. (Binary content is not pinned: see
  L11.)

### L6: `agentnet device scope --show` printed the repo path raw (fixed)

- **Location:** `cmd/agentnet/device_scope.go` `printScope`.
- **Problem:** the path was printed without quoting, so an escape sequence in a directory
  name reached the terminal.
- **Fix:** `DisplayQuote`/`DisplayArgv`, as in M1.

### L7: an offer dated in the future stayed fresh as long as its sender chose (fixed)

- **Location:** `internal/device/device.go` `OfferFresh`.
- **Problem:** only the lower bound (`now < at + 10 min`) was checked. A far-future `at`
  was fresh indefinitely and always passed the unlink watermark. It needs the peer's own
  signature, so only the paired device can do it, but it defeats the D22 intent.
- **Fix:** `at` may be at most 10 min ahead of the receiver's clock. Docs: device.md §Link
  flow. Test: `TestOfferFreshBoundsFuture`.

### L8: kinds passed in `Options.MailKinds` are not refused by mail_submit (noted)

- **Location:** `internal/daemon/outbox.go` `ownedKinds`.
- **Problem:** the owned set is built from `daemonKinds` and `withDeviceKinds`, not from
  `opts.MailKinds`. In production the only extra kinds are the device kinds (covered), and
  tests add `note` on purpose so that it can be sent. The reserved prefixes are the
  backstop for anything new.
- **Recommendation:** if a production caller ever adds kinds through `MailKinds`, derive the
  set from the receiver's final map, minus the debug kind.

### L9: a `device.unlink` `at` in the future pins the watermark (noted)

- **Location:** `device.go` `NoteUnlinkTx`.
- **Problem:** the `at` is taken as sent. A peer that sends a far-future `at` blocks its own
  later offers until then. Only that peer's own link is affected.
- **Recommendation:** clamp to `now + IntentTTL` when a clock-skew bug shows up.

### L10: OnReject reads the approval id through a mutex that Create may not have filled yet (noted)

- **Location:** `device_scope.go` `device_scope_set`.
- **Problem:** if the approval ends before `Create` returns (a window that fails at once),
  the hook sees `""` and leaves `pending` holding the new id. The only effect: a later
  `take` rejects an approval that is no longer pending, and the error is ignored. Separately,
  `expireNow` skips the hook when its DB update fails; the entry is gone and the hierarchy
  slot lapses after `IntentTTL`, as before 2.D2.

### L11: argv[0] is not pinned by content or ownership (owner decision, noted)

- **Location:** `scope.go` `resolveProgram`.
- **Problem:** the stored path protects against a PATH change, not against the file being
  replaced. A program in a directory that others can write to (a shared tool dir, or the
  repo itself: `./gradlew`) can be swapped after approval.
- **Recommendation:** refuse, at set and run time, a program whose file or directory is
  writable by others (Unix mode bits, Windows ACL). Or store a hash and compare at start
  (costly for large binaries). The human sees the path in the summary.
