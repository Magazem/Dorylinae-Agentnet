## Medium

### M1: a dry run's SHA256SUMS signed with the real key could be installed as 0.1.0 for ever

**Where:** `release.yml` `workflow_dispatch.inputs.version` (default `0.1.0`), the `meta`
job, and the draft notes (step 2: `sign -key <offline key>` for dry runs too).

**Defect.** Anyone with write access can start a dry run from any branch, so its binaries
are unreviewed. Its default version is `0.1.0`, which equals `AGENTNET_MIN_VERSION`, and it
is also the likely first real release. The dry-run notes tell the owner to sign with the
offline key. An owner who rehearses the flow would produce a signature that stays valid for
ever for those bytes. Later, anyone able to replace the GitHub assets (a leaked token: the
exact threat D36 is meant to stop) could serve that dry-run SHA256SUMS and its archives. They
would pass `install.sh` as 0.1.0, or `--version 0.1.0`. Nothing binds a signature to a
reviewed commit.

**Fix.** Dry-run versions must now be `0.0.Z` (default `0.0.1`), and `meta` refuses anything
else. That is below any `AGENTNET_MIN_VERSION` (≥ 0.1.0, only ever raised), so `install.sh`
refuses a dry run as a rollback even if the real key signed it. The dry-run draft notes now
say `<a TEST key; never sign a dry run with the release key>`, and
`Docs/ops/release-signing.md` explains why.

The release.yml install-sh job tests the real dry-run archives, so the test copy of
`install.sh` in `tests/install/run.sh` now sets its minimum to the version under test. The
"too old" fixture is now 0.0.0, which `run.sh` refuses to test against.

## Low (fixed)

- **L1** `install.sh` is now one `main() { ... }` called on the last line; the key and
  minimum lines stay at top level so `releasesign embed` still matches them. Measured before
  the fix: 13 of 311 line-prefixes piped to `dash` left files behind (the install dir, or an
  install without its closing messages). After: 0 of 326. This is now a case in
  `tests/install/cases.sh` (`truncated-script-runs-nothing`).
- **L2** `tar -xzf ... agentnet agentnetd` extracts only the two members, and each must be a
  regular file (`-f` and not `-h`). The archive is already hash-checked against the signed
  sums, so this is defence in depth. There is a new signed `symlink` fixture (agentnet →
  `/etc/passwd`, plus an extra member) and case `symlink-in-archive`.
- **L3** wget: GNU wget's `--https-only` applies only to recursive downloads, and BusyBox
  wget (Alpine's default, where curl is often missing) rejects it, so every install failed
  there. Now GNU wget gets `--secure-protocol=TLSv1_2` and BusyBox wget gets no options. An
  http mirror still needs `AGENTNET_ALLOW_INSECURE_URL=1`, and the signature is the control.
- **L4** `doctor` re-parses `min_client` with `version.ParseRelease` before printing it
  (the daemon already drops junk; this covers a daemon/CLI mismatch). New test case
  `junk minimum` (`"9.9.9\x1b[2J"` → ok, not shown).
- **L5** A compromised build *before* the owner signs is signed with it. The texts now say
  "after the owner signed them … cannot catch a build that was already bad". Spec 49 line
  ~207 still has the old sentence (owner/spec text; not edited).
- **L6** Every `actions/checkout` in `release.yml` has `persist-credentials: false`.

## Low (open / owner)

- **L7 (owner decides)** Pin actions by full commit SHA, at least in the `draft` job (the
  only one with `contents: write`; it runs `actions/download-artifact@v4`) and in `build`.
  Dependabot can keep SHAs current.
- **L8 (owner decides)** Add a repository ruleset so only the owner can create `v*` tags,
  and `environment: release` with a required reviewer on the `draft` job.
- **L9** Rollback protection is only `AGENTNET_MIN_VERSION`: raise it with every release
  that fixes a security bug (already in the runbook).
- **L10** Add a macOS case (e.g. in the `homebrew` job: `brew install minisign`, then
  `install.sh` with a test key and LibreSSL's `openssl`) so the macOS route is proven
  against Homebrew's minisign version.
- **L11** Write to a `mktemp` name inside the install dir. This only matters if the dir is
  writable by others, which the default `~/.local/bin` is not.
- **L12** On Windows, keep the key on an encrypted medium (the runbook says so); `0600` is
  not an ACL there.
- **L13** Consider `cache: false` in all release jobs, so a cache written by `main` can
  never reach release tooling.
- **L14** Pre-existing; fix in a CI chore.

## Checked and fine

- **install.sh.** The version regex is 9 digits max (fits `-gt`). `version_ge` is correct.
  One version per SHA256SUMS; `--version` must match. The full-line regex is anchored and
  rejects CR, blank and extra lines. `awk $2 == f` selects exactly one sum, and a duplicate
  line yields a multi-line value that fails the compare. OpenSSL `3–9.x` / `1x.x` detection;
  "LibreSSL …" never matches. With neither verifier the script stops and prints routes. The
  `AGENTNET_DOWNLOAD_URL` override keeps the signature check; http needs the explicit opt-in.
  curl uses `--proto =https --proto-redir =https --tlsv1.2 -f`. The temp dir comes from
  `mktemp -d` and is removed on EXIT, so there is no TOCTOU between verify and unpack.
  There is no sudo. The binaries are replaced by same-dir `mv -f`. Run locally under `dash`
  and bash-as-`sh` with OpenSSL 3.5 against signed fixtures: good, rollback, flipped sums,
  wrong key, asked-too-old, asked-other, placeholder and pipe cases all behave as expected.
- **releasesign.** The legacy minisign format matches minisign: `Ed` ‖ keynum ‖ sig; the
  global signature is over sig ‖ trusted-comment text; the key id is derived, which minisign
  allows. CI proves `minisign -V` accepts it. `embed` counts exactly one match per line and
  uses `ReplaceAllLiteralString`; PEM/base64 cannot contain `'`. `keygen` uses `O_EXCL`,
  `0600`, and prints only public values. `sign` refuses to overwrite and self-verifies.
  `ed25519.Verify` returns false on a wrong-length signature.
- **release.yml.** Top-level permissions are `contents: read`; `contents: write` is set only
  on `draft`. Every `${{ inputs.* }}` and ref name goes through `env` and is validated with
  the X.Y.Z regex. `GOFLAGS: ""`, `CGO_ENABLED=0`, `-trimpath`, `cache: false` in `build`.
  `go version -m` fails on any `-tags` and needs the version ldflag (no `testhooks` tag
  exists in the tree today). `workflow_dispatch` with `dry_run=false` is refused. The
  release is created `--draft` only and asserted `isDraft`. A rerun is refused because the
  release name exists (`gh release view` also finds drafts). A draft creates no tag.
- **min_client.** The relay validates at `Open` and at the flag. The client keeps it only
  if `ParseRelease` passes (a test covers the ESC-sequence case). `status` prints it only
  when both versions parse. It never affects the connection.
