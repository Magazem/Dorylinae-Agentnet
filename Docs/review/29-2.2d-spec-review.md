## What holds (checked, no finding)

- **No code path for an agent.** With `approval_confirm` and the `approve <a-id> <code>` form
  removed, a code reaches the daemon only through the window's stdout pipe (held by the
  daemon) or, in terminal mode, the daemon's own stdin. `approval_open` only shows a window
  and is audited; `approval_reject` only removes access. Nothing under `DORYLINAE_DEBUG` adds
  an entry path in desktop mode (made explicit, M6).
- **Terminal mode when an agent starts the daemon.** An agent's shell has pipes, not a TTY,
  so the daemon refuses to start unless `DORYLINAE_DEBUG=1`. Starting it with that variable
  means starting and configuring `agentnetd`, which is the stated OD-P2-2 boundary (and the
  snippet already puts `agentnetd` off limits). The service definitions set neither variable.
- **Injection on Windows and macOS.** The text travels through the environment into
  fixed scripts, the WinForms `Label.Text` and AppleScript strings are not interpreted, and
  the code never reaches the dialog. Phishing with a fake window gets a code that cannot be
  submitted anywhere.
- **Stray input cannot approve.** Approval needs the 6 digits from the notification. The worst
  a stray keystroke can do is reject, dismiss, or use one attempt.
- **Process lifetime.** A Job object with `KILL_ON_JOB_CLOSE` and `Pdeathsig` are both
  available without cgo or admin rights. An orphaned window's answer has nowhere to go, and a
  restart expires every pending approval.
- **Windows session.** The service task uses `LogonType InteractiveToken`
  (`internal/service/schtasks.go:77`), so the installed daemon runs on the user's desktop.
- **2.H harness.** Pipes plus `DORYLINAE_DEBUG=1` keep working, and the agent never holds
  either pipe.

## High

**H1. D18 cannot be done "in the same transaction" as written, and it misses cases.**
Location: `work-session.md` §Early complete step 1 and §inbox-copy-d18. Problem:
`receiver.store` runs the kind's `Apply` and only **then** inserts the `mail_inbox` row
(`internal/mail/receiver.go:201-216`), so an `UPDATE … SET signed=''` from the early-complete
`Apply` hits no row, and the plaintext is inserted afterwards. For a discard, the rows "of
the quarantined round" cannot be found: `mail_inbox` has no session or round, and
`work_sessions` keeps no mail id (`store.go:245`). Every `Inbox: true` kind is stored even
when `Apply` ignores it, so a `ws.result` for a stale round or a closed session (B can send
any number of them under new ids) keeps its plaintext for ever. The `ws.cancel` reason that
§Quarantine says "is not stored" is stored too. Fix (applied): the copy is **stored blank at
receipt** whenever `Apply` marks the content as withheld or dropped. That covers a quarantined
`ws.result`, an ignored `ws.result`, a dropped early complete, and `ws.cancel` under the
quarantine rule. Discard then has nothing to update. The test also covers receipt and the
stale-round case.

## Medium

**M1. Linux: a systemd user unit often lacks `DISPLAY`/`WAYLAND_DISPLAY`.** Location: the
Linux row of the table. Problem: `agentnetd.service` is `WantedBy=default.target`
(`internal/service/systemd.go:66`) and often starts before the desktop imports its display
variables into the user manager. It captures its environment once, so `approval_window`
stays `missing` on ordinary desktops. Fix (applied): take `DISPLAY`, `WAYLAND_DISPLAY`,
`XAUTHORITY` and `XDG_RUNTIME_DIR` from the systemd user manager's `Environment` property,
read in-process over godbus (already a dependency) at each opening.

**M2. Linux program resolution is `/usr/bin` only, and a missing helper gives no guidance.**
Problem: NixOS has no `/usr/bin/zenity`, and nothing checks that the file is trustworthy. A
user without the helper gets `approval_unavailable` without being told what to do. Fix
(applied): use a fixed candidate list (`/usr/bin`, `/bin`, `/run/current-system/sw/bin`)
with a root-owned, not group- or world-writable check, never `PATH`. Flatpak is stated as
not found. The message and `status` name the fix (install zenity or kdialog, or use
terminal mode). No automatic fallback, as D19 decided.

**M3. Linux argument injection and markup.** Problem: with the `--text …` two-argument form
and kdialog's positional handling, a summary that starts with `--` sits next to option
parsing. It is also unverified that zenity accepts `--no-markup` together with `--entry`. If
it rejects it, the ready check fails; if it ignores it, peer markup (a large bold decoy)
renders. Fix (applied): every value is a single `--opt=value` argument and never a
positional one. Text is markup-escaped for both tools unless the manual check proves that
`--no-markup` works with `--entry` on Ubuntu 22.04 and 24.04.

**M4. A notifier failure after the window is ready is unspecified.** Problem: the window
opens before the notification, but the spec does not say what happens if the toast then
fails. The result could be a live window whose code nobody can see, and a stored row. A
related case: a daemon in session 0 or an SSH logon fires `Shown` on a desktop nobody sees,
so the ready check passes. Fix (applied): if the notification fails, the daemon kills the
window and stores nothing (`approval_unavailable`). On Windows the window is `missing`
unless the session id is not 0 and the window station is `WinSta0`.

**M5. `grant.md` still says the CLI prompts for the code.** Location: `grant.md` §CLI.
Problem: "Prompts for the approval code on a terminal" contradicts D19. Fix (applied): the
command prints the approval id, returns `pending` and never prompts.

**M6. Debug and test hooks are not fenced.** Problem: the acceptance tests need a fake
dialog, and 2.H uses `DORYLINAE_DEBUG`. The spec did not rule out a convenience env var or
config key that swaps the dialog or reads answers from stdin in desktop mode, and that
would be a code path for an agent. Fix (applied): no env var, flag, config key or
`DORYLINAE_DEBUG` changes the program, script or answer source. The runner is swapped only
inside Go test code. A desktop-mode daemon never reads its stdin. There is an acceptance
test for this.

## Low

- **L1 (fixed).** Job assignment right after `Start`: a failed assignment kills the process
  and counts as not ready. `CREATE_NO_WINDOW` stops a console flash. `Pdeathsig` belongs to
  the starting **thread**, so the window is never started from a goroutine that calls
  `LockOSThread`.
- **L2 (fixed).** Derive the PowerShell path from `GetSystemDirectory`, not from
  `%SystemRoot%`. The existing approval toast and its removal call `powershell.exe` through
  `PATH` (`internal/notify/approval_windows.go:54,63`) and switch to the same path.
- **L3 (fixed).** The 1 s input guard counts from each `Activated`, not only from `Shown`,
  because a background process usually cannot take the focus. The TextBox is focused first,
  so Space cannot press Reject. Windows are cascaded.
- **L4 (fixed).** macOS: `activate` first, so the dialog is not hidden behind other windows.
  There is no `default button` and no `cancel button`. The manual check includes a
  non-ASCII name (`system attribute` decoding).
- **L5 (fixed).** Do Not Disturb or Focus Assist hides the toast. The window tells the
  human to look in the notification centre.
- **L6 (fixed).** zenity and kdialog cannot print `approve <digits>` themselves, so the daemon
  maps their exit status (0 → approve, extra button → reject, other exits including 5 →
  dismiss). An answer that arrives before the notification has been shown counts as dismiss.
- **L7 (listed).** Blanked bytes can stay in SQLite free pages and the WAL until they are
  reused. Only a reader of the database file sees them, which is outside the boundary.
  `PRAGMA secure_delete=ON` is a cheap later hardening step.
- **L8 (listed).** Up to 5 TopMost windows plus `approval_open` let an agent be a nuisance,
  not a threat: every reopen is audited and any caller can reject. Consider rate-limiting
  `approval_open` per approval if the audit shows abuse.
- **L9 (listed).** kdialog has no Reject button (already stated). The human rejects with
  `agentnet approve --reject`, which any caller can also run. That is harmless.
