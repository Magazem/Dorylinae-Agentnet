# T5: The audit/log never-contains-content invariant, and privacy

Reviewer: TH-T5 · model claude-opus-5-5 · elapsed ~240 min wall clock (includes a usage-limit pause; about 60 min active) · commit 6cc26a7

## Summary

| Critical | High | Medium | Low | Info |

| 0 | 0 | 0 | 1 | 2 |

Verdict: invariant 1 holds for the audit log. All 100+ `Append`/`AppendTx`/wrapper call sites
(inventory below) write only ids, keys, enums, counts, sizes, hashes and booleans. Peer-supplied
enums (request type and urgency, `ws.state` state, `verification`, debate outcome and reason,
decline code) are validated before they are audited. The two places where peer- or relay-chosen
strings reach `audit_events` are already chunk findings: C06-02 (relay `error` text, and
`agentcard`/announcement error text quoting peer member names, in `pair.fail.reason`) and C07-02
(relay-chosen envelope `id` in `mail.reject`, peer-chosen unknown `kind` in `mail.in`). No secret
(seed, mailbox key, approval code, pairing secret/K, webhook secret or URL) reaches the audit log,
a log line, or an error sent to a peer. Errors sent to peers are enum codes. The relay's logs, the
journal and `/metrics` carry only 8-character key prefixes, ids, sizes, account ids and limit
names, which matches envelope.md §Logging rule and relay-hosted.md "What the hosted relay learns".

New items:
- **T5-01 (Low):** the relay's `error` text (up to 1 MiB, unfiltered) is also written to the
  daemon log at every reconnect. One such line exceeds the 1 MiB rotation size, so the relay can
  erase the daemon's log history at will. This is a new sink for the C04-01/C28-01 root cause.
- **T5-02 (Info):** `TestAuditInventoryIsComplete` cannot see the five `debate.*` mail kinds, so
  a new debate kind without an audit row would not fail it.
- **T5-03 (Info):** the no-content tests scan only `audit_events.detail`. No test searches the
  daemon log, the outbox/webhook error columns or the relay log/queue of the e2e runs for
  content markers.

## Findings

### T5-01 · Low · confirmed-read
- **Where:** `internal/relayclient/relayclient.go:223-229` (`lastErr = err.Error()` and
  `c.log.Warn("relay connection lost", …, "error", err, …)`), root `internal/relayclient/wire.go:28-29`
  / `internal/envelope/frames.go:338`; sink `internal/logfile/logfile.go:14` (`MaxSize` 1 MiB),
  `cmd/agentnetd/main.go:101`
- **What goes wrong:** the relay's handshake `error` frame text (code plus message, up to the
  1 MiB frame, any characters) is written into the daemon log on every reconnect. One such line
  exceeds `logfile.MaxSize`, so each one rotates the log. Since only `<path>` and `<path>.1` are
  kept, two relay-triggered reconnects erase all earlier history. On macOS the launchd log is
  unrotated (C16-02), so the same text grows the disk by about 1 MiB per reconnect, at the
  relay-driven reconnect rate (C04-02, about 2/s).
- **Scenario:** a hostile or compromised relay answers each upgrade with
  `{"op":"error","code":"x","message":"<1 MiB>"}`. The daemon logs about 1 MiB per attempt
  (backoff 0.5–30 s, or about 2/s with the C04-02 `ready`-then-close trick). Within seconds, the
  lines an owner needs after an incident (`audit write failed`, `mail rejects not audited`,
  `session: peer lookup failed`, keychain fallback warnings) are rotated out. The TextHandler
  quotes the value, so there is no line injection. The impact is loss of the daemon's own
  diagnostics, controlled by the relay.
- **Spec:** `Docs/cli/status.md:94-96` (`last_error` is "content-free"); rubric §1, relay row
  ("grow its memory/disk without bound"); `Docs/cli/agentnetd.md:21` (the log rotates and keeps
  history).
- **Fix direction:** the C28-01 fix (keep only a validated `code`, drop or clip the relay
  `message`) also fixes this sink; log the clipped value.
- **Related:** C28-01 and C04-01 (same root, `status`/`doctor` sink), C16-02 (unrotated macOS
  log), C08-05, O-051 (log volume), C04-02.

### T5-02 · Info · confirmed-read
- **Where:** `internal/daemon/audit_inventory_test.go:131-134` (`kindsRE` matches only string
  literals, `kindConsRE` only `Kind…` constants in `../request`, `../worksession`, `../device`),
  `:113-132` (`mailKindInventory`); registrations `internal/daemon/mail.go:272-276`
  (`kinds[debate.MailEntry]` … `kinds[debate.MailSign]`); constants `internal/debate/store.go:24-26`,
  `constraint.go:23`, `decision.go:25`
- **What goes wrong:** the five `debate.*` mail kinds are registered through constants named
  `Mail…` in `internal/debate`. Neither regex sees them, and `mailKindInventory` does not list
  them. `TestAuditInventoryIsComplete` therefore passes without them, and a new debate kind
  added without an audit action would not fail it, which is the guarantee audit.md §Scope states.
  Today every debate kind does audit (`debate.entry_in`, `debate.reveal_in`, `debate.close_in`,
  `debate.constraint_in`, `decision.sign_in`/`decision.refuse`).
- **Scenario:** none today (test gap).
- **Spec:** `Docs/protocol/audit.md` §Scope: "a method added without an entry fails the build of
  the test suite" (the same for mail kinds).
- **Fix direction:** add `../debate` with a `Mail[A-Za-z]*\s+=` pattern, or scan `kinds\[` for
  any key expression, and list the five kinds.
- **Related:** C23, C24.

### T5-03 · Info · confirmed-read
- **Where:** `internal/daemon/e2e_1_9_test.go:259-266`, `e2e_2_9_test.go:286-299`,
  `e2e_3_9_test.go:275-281` (only `allAuditRows` details are scanned)
- **What goes wrong:** invariant 1 covers audit, **logs**, webhooks and peer-facing errors, but
  the three marker tests read only `audit_events.detail`. The daemons' slog output, the outbox
  and webhook `error` columns, the webhook payload with `title:false`, and the e2e relay's log
  are never searched for the markers. My read of the log inventory (Q2) found no leak today,
  but nothing would catch a future `log.Warn(…, "body", …)` or an `err` wrapping a body.
- **Scenario:** none today (test gap). A regression that logs an `Apply` error carrying a
  debate member name or a request title would pass CI.
- **Spec:** rubric §1 invariant 1; audit.md "No content, still"; notify.md §Privacy summary.
- **Fix direction:** give the harness daemons a buffer logger (and the relay a captured log) and
  assert that no marker appears there or in the `outbox.error`/webhook queue rows.
- **Related:** C30-01, C31-07 (script-level variants), R10 M2 pattern.
