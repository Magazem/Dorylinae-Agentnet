# Verify C16-01
Verifier: V-C16-01 · model claude-opus-5-5 · elapsed ~12 min · commit 6cc26a7
**Outcome:** confirmed (High)

**Claim restated:** On Windows the IPC pipe name is a predictable name in the machine-global
`\\.\pipe\` namespace, and neither the server nor the client checks who owns the pipe. Another
OS user who creates that name first therefore (a) makes the victim's `agentnetd run` exit as
"already running", and (b) receives every IPC request from the victim's CLI and agents, and can
answer them with forged results.
Precondition: the attacker has a process on the same PC, as a different user or a service,
that creates the pipe while the victim's daemon is not listening. That window exists before the
victim logs on, after a reboot, after a crash and after `agentnetd stop`.

**Path traced (from entry points):**
- Name: `internal/paths/paths.go:68-72` sets `endpoint(dir)` to `\\.\pipe\dorylinae-` + hex(sha256(dir)[:8]).
  The dir is `os.UserConfigDir()/dorylinae`, which is `C:\Users\<name>\AppData\Roaming\dorylinae`
  by default (ipc.md §Endpoint). Any user can list `C:\Users`, so anyone can compute the name.
  The name contains no secret and no SID.
- Daemon start: `cmd/agentnetd/main.go:114` calls `daemon.RunWithOptions`, which calls
  `internal/daemon/daemon.go:283` `ipc.Listen`, which calls `internal/ipc/transport_windows.go:27`
  `winio.ListenPipe`. go-winio v0.6.2 `pipe.go:380` creates the first instance with `FILE_CREATE`.
  Because the name already exists, the call fails, and `:31-32` maps ACCESS_DENIED to
  `ErrAlreadyRunning`. Then `main.go:115-121` calls `runningPID`, which runs `ipc.Call("status")`
  against the squatter (`main.go:135-143`), prints the squatter's PID and returns exit 3. No
  retry or ownership check follows. `Listen` also runs before any audit, so the victim's log
  shows no trace.
- Client: `internal/ipc/ipc.go:229-280` `Call` calls `Dial` (`transport_windows.go:40-50`
  `winio.DialPipeContext`) and then sends the request JSON. Nothing inspects the server
  process, owner or SID. The squatter's response is decoded and trusted. `cmd/agentnet/log.go:307`
  dials the same way. `stop.go:44` `StopWait` goes through the same path.

**Checks that could block it:**
- Victim's pipe DACL (`transport_windows.go:26`, owner SID only). It does not block: the DACL
  applies only to a pipe the victim creates. With the victim's daemon up, the attacker cannot
  add an instance, because FILE_CREATE_PIPE_INSTANCE is denied. That is why the scenario needs
  the daemon-down window. It does not protect against a pipe that already exists.
- Session isolation. It does not block: NPFS pipe names are global across logon sessions.
  There is no `Local\` namespace for pipes, unlike named kernel objects.
- Pipe-creation restrictions in Windows 10/11. These apply only to AppContainer and
  low-integrity processes. A normal medium-integrity user or a service can create any unused
  pipe name.
- Remote access. Not relevant: `FILE_PIPE_REJECT_REMOTE_CLIENTS` concerns remote clients. The
  attacker here is local.
- Impersonation of the victim by the squatter. Blocked: go-winio dials at
  `PipeImpLevelAnonymous` (`pipe.go:264,273-275`). This matches the reviewer's own caveat and
  limits the impact to data, forged results and DoS.
- Spec or owner decision. None accepts the behaviour. `Docs/protocol/ipc.md:13` promises
  access for "the current user's SID only". The rubric §1 says another local OS user must never
  read the IPC endpoint. Not in 02-open-findings (O-203 is the Unix long-path issue). No prior
  review raised pipe squatting (grep of `Docs/review/*.md`).

**Test:**
- The reviewer's test `internal/ipc/zz_review55_C16-01_test.go`, run with
  `go test ./internal/ipc -run TestReview55C16_01PipeSquat -count=1 -v`, passes (the test
  asserts the vulnerable behaviour):
  `squatter received: {"id":"1","method":"mail_submit","params":{"body":"secret content"}}; client accepted forged result map[pid:4242]`.
  `Listen` returned `ErrAlreadyRunning`, which is the stated reason and not an unrelated error.
- Limit: the test runs as a single user. I have no second account on this PC, so the
  cross-user leg is confirmed by reading only.
  - With the squatter's Everyone:GA DACL, the victim's access check is the same as in the
    test. Pipe ownership does not enter the FILE_CREATE collision or the client open.
  - I tried a variant with a SYSTEM-only squatter DACL to simulate a foreign owner. It is not
    usable: go-winio's own second-instance create fails with "Incorrect function" when the
    creator is not in the DACL. I deleted that file.
- A two-account manual check would settle the last bit: user B runs the squat test's listener
  on the name of user A's pipe, then user A runs `agentnetd run` and `agentnet status`.

**Severity reasoning:**
- The actor is "another local OS user" (rubric §1). That row says it must never read the IPC
  endpoint.
- Impact:
  - Content from IPC requests reaches another user: `mail_submit` bodies, request and debate
    text.
  - The victim's local agents get forged `inbox`/`status` results, which can carry a
    prompt injection.
  - The victim's daemon stays down for as long as the squatter holds the name.
- Critical does not fit: its reachability clause names only the relay, strangers and paired
  peers.
- High fits: "a core security property breaks, but the attacker needs a narrower position"
  (a local account plus a daemon-down window).
- It is not Low under the "owner's own mistake" rule, because it needs no misconfiguration by
  the victim. The High rating stands.
