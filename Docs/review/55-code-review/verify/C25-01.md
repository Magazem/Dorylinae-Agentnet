# Verify C25-01
Verifier: V-C25-01 · model claude-opus-5-5 · elapsed ~8 min · commit 6cc26a7
**Outcome:** confirmed

**Claim restated:** `agentnet decision verify FILE` (human output, no `--json`) prints
`Result.Reason` raw, and for a file with an unknown member the reason carries the
attacker's JSON member name verbatim (after JSON unescaping, so `\r`, `\n`, ESC are real
control bytes); a crafted name overwrites the "invalid" line with a fake "valid, signed by
initiator and respondent" verdict plus the expected fingerprint lines.
Precondition: the user runs `decision verify` on a file someone else supplied (the command's
purpose, decision.md "A valid file proves…"; C25 entry points: "anyone can hand you a file")
and reads the human output rather than `$?`/`--json`.

**Path traced:**
1. `cmd/agentnet/decision.go:58-59` `decision verify` → `runDecisionVerify` (`:287`).
2. `:308` `readDecisionFile`: only a size cap (8 MiB, `:360-373`); no content filtering.
3. `:312` `decision.Verify(data, debate.DecisionSchema())`.
4. `internal/decision/verify.go:60` `agentcard.ParseStrict` (`internal/agentcard/canonical.go:24-81`):
   checks UTF-8, duplicate keys, trailing data. It does **not** restrict key characters;
   `encoding/json` unescapes `\r`, `\n`, `\u001b` in keys into raw bytes.
5. `verify.go:68` `members("", file, {"decision","hash","signatures"}, nil)`: required
   members present, then `:180` `fmt.Errorf("unknown member %s", name(k))`, with the raw key and no `%q`.
6. `verify.go:69` `fail(res, 1, "%v", err)` → `Reason` = that string.
7. `decision.go:334-335` not `--json` → `printDecisionVerifyHuman` → `:387`
   `Fprintf(w, "invalid at step %d: %s\n", res.Step, res.Reason)`, raw to stdout.
The same pattern holds for nested members (`members("signatures", …)`, `checkSchema`'s
`members` calls) and for embedded entries via `internal/debate/decode.go:322-323` →
`fieldErr(member(field,k), …)` (`internal/debate/schema.go:59,170`), which also has no quoting.

**Checks that could block it:**
- ParseStrict strictness: rejects bad UTF-8/dups only; control chars in keys pass. Does not block.
- Size cap: irrelevant (payload is ~200 bytes).
- `termSafe` (`cmd/agentnet/fetch.go:267`) exists in the package but is not applied to
  `Reason` or anywhere in `decision.go`. Does not block.
- Exit code 1 and `--json` output are correct (`decision.go:316-317`, `:322-333`), so scripts
  and `$? -eq 0` checks are not fooled. `--md` renders nothing for an invalid file
  (`:337`), which is a hint only if the user passed `--md`. None of these reaches the human reader of the plain output.
- Terminal: a bare `\r` is enough (no VT processing needed). The spoofed text is longer than
  the 34-byte prefix `invalid at step 1: unknown member `, so it fully overwrites that prefix
  on conhost, Windows Terminal and Unix terminals alike. ESC `[2K` adds a clean erase where VT is on.
  The format string then adds only `\n`, so nothing trails the fake verdict. The cmd/agentnet
  code never calls `SetConsoleMode`, and none is needed.
- Spec/decisions: decision.md step 6 defines the report and says the reader compares
  fingerprints from "the verify output"; no D-decision makes raw reasons intended.
- Duplicate check: O-100 / R48 L2 cover *validated* request titles/texts (C1/bidi) in
  `inbox`/`request show`/`debates`/`decisions`. This is a different source (arbitrary
  unvalidated file keys, C0 incl. CR/LF), a different command, a weaker actor (no pairing needed),
  and a spoofed security verdict. So it is not a duplicate. Related: O-100.

**Severity reasoning:** I re-rated it independently and it stays **High**.
- Not Low: Low needs "display fidelity of attacker-controlled text that **cannot hide or spoof
  anything important**". This spoofs the one important output, the signature verdict and the
  fingerprints a reader is told to compare.
- No Medium criterion fully fits. There is a direct exploit, so "spec deviation … no direct
  exploit" does not apply, and it is not a DoS, leak, race or repairable state.
- High fits: "A core security property breaks … **or** the impact is bounded". The property
  is that `decision verify` tells a human whether two keys signed a Decision. Anyone
  (weaker than a paired peer) can make a forged Decision *look* mutually signed. Invariant 4
  (peer input must not drive our terminal, "at least Medium, usually High") also applies.
- Not Critical: nothing is forged in any machine-checkable state. The exit code, `--json`
  and `--md` stay correct, no daemon stores or acts on it, and the attack only works if the
  human relies on the plain-text line. That bounded impact is the High criterion.
