# Verify T13-01
Verifier: V-T13-01 · model claude-opus-5-5 · elapsed 2 min (system clock) · commit 6cc26a7

**Outcome:** confirmed (High)

**Claim restated:** on macOS 10.15+, a local agent can pass issuance step 3 with the
Data-volume spelling of a forbidden resource (`/System/Volumes/Data` + config dir, + home,
or `/System/Volumes/Data` itself), because `validateResource` compares path strings and
`filepath.EvalSymlinks` does not resolve firmlinks. Precondition: a requester session with
the peer is open, and the human approves the grant (or a policy created the same way was
approved once).

**Path traced:**
1. IPC `grant_create` (`internal/daemon/grant.go:380`) → params checks (`:385-390`) →
   session step 1 (`:396-411`) → D5 (`:413-415`) → `splitResource` + `validateResource`
   (`:419-420`). Same function from `grant_policy_add` (`:885`) and device scope repos
   (`internal/daemon/device_scope.go:136`).
2. `validateResource` (`grant.go:133-162`): `IsAbs` ok; `EvalSymlinks` walks components with
   `Lstat` and replaces only `ModeSymlink` entries. `/System`, `/System/Volumes`,
   `/System/Volumes/Data` (a mount point) and `…/Data/Users/<me>` are all plain directories,
   so the input comes back unchanged. `os.Stat` → directory, ok.
3. Config-dir check (`:146-150`): `cfg` = `EvalSymlinks(configDir)`. `configDir` comes from
   `os.UserConfigDir()` (`internal/paths/paths.go:34`) = `$HOME/Library/Application Support/…`
   with `$HOME=/Users/<me>`; `/Users` is a firmlink, not a symlink, so `cfg` stays
   `/Users/<me>/…`. `pathEqualOrContains` (`:181-187`) works on `foldPath` strings
   (`Clean` + lower-case, `:170-176`) and `filepath.Rel`: `/users/me/…` vs
   `/system/volumes/data/users/me/…` are neither equal nor nested → passes.
4. Home check (`:151-155`): `pathsEqual` on strings → `/System/Volumes/Data/Users/<me>` ≠
   `/Users/<me>` → passes.
5. Root check (`isFilesystemRoot`, `:209-216`): on unix only `p == "/"` → `/System/Volumes/Data`
   passes (it also contains the config dir and home under their Data spelling, which step 3
   does not see).
6. Approval Precondition `recheckResource` (`:777-791`) runs the same `validateResource` on
   the stored resolved path, which resolves to itself → passes; grant becomes active.
7. Serving: `capability.openRoot` (`internal/capability/fs.go:231`) does `os.OpenRoot(rec.Path)`
   with no further forbidden-path check; the scope/walk rules only confine requests to below
   that root.

**Checks that could block it:**
- `EvalSymlinks` canonicalisation: does not apply; firmlinks are not `ModeSymlink` (documented
  Apple behaviour since Catalina: the system volume's `/Users` firmlinks to the data volume's
  `/System/Volumes/Data/Users`; both spellings are the same inode).
- Case folding / O-135 (NFC/NFD): orthogonal, string-based only.
- Serving-side exclusion of the config dir or dotfiles: none found in `internal/capability`
  (grep for config dir / `.ssh` / forbidden: no hits outside errors).
- TCC (macOS privacy): does not protect `~/Library/Application Support/<app>` of the daemon's
  own files, nor `~/.ssh`; the daemon reads its own DB already. Not a block.
- Human approval: required, but the window shows only the label (`deriveLabel`, `grant.go:294`,
  basename-derived, e.g. `dorylinae-…`/`me-…`/`data-…`, see C11-01). This is the gate the
  step-3 refusal exists to back up; the spec makes the refusal unconditional.
- No owner decision or spec text allows these paths; `Docs/protocol/grant.md:122-124` refuses
  them by meaning, not by spelling.

**Severity reasoning:** rubric §2 High, "A core security property breaks, but the attacker
needs a narrower position (a local agent via IPC …)". Actor: a local (possibly
prompt-injected) agent via IPC, plus one human approval that the misleading label makes
likely. Impact once approved: a paired peer reads the DB (mail, requests, audit), key files
with the file keystore, `~/.ssh`, or everything under the data volume. Not Critical: not
reachable by relay/stranger/peer alone. Same class and level as C11-04 (Windows `\\?\`/UNC);
the consolidator may merge them under one file-identity fix.
