**Outcome:** confirmed (High)

**Claim restated:** The `device_link` and `device_scope_set` approvals show the human only the peer's
self-chosen name and the role, never its fingerprint, while the fingerprint that "binds" the link
arrives as an IPC parameter the (possibly prompt-injected) local agent supplies. A hostile paired
peer that shares the name of the user's real other device can therefore be linked as controller or
helper with a human confirmation that cannot tell the two keys apart.
Precondition: (a) a paired peer X whose card name equals the user's other device (any trust other
than `relay` on a non-loopback relay); (b) a local agent that is prompt-injected (or simply picks the
wrong key); (c) the human starts a link on both devices and confirms the window.
