# C25: Decision record: build, sign, verify, Markdown export

Reviewer: CR-C25 · model claude-opus-5-5 · elapsed 4 min (per `date`) · commit 6cc26a7

## Summary

Critical 0 · High 1 · Medium 0 · Low 0 · Info 1.

The cryptographic core holds. A tampered file, or one signed only by the initiator, cannot
exit 0. Every step of decision.md §Signed file is implemented in order, and every step-5
invariant is present. The Markdown renderer keeps all peer text in fences or code spans after
`Visible` and `TemplateInert`, and I found no way out of them. `--out` is atomic and refuses a
dangling symlink. The one real defect is in the CLI's **human** output of `decision verify`. On
an invalid file it prints the failure reason unescaped, and that reason can contain a JSON
member name from the attacker's file. A `\r`, a newline or an ESC sequence in that name can
overwrite the "invalid at step 1" line with a forged "valid, signed by initiator and
respondent" verdict and forged fingerprints. The exit code (1) and `--json` output stay
correct.

## Questions

1. **Can a single-signed or tampered file verify as confirmed (exit 0)? No.**
   - Step 1 parses the file strictly (`internal/decision/verify.go:60`, `agentcard.ParseStrict`).
     It accepts only the members `decision`/`hash`/`signatures` (`:68`), and `signatures` must
     have `initiator` with `respondent` optional (`:83`).
   - Step 1 also runs the full schema, and every embedded entry goes through
     `debate.ParseEntry`. That call demands canonical bytes (`internal/debate/decode.go:52`),
     so each entry has exactly its listed members.
   - Keys must be strict base64url of 32 bytes (`verify.go:282-288`). The canonical form must be
     at most `MaxDecision` (`:108`).
   - Step 2 recomputes the hash over `canonical(decision)` (`:114`). Step 3 checks each present
     signature under its role's key (`:119-131`, strict decode in `decision.go:87-97`). Step 4
     recomputes the id (`:133`).
   - Step 5 checks all the invariants the spec lists (`:499-575`): rule 6, `final_agreement`
     present iff agreed and equal to the proposal's, rule 8, `affected_artifacts`,
     `positions.*.final` = last revision, `n = i+1`, initiator ≠ respondent, and
     `opened ≤ closed`.
   - `Complete` is true only when the respondent signature is present and verified
     (`:144-148`). The CLI maps `!Complete` to exit 6 (`cmd/agentnet/decision.go:314-320`).
   - Size cap before parse: the CLI stops reading at 8 MiB (`cmd/agentnet/decision.go:359-375`).
     Deep nesting is refused by the decoder ("exceeded max depth" even at 8 Mi `[`; see Commands).
   - Deviation: a signature that fails strict base64 fails at step 3, not at step 1 as the spec
     says (C25-02, Info).
2. **Markdown is inert.**
   - Every peer string goes through `codeSpan` or `writeFence` (`markdown.go:385-409`), and
     both apply `Visible` and then `TemplateInert`.
   - Fences sit at column 0 and use at least three backticks, one more than the longest run in
     the text. Nothing is ever inside a list or quote container, and no tables are used.
   - `TemplateInert` output cannot contain `{{`, `{%` or `{#` (`visible.go:66-81`). The escape
     itself is `\u{7B}`: its `{` is followed by `7`.
   - Daemon-written text is fixed labels, validated ids and times, the hash, and fingerprints.
     The file starts with `>` or `#`, never `---`, so there is no front matter.
   - Artifact keys print raw (`markdown.go:348`) but are fixed by the strict artifact decoder
     plus the canonical round-trip in `ParseEntry`.
   - No link, image or HTML is emitted. goldmark is test-only: it is used only by
     `markdown_ast_test.go` and `markdown_test.go`, and `TestBinariesDoNotLinkGoldmark` passes
     (D32).
3. **`--out`.**
   - Without `--force`, `Lstat` refuses any existing entry, including a dangling symlink
     (`cmd/agentnet/decision.go:187-194`, R48 L6 fixed).
   - The write is a temp file in the same directory, then `Sync`, then rename, and the temp
     file is removed on error (`cmd/agentnet/fetch.go:243-263`). No partial file can appear.
   - With `--force`, the rename replaces a symlink itself, not its target. The file mode is
     0600 and the Stat-then-rename TOCTOU remains (both O-179). The name is always the user's.
4. **D33 facts (O-177).**
   - What an unaudited export exposes: the full Decision content (topic, positions, arguments,
     constraint texts). That content is already readable, unaudited, through `decision_show`
     (`internal/daemon/decision.go:156-174`), and a larger superset through `debate_show`
     (`internal/daemon/debate.go:287`). Neither is audited.
   - The export itself happens in the CLI (`writeDecisionOutput`). The daemon cannot tell a
     show from an export, so an audit only on `--out` would record a CLI-side claim that a local
     agent can bypass by calling IPC directly.
   - A content-free audit is feasible: `decision.show {id, session, peer, hash}` in the
     `decision_show` handler holds no content. It would log every read, not only exports, and
     for consistency `debate_show` would need the same treatment.

## Findings

### C25-01 · High · confirmed-test
- **Where:** `cmd/agentnet/decision.go:387` (`printDecisionVerifyHuman`). The reason comes from
  `internal/decision/verify.go:180` (`members` puts the raw member name in the error) and
  `internal/debate/decode.go:324` (the same for embedded entries).
- **What goes wrong:** `decision verify FILE` without `--json` prints `res.Reason` to the
  terminal unescaped. The reason contains an attacker-chosen JSON member name, which can hold
  `\r`, `\n` or ESC after JSON unescaping.
- **Scenario:** Anyone who hands the user a Decision file ("verify this before merging")
  writes a forged Decision and adds a member whose name is
  `\r\u001b[2Kd-<id>  hash <h>  valid, signed by initiator and respondent\n  initiator fingerprint: <real A fp>\n  respondent fingerprint: <real B fp>`.
  The terminal shows a clean "valid, signed by initiator and respondent" verdict with the
  fingerprints the user expects. Even a plain `\r` (no ESC) overwrites the line on the Windows
  console. The exit code is 1 and `--json` is correct, so only a human reader is fooled. But
  that human reading is the point of third-party verification (decision.md "compare the
  fingerprint").
- **Spec:** `Docs/protocol/decision.md` §Signed file step 6 (the verify report); rubric
  invariant 4 (peer input must not drive our terminal).
- **Fix direction:** print `Reason` through `termSafe` (or quote member names in `members`/
  `object` errors with `%q`), and print the invalid verdict last or on its own line.
- **Related:** O-100 (the same class for titles in `decisions`/`debates`; this is a new path,
  with C0 controls and a spoofed verdict), R48 L2.

### C25-02 · Info · confirmed-read
- **Where:** `internal/decision/verify.go:89` (step 1 checks only `sigPattern`),
  `internal/decision/decision.go:92` (strict decode happens at step 3).
- **What goes wrong:** a signature whose last character has non-zero padding bits fails at
  step 3 ("does not verify"), but decision.md step 1 says keys **and signatures** are strict
  base64url at parse time. It fails closed; only the reported step differs, and
  `TestVerifyRefusesNonCanonicalBase64` pins step 3.
- **Scenario:** none with impact.
- **Spec:** decision.md §Signed file step 1, "Keys and signatures are strict base64url".
- **Fix direction:** align the spec text or add the strict decode at step 1.
- **Related:** R47 L1.

## Assumptions and contracts

- `Verify` assumes `schema.Entry` (= `debate.ParseEntry`) rejects unknown members and
  non-canonical encodings, which pins artifact keys and entry shapes for the renderer
  (`internal/debate/decode.go:52`, `:317`). **checked**
- `Verify` assumes `agentcard.ParseStrict` rejects duplicate keys and bounds nesting depth
  (`internal/agentcard/canonical.go:24`). Depth was **checked** by test; duplicates
  **unchecked** here (C-agentcard).
- `Render` in the `decision <id> --md` path assumes the daemon's stored Decision was derived
  from validated entries (`internal/debate/decision.go:57`, `deriveTx`). **unchecked** (C-debate)
- `Render` assumes the daemon supplies `hash`, `PeerFPs` and the ids unmodified; they print
  outside code spans (`markdown.go:61-69`). Trusted local daemon.
- `writeDecisionOutput` relies on `writeFileAtomic` (`cmd/agentnet/fetch.go:243`). **checked**
- `printDecisionHuman` prints `res.PeerNames` raw (`cmd/agentnet/decision.go:160`). Petnames
  come from `resolvePeer`. Whether a peer can choose them is **unchecked** (see Leads).
