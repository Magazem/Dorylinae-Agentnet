# C30: Test harness: stand-in agent and POSIX scripts

Reviewer: CR-C30 · model claude-opus-5-5 · elapsed 5 min · commit 6cc26a7

## Summary

| Critical | High | Medium | Low | Info |
|---|---|---|---|---|
| 0 | 0 | 0 | 5 | 4 |

This is test-only code, run weekly in CI (stand-in, phase 2/3) and by hand with real agent CLIs.
No path gives a relay, stranger or paired peer anything. The stand-in never uses a shell
(`exec.Command` with a fixed binary). Every daemon gets its own `DORYLINAE_HOME` under a
`mktemp -d` directory. The defects are about assertion strength and hygiene. Two checks
cannot fail in cases they claim to cover: the phase 1 smoke's audit/no-content check
passes when the DB read errors (C30-01), and phase 3's forced-escalation round accepts
`agreed` (C30-02). One check fails when it should pass: a quoting bug in phase 1's audit
check (C30-03). The scripts also write test key material into the owner's real OS keychain
without cleaning it up (C30-04), and they use a predictable `/tmp` stderr file (C30-05).

## Questions

1. **Credentials / real config / real daemon / keychain.** Every `agentnet`/`agentnetd`
   call sets `DORYLINAE_HOME` to a per-round dir under `mktemp -d` (`phase1-agents.sh:84,218-221`,
   `phase2-agents.sh:89,241-247`, `phase3-agents.sh:89,308-314`, `phase0-smoke.sh:23,40,57`,
   `phase1-smoke.sh:37,60,85`; stand-in `standin/main.go:108`). The one call that does not set it,
   `agentnet decision verify` (`phase3-agents.sh:516`), is purely offline
   (`cmd/agentnet/decision.go:287-311` reads only the file). So the owner's real daemon and
   DB are not touched. **But the real OS keychain is touched:** no script sets
   `DORYLINAE_KEYSTORE=file`, and the default mode `auto` puts identity/mailbox/webhook
   secrets in the keychain under per-home accounts (`internal/identity/identity.go:58-62`,
   `internal/daemon/daemon.go:707-713`), which nothing deletes → C30-04. Real agent CLIs
   use the owner's own login (needed). Claude runs with `--setting-sources project`,
   an empty MCP config and a narrow allowlist. agy runs with `--dangerously-skip-permissions`,
   a documented choice (`phase1-agents.sh:166-176`) → C30-08. The CI workflows pass no
   secrets (`.github/workflows/phase2-harness.yml`, `phase3-harness.yml`).
2. **Quoting / temp files.** Paths are quoted throughout. `rm -rf "$work"` in the smokes
   (`phase0-smoke.sh:63`, `phase1-smoke.sh:97`) is a no-op if `$work` is empty. The harness
   scripts never `rm -rf`. `set -e` is not used; failures are checked explicitly per step.
   Defects: the predictable `/tmp/agentnet-stderr.$$` (C30-05); the `$'\n'` inside double
   quotes (C30-03); background daemons are started as `( cd … && daemon ) &`, so on
   bash < 5.1 `$!` is the subshell (C30-06).
3. **PASS conditions.** The checks mostly use `--json` output, parsed by Python or matched
   on compact JSON (compact output is confirmed by the weekly CI passes that grep
   `"ok":true`), plus `audit_events`. Weak spots: C30-01 (the audit/leak check fails open),
   C30-02 (the escalation scenario is not asserted), C30-03 (false FAIL). Also,
   `invoke_agent` greps the agent's own stdout for `authentic`/`quota`, so the agent's prose
   can cause a false FAIL (C30-07).
4. **Stand-in: defensive parsing / steering.** All output is parsed with
   `json.Unmarshal` into `map[string]interface{}` with checked type assertions
   (`standin/main.go:117-135,160-171`). A non-JSON stdout is an error. No shell is involved,
   so peer text cannot become a command. The only peer-derived argv element that is not an
   id is the listed file name passed to `fetch` without a `--` separator
   (`standin/main.go:416,423`). A name like `--out=x` would be parsed as a flag by
   `parseInterspersed` (`cmd/agentnet/pair.go:188-199`) → C30-09 (Info, suspected).
   The stand-in accepts any `review`/`task`/`question` in its inbox and the first
   invited debate (`:326-341,502`). That is fine because the harness pairs only its own two daemons.

## Findings

### C30-01 · Low · confirmed-test
- **Where:** `tests/phase1-smoke.sh:409-439`
- **What goes wrong:** The audit check prints `MISSING:`/`LEAK:` lines only on success. On
  any exception it prints `ERROR …` and exits 1. The shell then extracts empty
  `missing_line`/`leak_line`, so both "all expected actions present" and "no request content
  leaks into audit_events" report PASS. The check also puts no marker in the request
  **title** or the urgency reason, although the step text says "title/brief/reason/…".
- **Scenario:** The DB file is renamed, locked or unreadable. `sqlite3.connect` creates an empty
  file and the query raises `no such table: audit_events`. Reproduced: the same Python block and
  extraction against a missing DB printed `ERROR …: no such table: audit_events` and then
  `PASS audit present` / `PASS no leak`. So invariant 1 (no content in audit) can pass
  unverified. A title leaking into `audit_events.detail` would never be caught.
- **Spec:** audit.md "No content, still" (invariant 1); rubric §3 "a test that claims to cover an invariant but cannot fail".
- **Fix direction:** Treat a missing `MISSING:`/`LEAK:` line or a non-zero Python exit as FAIL. Add a marker to the title and the urgency reason.
- **Related:** none

### C30-02 · Low · confirmed-read
- **Where:** `tests/harness/phase3-agents.sh:504` (also `:550`, `standin/main.go:571-580`)
- **What goes wrong:** Round 2 is the "forced escalation" scenario (`-disagree`,
  "deterministic only with the stand-in", `:547-549`). Its pass condition is the same as
  round 1: `agreed|escalated`. The expected outcome per scenario is never checked, and neither is
  `remaining_disagreement` in the Decision.
- **Scenario:** A regression makes the daemon treat `{"accept": false, …}` as agreement, or
  the stand-in stops sending it. Round 2 closes `agreed` and the weekly CI stays green, although
  the workflow says it "runs both an agreed debate and a forced escalation" (`phase3-harness.yml:6`).
  The escalated-Decision path (signed Decision with disagreement) then has no end-to-end coverage.
- **Spec:** `tests/harness/README.md:245-256`; OD-P3-7/3.5.
- **Fix direction:** In stand-in mode, require `outcome == $scenario`. For `escalated`, check that the Decision has a non-empty remaining disagreement.
- **Related:** lead for C31 (`phase3-agents.ps1:681` has the same check)

### C30-03 · Low · confirmed-test
- **Where:** `tests/harness/phase1-agents.sh:325`
- **What goes wrong:** `<<<"$audit_a$'\n'$audit_b"` puts `$'\n'` **inside** double quotes, where
  ANSI-C quoting does not apply. The two logs are therefore joined by the literal text `$'\n'`,
  which fuses A's last action and B's first action into one line that matches no `grep -x`.
  (`phase2-agents.sh:343` and `phase3-agents.sh:533` quote this correctly.)
- **Scenario:** A's final audit row is `request.state` (the mirror update). If B never logs
  that action, the round reports "audit log missing: request.state" although it happened,
  which is a false FAIL on the manual 1.H run. Reproduced in bash 5.3: with `a=$'x\nrequest.state'`
  and `b=$'request.in\ny'`, both `request.state` and `request.in` report MISSING.
- **Spec:** none
- **Fix direction:** Use `<<<"$audit_a"$'\n'"$audit_b"` as in phase 2/3.
- **Related:** none

### C30-04 · Low · confirmed-read
- **Where:** `tests/harness/phase1-agents.sh:218-223`, `phase2-agents.sh:241-248`,
  `phase3-agents.sh:308-315`, `tests/phase0-smoke.sh:57`, `tests/phase1-smoke.sh:85`; root cause
  is that the default keystore mode is `auto` (`internal/identity/identity.go:58-62`, `internal/daemon/daemon.go:707-713`)
- **What goes wrong:** No script sets `DORYLINAE_KEYSTORE=file`, so each spawned daemon stores its
  identity seed, mailbox keys and (phase 1 smoke) webhook secret in the **owner's real OS
  keychain** (Windows Credential Manager / macOS Keychain / Secret Service). The account is
  `identity-<sha256(dir)[:8]>`, and nothing removes the entry. The smokes `rm -rf` the home, and the
  harness scripts keep it.
- **Scenario:** The owner runs `phase1-smoke.sh` in Git Bash, or a real-agent harness round, on their
  PC. Four daemons leave about 8–12 orphaned `dorylinae` credentials per run, which build up
  forever. These are throwaway keys, not the owner's, so there is no secret disclosure. But it is
  the "touch the user's real keychain" that Q1 rules out, and CI's own e2e jobs deliberately avoid it
  (`.github/workflows/ci.yml:102-104`, the `webhookKeystore` comment "tests … must not touch
  the real keychain"). On a locked or absent Secret Service, each key operation can also stall
  for up to 5 s (`internal/keystore/keychain.go:18`).
- **Spec:** `internal/daemon/daemon.go:704-706` comment; C30 Q1.
- **Fix direction:** Export `DORYLINAE_KEYSTORE=file` in every script (and the `.ps1` twins).
- **Related:** lead for C31

### C30-05 · Low · confirmed-read
- **Where:** `tests/harness/phase1-agents.sh:90-92`, `phase2-agents.sh:95-97`, `phase3-agents.sh:95-97`
- **What goes wrong:** `cli_json` redirects stderr to the fixed, guessable path
  `/tmp/agentnet-stderr.$$`, never reads it, then deletes it. The shell opens it with `O_CREAT|O_TRUNC`
  and follows symlinks.
- **Scenario:** Another local OS user on a shared macOS machine (no `protected_symlinks`) pre-creates
  `/tmp/agentnet-stderr.<pid>` symlinks for a range of PIDs pointing at files of the user running
  the harness (e.g. `~/.zshrc`). Each `cli_json` call truncates that file and overwrites it with agentnet's
  stderr (usually empty). On Linux with `fs.protected_symlinks=1` this is blocked. The captured stderr
  is also discarded, so diagnostics are lost.
- **Spec:** none (C30 Q2 "predictable temp names")
- **Fix direction:** Use `2>/dev/null`, or a file inside `$ROOT_RUN` so the stderr is kept for debugging.
- **Related:** none

### C30-06 · Info · suspected
- **Where:** `tests/harness/phase1-agents.sh:218-223,202-206`, same pattern in `phase2-agents.sh:241-248`, `phase3-agents.sh:308-315`
- **What goes wrong:** Daemons start as `( cd "$home" && … "$DAEMON" … ) &`, and `cleanup` kills
  `$!`. Bash ≥ 5.1 execs the last command, so `$!` is the daemon: verified in bash 5.3, where `$!`
  equals the child's PID. On bash 3.2 (macOS `/bin/bash`), `$!` is likely the subshell, so the
  daemon survives cleanup. In phase 2/3 it probably dies of SIGPIPE on its stderr FIFO once
  the pump is killed. In phase 1 (stderr to a file) it keeps running and retries the dead relay
  after the script ends. Not verified on bash 3.2.
- **Scenario:** A manual phase 1 run on macOS leaves two `agentnetd` processes per round running.
- **Spec:** none
- **Fix direction:** `exec "$DAEMON" …` inside the subshell, or start the daemon without a subshell and use `--home`/`cd` differently.
- **Related:** none

### C30-07 · Info · confirmed-read
- **Where:** `tests/harness/phase1-agents.sh:186`, `phase2-agents.sh:193`, `phase3-agents.sh:195`
- **What goes wrong:** The "auth/usage-limit" detector greps the agent's whole stdout, which
  includes the model's final prose (`--output-format json`), for `authentic|quota|rate limit`.
  A normal answer that mentions "authenticated" (plausible in a grant/pairing task) fails the round.
- **Scenario:** In a real phase 2 round, the agent's summary says "the grant was authenticated". The
  round reports "reported an auth/usage-limit error", which is a false FAIL (costs a paid rerun).
- **Spec:** none
- **Fix direction:** Match only stderr, or the harness's structured error field (`is_error`/`subtype`).
- **Related:** none

### C30-08 · Info · confirmed-read
- **Where:** `tests/harness/phase1-agents.sh:177-180` (and phase 2/3 `agy` branch), `phase3-agents.sh:170`
- **What goes wrong:** In real rounds, agy runs with `--dangerously-skip-permissions` and the owner's full
  environment, and phase 3's Claude may run `cat *` (any file). Each agent reads text written by the
  other agent (debate moves, request briefs). A prompt injection between the two agents could make agy
  run arbitrary commands, or make Claude `cat` the owner's credential files into a debate move stored
  under `/tmp/phase3-agents-*`. Both agents are the owner's own, over a loopback relay, so no
  outside actor is involved. The design note is documented (`:166-176`).
- **Scenario:** Design note only. No outside actor.
- **Spec:** approval.md "Boundary, stated plainly" (harness confinement)
- **Fix direction:** Consider a throwaway `HOME` for agy, or narrowing `cat *` to `cat NOTES.md`.
- **Related:** none

### C30-09 · Info · suspected
- **Where:** `tests/harness/standin/main.go:416,423`
- **What goes wrong:** The file name from the peer's `fetch --list` is passed as a positional argument
  with no `--` before it. `parseInterspersed` treats any `-`-prefixed token that matches a flag as
  that flag (`cmd/agentnet/pair.go:188-199`), and `fetch` has `--out` (`cmd/agentnet/*fetch*.go:91`).
- **Scenario:** A granted directory holding a file named `--out=x` would make the stand-in run
  `agentnet fetch <grant> --out=x --json`. I did not check whether the fs list/serve path allows such
  names, and in the harness the granter is the other stand-in.
- **Spec:** none
- **Fix direction:** Put `--` before the file-name argument.
- **Related:** none

## Assumptions and contracts

- `agentnet … --json` prints compact JSON (no space after `:`). The greps `'"ok":true'`,
  `'"state":"complete"'` and `'"webhook":{'` (`phase*-agents.sh:235,245,265,274,332,341,375,452`,
  `phase1-smoke.sh:393`) rely on it. **Checked (indirectly):** the weekly phase 2/3 CI passes with
  these greps. `phase1-smoke.sh:393` is a *negative* grep, so pretty-printed output would make it
  unfailable. **Unchecked** for `notify` in particular.
- The daemon DB is `<home>/dorylinae.db` (all audit reads). **Checked:** `internal/paths/paths.go:49`.
- `DORYLINAE_HOME` isolates everything except the keychain. **Checked:** `internal/paths/paths.go:15,29`,
  `internal/keystore/keychain.go:28-31` (see C30-04).
- The approval pump relies on the daemon's terminal-approval line format
  `AgentNet approval a-<hex>: <summary>. Code <digits>.` on stderr, one line per prompt, with the
  summary free of newlines (`phase2-agents.sh:142`). A greedy `.*` picks the **last** `Code N.`, which is
  the real one as long as nothing peer-controlled follows it on the line. **Unchecked** (C22/approval chunk).
- `agentnet decision verify` needs no home and makes no daemon call. **Checked:** `cmd/agentnet/decision.go:287-311`.
- The stand-in assumes `request show` returns `request.session.id`, `grants` returns `grants[].id/state`,
  `fetch --list` returns `entries[].type/name`, `debate` returns `debate.phase/turn/expect` and
  `wait` returns `wait`. **Checked indirectly** by the weekly CI passes. **Unchecked** against `Docs/cli/*`.

## Checked and fine

- No shell is involved in the stand-in: `exec.Command(c.agentnet, args…)`, fixed binary (`standin/main.go:107`).
  All JSON is decoded with checked type assertions. A non-zero exit or `ok:false` is an error (`:117-135`).
- The stand-in's consult answer temp file uses `os.CreateTemp` (random name) and is removed (`standin/main.go:436-440`).
- Every `pollUntil` is bounded by a deadline (`standin/main.go:140-158`). `roleB` is bounded (`:309-349`).
  `debateLoop` checks its deadline only on the waiting path (see Notes).
- `mktemp -d` is used for all run dirs, with a short `/tmp` path for the macOS socket limit
  (`phase2-agents.sh:86-89`). There is no `rm -rf` on a possibly empty variable
  (`phase0-smoke.sh:63`, `phase1-smoke.sh:97` quote `$work`, which comes from `mktemp`).
- The RETURN trap in `run_round` fires only when `run_round` itself returns, not on nested
  `step`/`fail` calls. Verified in bash 5.3.
- Empty-array expansion is safe on bash 3.2 (`phase3-agents.sh:364`, SH-FIX). Fixed fds 7/8 are used instead of `{var}`.
- Phase 2 asserts real outcomes: exactly one review and one question request, two sessions `closed/accepted`,
  the grant revoked after close, and `grant.fetch` in the audit log (`phase2-agents.sh:324-345`). Phase 3 checks
  `decision verify` is `complete` (two signatures), the human constraint in `human_decisions`, and `log --verify` on
  both homes (`phase3-agents.sh:511-540`).
- The phase 1 smoke verifies the webhook HMAC for every delivery against the spec's `v1:{ts}:{id}:{body}`
  (`phase1-smoke.sh:352-389`). An empty set fails because `total -ge 2` is required.
- CI harness workflows pass no secrets. Logs uploaded on failure contain only throwaway loopback identities.
- The loopback relay binds 127.0.0.1 only. A port already taken is detected (`kill -0` after 0.5 s).
- None of 02-open-findings covers this chunk. No O-id is touched.

## Notes

- `standin/main.go:590-593`: after a successful submit, `debateLoop` `continue`s without checking the deadline. A daemon
  that keeps saying `turn: you` would loop until the CI job timeout.
- `phase2-agents.sh:313,315`: `x=$(invoke_agent …) &` sets the variable only in the background subshell, so the
  failure reason is always empty in the FAIL line.
- With `--max-attempts >1`, attempt 2 reuses the same relay port right after a `kill` without `wait`. This could flake on "relay exited immediately".

## Commands run

- Bash (bash 5.3.9, Git Bash): `grep -qx … <<<"$a$'\n'$b"` reproduction → `request.state MISSING`, `request.in MISSING` (C30-03).
- Bash: `( cd /tmp && sleep 30 ) & p=$!` → `$!` equals the `sleep` PID on bash 5.3 (C30-06 limited to bash < 5.1).
- Bash: RETURN-trap scope test → cleanup fired only on the outer function's return.
- Bash + python3: phase 1 smoke audit block against a missing DB → `ERROR … no such table: audit_events`, then `PASS audit present`, `PASS no leak` (C30-01).
