# C31: Test harness and smoke tests: PowerShell

Reviewer: CR-C31 · model claude-opus-5-5 · elapsed 6 min (wall clock) · commit 6cc26a7

## Summary

| Critical | High | Medium | Low | Info |
|---|---|---|---|---|
| 0 | 0 | 0 | 3 | 4 |

Verdict: the five PowerShell scripts are sound on the points that matter most. Every daemon
and CLI call gets its own `DORYLINAE_HOME`. The Windows pipe name and the keychain account
are both derived from that home (`internal/paths/paths.go:69-72`,
`internal/keystore/keychain.go:25-28`), so a run can never reach the owner's real daemon or
overwrite their real keys. Pass conditions come from `--json` and the audit table, not from
agent prose. Claude Code runs with the full isolation set from HANDOFF §5, and I checked
every flag against `claude --help` (2.1.284). The weak points are hygiene and test fidelity:
- every run writes throwaway keys into the owner's real Windows Credential Manager and never
  removes them (C31-01);
- two timeout paths cannot fire, so a hung child hangs the whole harness with the daemons
  still running (C31-02);
- the forced-escalation debate round cannot fail on a wrong outcome (C31-03).

## Questions

1. **Credentials, real config dir, real daemon/keychain.** No run touches the real config dir
   or the real daemon. Every `agentnetd` gets `DORYLINAE_HOME` (`phase1-agents.ps1:246-251`,
   `phase2-agents.ps1:306-309`, `phase3-agents.ps1:467-470`, `phase0-smoke.ps1:105-106`,
   `phase1-smoke.ps1:148-150`), and so does every CLI call (`Invoke-CliJson`
   `phase*-agents.ps1:147/161/161`; `Ag` in both smoke scripts). The pipe name is
   `sha256(dir)` (`internal/paths/paths.go:69-72`). The CLI calls without a home
   (`phase3-agents.ps1:695-701`, `decision verify`) are offline: `cmd/agentnet/decision.go:287`
   does not dial. **But** no script sets `DORYLINAE_KEYSTORE=file`, so each run writes
   identity and mailbox keys (and a webhook secret in `phase1-smoke`) into the owner's real
   Credential Manager and never deletes them. See C31-01. Agent CLIs inherit the operator's
   whole environment (API logins). They need it, and the environment is written only to the
   agent's own stdout/stderr logs, never to a file.
2. **Quoting and temp files.** The temp roots use GUID names under the per-user `%TEMP%`
   (`phase1-agents.ps1:540`, `phase2:570`, `phase3:771`, `phase0-smoke:29`,
   `phase1-smoke:39`). The only recursive delete is on the GUID path, and only after a full
   pass (`phase0-smoke.ps1:211`, `phase1-smoke.ps1:456`). There is no `rm -rf` on an empty
   variable. `Format-ArgList` (`phase1-agents.ps1:82-91` and copies) escapes `"` but not a
   backslash just before a quote, and it drops empty arguments. No current argument ends in
   `\` or is empty, so this is only a note. `$ErrorActionPreference='Stop'` is set everywhere.
   A `Wait-Until` timeout throws past the retry loop, so the run ends with no summary but
   still exits non-zero (C31-06).
3. **Do the PASS conditions check the outcome?** Mostly yes. The harness scripts assert
   request counts, states, D14 fields, grant revocation and audit actions
   (`phase1-agents.ps1:382-406`, `phase2:421-452`). `phase3` checks phase, rounds, Decision
   export, `verify` exit code, `complete`, `human_decisions` and `log --verify` exit codes
   (`phase3:668-734`). Gaps:
   - the forced-escalation round accepts `agreed` (C31-03);
   - phase 2 never checks the grant's scope or path (C31-07);
   - `phase1-smoke.ps1:215` passes vacuously when B is missing from the roster (C31-07);
   - the smoke audit-content check has no marker in titles or urgency reasons, although its
     step name claims titles (C31-07). The Go e2e tests do cover titles
     (`internal/daemon/e2e_1_9_test.go:187-196`).
4. **Stand-in parsing** is Go (C30). On the PowerShell side, JSON is parsed with
   `ConvertFrom-Json` inside `try`, and a parse failure gives `$null`, which fails the check
   (fail closed, `phase1-agents.ps1:153-155`). Peer text is never executed.
5. **Claude isolation (HANDOFF §5).** All three harness scripts pass `--restricted`,
   `--tools PowerShell…`, `--allowedTools "PowerShell(agentnet *)"…`,
   `--permission-prompts none`, `--strict-mcp-config --mcp-config '{"mcpServers":{}}'` and
   `--setting-sources project` (`phase1-agents.ps1:443-451`, `phase2:476-478`,
   `phase3:275-278`). I checked each flag against `claude --help` 2.1.284: `--restricted`
   ignores user/project/local settings, and `--permission-prompts none` auto-denies. There
   are three weaker spots:
   - Phase 3 adds `PowerShell(Get-Content *)`, which can read any file the user can read.
     `--restricted` confines only the file tools, not the shell (C31-04).
   - agy runs with `--dangerously-skip-permissions`. This is documented and accepted in
     `tests/harness/README.md:113-139`.
   - codex has only `--sandbox workspace-write`, also documented.
6. **Are processes killed with `taskkill /T /F` on every exit path?**
   - The harness scripts kill daemons and the relay in `finally`
     (`phase1-agents.ps1:411-415`, `phase2:457-461`, `phase3:740-744`) through
     `taskkill /T /F` (`Stop-ProcessTree`).
   - **Not on every path.** Two timeout paths cannot fire, so a hang never reaches `finally`
     (C31-02).
   - In `phase3`, an exception between starting the stand-ins and waiting for them
     (`:535-546`) leaves stand-ins A and B running. `finally` does not know them (C31-05).
   - The smoke scripts use `Process.Kill()`, not `taskkill /T` (`phase0-smoke.ps1:78`,
     `phase1-smoke.ps1:99`). `agentnetd run` and `relay` are single processes here, so
     nothing is orphaned. This deviates from the HANDOFF rule but is harmless today.

## Findings

### C31-01 · Low · confirmed-read
- **Where:** `tests/phase0-smoke.ps1:105-106`, `tests/phase1-smoke.ps1:148-150,337,365-368`,
  `tests/harness/phase1-agents.ps1:246-251`, `phase2-agents.ps1:306-309`,
  `phase3-agents.ps1:467-470`. Mechanism: `internal/identity/identity.go:57-62`,
  `internal/mailbox/mailbox.go:119-123`, `internal/daemon/daemon.go:707-714`.
- **What goes wrong:** no script sets `DORYLINAE_KEYSTORE=file`. On Windows every throwaway
  daemon therefore stores its identity seed and mailbox private keys in the owner's **real**
  Credential Manager (service `dorylinae`, accounts `identity-<hash>` and
  `mailbox-<hash>-<keyid>`). `phase1-smoke` also stores the webhook secret
  (`webhook-<hash>`). Nothing ever deletes these entries. The smoke scripts even delete the
  home directory on a pass (`phase1-smoke.ps1:456`), which leaves the secrets orphaned.
- **Scenario:** the owner runs `phase1-smoke.ps1` (4 daemons) and the three harnesses. Each
  run leaves about 2 entries per daemon for good. On this PC, `cmdkey /list` now shows **166
  `dorylinae:` entries (82 identity, 84 mailbox)**, while the owner has one real home. I did
  not attribute each entry to a script, since Go tests could add some. Because the account is
  hashed per directory, the real key is never overwritten, so the impact is keychain clutter
  and key material that outlives its test. The CI workflow already guards against this for
  the installed daemon (`.github/workflows/ci.yml:94-104`), so the intent exists.
- **Spec:** `internal/daemon/daemon.go:704-706`: "tests, which must not touch the real
  keychain". HANDOFF §5 has no rule on this.
- **Fix direction:** set `DORYLINAE_KEYSTORE=file` in every daemon env hashtable in the five
  scripts (and in the `.sh` ports, C30).
- **Related:** none open.

### C31-02 · Low · confirmed-read
- **Where:**
  - `tests/harness/phase2-agents.ps1:363-370`, `phase3-agents.ps1:548-555`: stand-in wait;
  - `phase1-agents.ps1:149-151`, `phase2-agents.ps1:163-165`, `phase3-agents.ps1:163-165`:
    `Invoke-CliJson`.
- **What goes wrong:** both timeouts are dead code.
  - (a) After `WaitForExit(timeout)` returns false for a stand-in, the script reads
    `$aOut.Result` (a `ReadToEndAsync` task) **before** `Stop-ProcessTree`. `.Result` blocks
    until the child's stdout closes, which only happens when the child exits.
  - (b) `Invoke-CliJson` calls the synchronous `StandardOutput.ReadToEnd()` before
    `WaitForExit($TimeoutMs)`, so a hung `agentnet` blocks forever and the 5-8 s timeout never
    applies.
- **Scenario:** the stand-in's `agentnet` calls have no timeout (`exec.Command`,
  `tests/harness/standin/main.go:107`). A daemon wedge that hangs one IPC call is exactly the
  bug the harness exists to catch, and it hangs the stand-in. The script then blocks at
  `:365`. The kill, the result and `finally` (daemons, relay) never run.
  - Locally: the harness hangs and leaves two daemons and a relay running.
  - In CI: the job runs until `timeout-minutes` (20/25) and is **cancelled**. The
    `if: failure()` log upload (`.github/workflows/phase2-harness.yml:36`) does not run on a
    cancel, so the logs of the one run that found the wedge are lost.
- **Spec:** none (harness contract: "Each agent gets up to 7 minutes", `tests/harness/README.md:177`).
- **Fix direction:** kill first, then read `.Result`. In `Invoke-CliJson`, use
  `ReadToEndAsync` and wait on the process with the timeout before reading.
- **Related:** C31-05.

### C31-03 · Low · confirmed-read
- **Where:** `tests/harness/phase3-agents.ps1:681` (with `:779-782`), also
  `tests/harness/standin/main.go:11`.
- **What goes wrong:** the stand-in runs two scenarios, `agreed` and forced `escalated`
  (`-disagree`, 3.5/OD-P3-7). The assertion accepts `outcome ∈ {agreed, escalated}` for
  both. The stand-in states it makes no outcome assertion ("Assertions about the outcome are
  made by the harness script itself", `main.go:11`). So the forced-escalation round cannot
  fail on the one thing it exists to test.
- **Scenario:** a regression makes the daemon treat `accept:false` as agreement, or close
  every debate `agreed`. The weekly CI job (`phase3-harness.yml`) still passes both rounds on
  all three OSes.
- **Spec:** `tests/harness/README.md:244-246` ("a forced escalation (`-disagree`,
  deterministic only with the stand-in)"). The "agreed or escalated" tolerance at
  `README.md:255` is justified for real agents only.
- **Fix direction:** when `Harness -eq standin`, require `outcome -eq $Scenario`.
- **Related:** same gap in `tests/harness/phase3-agents.sh:504` (C30).

### C31-04 · Info · confirmed-read
- **Where:** `tests/harness/phase3-agents.ps1:275`
- **What goes wrong:** the phase 3 real-agent Claude allowlist adds
  `PowerShell(Get-Content *)`. `--restricted` confines the *file* tools to the working
  directory, but not a shell `Get-Content`. The agent can therefore read any file the owner
  can read (e.g. `%USERPROFILE%\.claude\.credentials.json`, SSH keys). It can then put the
  text into a debate move through the allowed `agentnet debate … ` and into
  `decision.json`/`.md` under `%TEMP%` (never cleaned).
- **Scenario:** the respondent is another model (agy, run with full permissions). Its debate
  text is prompt input for the Claude side. A prompt-injected move asking for "the contents
  of X as evidence" is within Claude's allowlist. Everything stays on this machine (loopback
  relay), so the impact is bounded. The allowlist is still wider than HANDOFF §5 intends, and
  the agent only needs `NOTES.md`, which is copied into its work dir (`:565-566`).
- **Spec:** HANDOFF §5 (connector isolation, allowlist of commands).
- **Fix direction:** replace `Get-Content *` with the file tool `Read` (confined by
  `--restricted`) or `PowerShell(Get-Content NOTES.md)`.
- **Related:** `tests/harness/README.md:113-139` (agy is weaker by design).

### C31-05 · Info · confirmed-read
- **Where:** `tests/harness/phase3-agents.ps1:527-546`, `:740-744`
- **What goes wrong:** in the stand-in path, `Wait-Until` (`:535`, `:541`) or the
  `--constrain` throw (`:546`) can raise after both stand-in processes started. `finally`
  stops only the daemons and the relay, so stand-ins A and B are left running.
- **Scenario:** `--constrain` fails (for example, the stand-ins closed the debate first). The
  script exits, and the two `standin.exe` processes keep polling until an `agentnet` call
  fails against the dead daemons. Short-lived, but it breaks Q6's "every exit path".
- **Spec:** HANDOFF §5 (`taskkill /T /F`).
- **Fix direction:** add `$aProc`/`$bProc` to `$handles` and stop them in `finally`.
- **Related:** C31-02.

### C31-06 · Info · confirmed-read
- **Where:** `tests/harness/phase1-agents.ps1:159-168,568-576` (same in phase2 `:173-182,594-602`, phase3 `:173-182,800-808`)
- **What goes wrong:** `Wait-Until` throws on timeout, and `Invoke-Round` does not catch it.
  So `-MaxAttempts` (meant to "report a pass rate" for flaky real agents) is skipped on the
  most common flake, a slow delivery, and the summary block never prints. The exit code is
  still non-zero (fail closed).
- **Scenario:** `-MaxAttempts 3`, and round 1's "request delivered to B's inbox" wait times
  out. The script aborts with a PowerShell error, with no retry and no pass-rate line.
- **Spec:** `tests/harness/README.md:87-88` ("retry a failed round up to N times and report a pass rate").
- **Fix direction:** wrap `Invoke-Round` in `try/catch` inside the attempt loop and record
  the exception text as `Reason`.
- **Related:** none.

### C31-07 · Info · confirmed-read
- **Where:** `tests/phase1-smoke.ps1:215`, `:438-445`; `tests/harness/phase2-agents.ps1:439-445`
- **What goes wrong:** three weak assertions.
  - (a) `-not $m.daemon_online` is true when `$m` is `$null` (B missing, or
    `status --team` returned no JSON). The "B goes offline after --invisible" step can pass
    vacuously. Compare `:230`, which guards with `$m -and`.
  - (b) The audit no-content step says "title/brief/reason/…", but the titles
    (`:243`, `:262-266`) and the urgency reason carry no `SMOKEMARK` marker, so a title leak
    would not be caught here. The Go e2e test does cover titles
    (`internal/daemon/e2e_1_9_test.go:187-196`).
  - (c) Phase 2 accepts "at least one issued grant" without checking its path equals
    `$fixtureDir`. The approval pump approves every approval blindly
    (`phase2-agents.ps1:220-231`), so a real agent that granted a wider path would still pass.
- **Scenario:** as stated in each item. None of them hides a production defect today.
- **Spec:** `Docs/protocol/audit.md:15` ("never titles, … reasons").
- **Fix direction:** add a `$m -and` guard, add markers in titles and urgency reasons, and
  assert the grant path.
- **Related:** none.

## Assumptions and contracts

- The IPC endpoint is unique per `DORYLINAE_HOME`, so harness daemons cannot collide with
  the owner's daemon. **Checked:** `internal/paths/paths.go:69-72` (pipe = sha256 of the
  absolute dir).
- The keychain account is unique per home, so throwaway daemons cannot overwrite the real
  identity. **Checked:** `internal/keystore/keychain.go:25-28`, `internal/identity/identity.go:62`,
  `internal/mailbox/mailbox.go:123`, `internal/daemon/daemon.go:712`.
- `agentnetd` with no `--relay` and no `DORYLINAE_RELAY_URL` connects to no relay. The
  "relay-less" restart in `phase1-smoke.ps1:337` relies on this. **Checked:**
  `cmd/agentnetd/main.go:58` ("empty = no relay"). **Caveat:** the child inherits the
  operator's environment, so a `DORYLINAE_RELAY_URL` already set in the operator's shell would
  connect that daemon to that relay (owner-environment dependency, not reported).
- `relay --queue-db` is still accepted. **Checked:** `cmd/relay/main.go:61` (deprecated
  alias for `--db`).
- The daemon writes terminal-approval prompts to stderr as one line,
  `AgentNet approval a-<hex>: … Code <digits>.`, and reads `<tag> <code>` on stdin. The pump
  regex (`phase2-agents.ps1:220`) depends on this. **Unchecked** (C11 owns the terminal
  approval path).
- `agentnet decision verify <file>` works offline without `DORYLINAE_HOME`. **Checked:**
  `cmd/agentnet/decision.go:287-340` (no dial).
- The relay logs at Warn unless `--verbose`, so its undrained stdout/stderr pipes in
  phase2/3 (`phase2-agents.ps1:297-300`, `phase3:458-461`) never fill. **Checked:**
  `cmd/relay/main.go:189-193`.
- The stand-in exits on its own `-timeout`. **Checked, and false** for a hung child call
  (`tests/harness/standin/main.go:107`, no context). See C31-02.

## Checked and fine

- Every daemon and CLI invocation sets its own `DORYLINAE_HOME`, in all five scripts (Q1).
- Temp roots are GUID-named, and the only `Remove-Item -Recurse` target is that GUID path,
  after a full pass (`phase0-smoke.ps1:211`, `phase1-smoke.ps1:456`).
- `Stop-ProcessTree` uses `taskkill /T /F` rather than `Kill($true)` (HANDOFF §5), in all
  three harness scripts.
- `ProcessStartInfo.ArgumentList` is never used (.NET Framework safe).
- Approval codes are answered only by the script's pump. No prompt tells an agent a code, and
  the agent has no pipe to the daemon (OD-P3-3). The phase 3 human constraint is run by the
  script (`phase3-agents.ps1:545,631`).
- Every Claude flag used exists and means what the comments say (`claude --help` 2.1.284).
  Connectors are isolated (`--strict-mcp-config` with an empty config), and the skill needed
  in phase 3 is copied into the work dir for `--setting-sources project`
  (`phase3-agents.ps1:567-573`).
- The relay is loopback-only in all scripts (`--listen 127.0.0.1:<port>`).
- An unexpected early relay exit is detected (`phase1-agents.ps1:242`, `phase2:302`,
  `phase3:463`).
- Webhook HMAC verification in `phase1-smoke.ps1:391-403` recomputes
  `v1:<ts>:<id>:<body>` with the right per-daemon secret and requires every delivery to
  verify (`$verified -eq $posts.Count`).
- The phase 3 Decision checks are real: the `verify` exit code, `complete: true`, a non-empty
  `human_decisions`, and the `log --verify` exit code on both daemons (`phase3-agents.ps1:692-734`).
- The phase 0 smoke test checks negative paths: code reuse → `code_used`, a wrong fingerprint
  → exit 1 with `fingerprint_mismatch`, a removed peer → `unknown_peer`
  (`phase0-smoke.ps1:142,149,202`).
- Build failures stop the run (`$LASTEXITCODE` checks at `phase1-agents.ps1:530`,
  `phase2:556-558`, `phase3:757-759`, and throws in the smoke scripts).

## Notes

- `Format-ArgList` does not double backslashes before a quote or trailing ones, and drops
  empty arguments. Harmless for the current arguments.
- `phase1-agents.ps1:38` resolves `$RepoRoot` from `$PSScriptRoot` in `param()`. phase2/3
  fixed this, phase1 did not.
- `go build -o "$BinDir\"` in both smoke scripts breaks on a path with spaces (the `\"`
  escapes the quote). The smoke scripts also silently reuse stale binaries unless `-Build` is
  passed.
- `Register-ObjectEvent` subscriptions in `phase1-agents.ps1:113-118` are never unregistered.
