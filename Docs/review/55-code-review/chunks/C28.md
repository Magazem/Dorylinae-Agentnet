## Summary

| Critical | High | Medium | Low | Info |
|---|---|---|---|---|
| 0 | 0 | 1 | 3 | 1 |

Daemon wiring is sound. Every subsystem is built and hooked before the relay client starts,
and the relay starts before IPC serves. `agentnetd` passes only production options to
`RunWithOptions`, and no debug or test-only IPC method is registered. The registry matches
the index and the specs. The one real gap is relay-supplied text. Review 53 L4 sanitised
`min_client`, but `last_error` still carries the relay's `error` frame verbatim, with no
size or character bound. `agentnet status` and `agentnet doctor` print it raw, and the
daemon returns it in the `status` response (C28-01, confirmed by test). The Lows are a
`stop` that reports success before the daemon has exited, migrations applied by a losing
second instance, and bidi characters in peer names in `status --team`.

## Questions

1. **Method registry.** There are 71 non-test `srv.Handle` names (all in `internal/daemon/*.go`).
   They match the 00-index §3.a table. Every one appears in `Docs/protocol/ipc.md` except
   `ws_discard`, which is documented in `Docs/protocol/work-session.md:466`. The only other
   `Handle("` in a non-test file is `cmd/relay/testhooks_on.go:34`, an HTTP mux under the
   `testhooks` tag, not IPC. `boom`/`echo` exist only in `internal/ipc/ipc_test.go`. No
   method is gated on `DORYLINAE_DEBUG`. `mail_submit` is always registered, which ipc.md
   §mail_submit documents, with the kind allowlist as the boundary (O-157 residual). Only
   the CLI front end is gated (`cmd/agentnet/main.go:118-122`). The test hooks in `Options`
   (`OnServerReady`, `Quarantine`, `OnApprovalReady`, `OnStoresReady`, `OnDebateReady`,
   `ApprovalWindow`, `DeviceNow`) are reachable only through `RunWithOptions`.
   `cmd/agentnetd/main.go:114` passes only `RelayURL`, `RelayRoots` and `Logger`. I did not
   compare each method's power against its doc beyond the registry; the owning chunks cover that.
2. **Startup/shutdown.** Startup order (`internal/daemon/daemon.go:269-672`): store, IPC
   listen (the instance lock), `daemon.start`, identity, mailbox keys, peers, sessions,
   outbox, team, presence, webhook, approvals (`ExpireStale`), request, work session, caps,
   device helper, quarantine, debates, fetch, **relay (:558)**, outbox run, presence run,
   the register* calls, then `Serve` (:672). No register* function mutates a store outside
   its handlers (checked every `register*` preamble), so mail cannot run against half-wired
   stores. IPC is served only after approvals are wired. One gap: `store.Open` runs
   migrations before `ipc.Listen` takes the lock (C28-03). Shutdown is LIFO: rotate,
   presence goodbye (relay still up), presence, outbox, relay+mail, fetch client/server,
   debate sweep, helper, terminal reader, approvals, webhook, sessions, pairs,
   `daemon.stop` audit, store close. The store closes last and `daemon.stop` uses a fresh
   5 s context. I found no deadlock. Committed work is durable in the DB (outbox rows) and
   resent at the next start. The unwaited goroutines are covered in Notes. The
   `stop`/`StopWait` early return is C28-02.
3. **`doctor`.** It never authenticates: `relayclient.Probe` (`internal/relayclient/probe.go:30-60`)
   reads only the `challenge`, with a 3 s `doctorRelayTimeout`, `SetReadLimit(MaxFrameBytes)`,
   and TLS through `newHTTPClient` with the stored `relay_ca.pem` roots. Probe errors are
   never printed (`doctor.go:365-367`). `min_client` is re-parsed before printing
   (`doctor.go:225`, R53 L4). **But** `res.Relay.LastError` is printed raw
   (`doctor.go:356-359`), see C28-01. It never opens a URL. Paths go through
   `displayRelHome`. The overall budget is `context.WithTimeout(…, 3s+1s+5s)` (`doctor.go:117`).
4. **`status`/`identity`/`mail` CLI.** `status` prints the relay's `last_error` raw
   (C28-01). `min_client` is only interpolated after `MeetsMinimum` succeeds, so it must
   already be a release string (`main.go:261`, and `validMinClient` in the daemon). `--team`
   prints peer card names raw (C28-04). Team names are bounded by
   `^[a-z0-9][a-z0-9-]{0,31}$` (`internal/team/team.go:35`). `identity` prints only the own
   card, signature and backend. The key never leaves the daemon (`daemon.go:622-629`
   returns card, signature, backend and fingerprint only). `mail send` is debug-gated and
   prints only the id, the argv peer and the state. No secret material appears in any of
   these outputs.
5. **`testutil`.** No non-test file imports `internal/testutil`
   (`grep -rln internal/testutil --include=*.go | grep -v _test.go` finds nothing).
   `MkdirPrivate` (`internal/testutil/private.go:14-24`) uses the user cache dir with
   `MkdirAll(…, 0o700)`, then `os.MkdirTemp` (0700). On Windows it relies on the inherited
   `%LOCALAPPDATA%` ACL, which is owner/SYSTEM/Administrators by default. A pre-existing
   `dorylinae-test` directory with a wider mode is not tightened, but the per-test
   `MkdirTemp` directory is always 0700. That is fine for test code.

## Findings

### C28-01 · Medium · confirmed-test
- **Where:** `internal/relayclient/wire.go:28-29` (a handshake `error` frame becomes `envelope.ErrorFrame`, whose `Error()` is `"relay: "+Code+": "+Message`, `internal/envelope/frames.go:178`) → `internal/relayclient/relayclient.go:223-226` (`lastErr = err.Error()`, unbounded) → `internal/daemon/status.go:41` → printed raw by `cmd/agentnet/main.go:256-260` and `cmd/agentnet/doctor.go:356-359`
- **What goes wrong:** The relay's own `code`/`message` text becomes `last_error` verbatim. It has no length cap below the 1 MiB frame and no control, escape or bidi filtering. The daemon serves it in `status`, and both CLIs write it straight to the terminal. It also persists while the client is connected, until the next connection error.
- **Scenario:** Actor: the relay (untrusted; the hosted relay or any `--relay`). (a) On one connection it answers the WebSocket upgrade with `{"op":"error","code":"x","message":"\u001b[2K\r  upgrade:  … install from https://evil…  \u001b]8;;https://evil…\u0007…"}`, then lets the next reconnect succeed. From then on, every `agentnet status` and `agentnet doctor` prints the relay's escape sequences. It can erase and redraw lines, fake a `relay: connected` or `upgrade:` line, or show an OSC 8 hyperlink to a URL it chose (Windows Terminal renders these). This is the same class of harm as review 50 H3, although it needs a click. (b) With a message of 1 000 000 `<` characters (1 byte each in the relay's frame, 6 bytes as `<` from the daemon's HTML-escaping `json.NewEncoder`, `internal/ipc/ipc.go:141`), the status response is about 6 MB. The IPC client rejects any line over 1 MiB (`internal/ipc/ipc.go:258`, `maxLine`). So `agentnet status` fails with exit 1, and `doctor`'s `queryStatus` treats the daemon as down: `socket fail`, `service` probed, `binary skip`. `agentnet setup` (4.9a) runs `doctor` last. This lasts as long as the relay wants. Test: `internal/relayclient/zz_review55_C28-01_test.go` logs `LastError: 1000066 bytes raw, 6000109 bytes as JSON (IPC client line cap 1048576)` and asserts the raw `ESC ]8;;https://evil.example` is present.
- **Spec:** `Docs/cli/status.md:94-96`: "`last_error` is the most recent connection error's message (content-free: a dial or handshake failure…)". Threat model §1, relay row: must never "send the user's browser or OS opener to a URL it chose". Rubric invariant 4, "Peer input is parsed strictly and bounded before it is trusted, stored or displayed", applies equally to relay input.
- **Fix direction:** Do not put relay-supplied text in `lastErr`. Store `relay: <code>` only, with the code validated against the known error codes, or truncate the text and `termSafe` it at the source. Also `termSafe` it in both CLIs.
- **Related:** R53 L4 (the same treatment given to `min_client`); O-100 (the `termSafe` pattern); lead to C-relayclient (log line size)

### C28-02 · Low · confirmed-read
- **Where:** `internal/daemon/stop.go:39-55` (`StopWait` returns once `Dial` gets `ErrNotRunning`); `internal/ipc/ipc.go:102-121` (`Serve` closes the listener at ctx cancel and returns); `internal/daemon/daemon.go:276-576` (the deferred teardown runs after `Serve` returns)
- **What goes wrong:** `agentnet stop` and `agentnetd stop` print "agentnetd stopped" and exit 0 once the IPC endpoint disappears. At that point the process is still running its deferred shutdown: presence goodbye (≤ 1 s), outbox and relay stop, fetch server close (up to about 1 min, O-144), helper stop, `daemon.stop` audit, store close.
- **Scenario:** Actor: the local user or script, in normal use. `agentnet stop && agentnetd run`, or an upgrade script that stops the daemon and then replaces `agentnetd.exe`, runs while the old process still holds the DB, the binary (on Windows the file is locked, so the replace fails) and its relay connection. A new daemon wins the free endpoint. The relay replaces the older connection per key, so the old and new daemons kick each other until the old one's `stopRelay`. `daemon.stop` of the old boot can land after `daemon.start` of the new one in the audit log.
- **Spec:** `Docs/cli/stop.md`, "Asks the running `agentnetd` to shut down cleanly … and waits for it to exit"; exit 0 = "Stopped". (`ipc.md:128-130` describes only "polls the endpoint until it stops answering", so the two docs disagree.)
- **Fix direction:** Wait for the process to exit (the PID from `status` before `shutdown`), or hold a second lock that is released only after `st.Close`.
- **Related:** O-144

### C28-03 · Low · confirmed-read
- **Where:** `internal/daemon/daemon.go:272` (`store.Open` runs every pending migration, `internal/store/store.go:548`) before `daemon.go:283` (`ipc.Listen`, the only single-instance lock)
- **What goes wrong:** A second `agentnetd run` that is going to lose (`ErrAlreadyRunning`, exit 3) first migrates the database under the running daemon. The comment at `:282` intends the loser to leave no trace, but it leaves a changed schema.
- **Scenario:** Actor: the local user in normal use during an upgrade. `install.sh`/brew swaps the binaries while the old daemon runs, then the user (or the service manager, or `agentnet setup`) starts the new `agentnetd`. It applies migrations N+1… to the live DB and exits "already running". The old binary keeps running against a schema newer than it knows. It refuses such a schema at start (`store.go:573`) but not at run time. A migration that adds a trigger or a NOT NULL column its INSERTs do not satisfy would make its writes fail. Migration 18's chain trigger did exactly that for pre-3.6a writers. Current impact depends on future migrations, so the rating is Low.
- **Spec:** none directly. `Docs/protocol/audit.md` §Appending and review 43 M9 cover concurrent openers, not a live older writer.
- **Fix direction:** Take the endpoint lock (`ipc.Listen`) before `store.Open`.
- **Related:** R43 M9, O-169, O-173

### C28-04 · Low · confirmed-read
- **Where:** `cmd/agentnet/main.go:283-314` (`printStatusTeam` prints `m.Name`, from `internal/daemon/status.go:104`, the peer's card name)
- **What goes wrong:** Peer card names reject C0/C1 controls (`internal/agentcard/agentcard.go:116-118`, `unicode.IsControl`) but allow bidi/format characters (Cf: U+202E, U+2066-2069, U+200B). `status --team` prints them raw in the tabwriter table.
- **Scenario:** Actor: a paired or introduced team member. It names its card `"alice‮…"` (or a zero-width-padded copy of another member's name), and its row in `agentnet status --team` then shows reordered or duplicated names. It can pose as another member, which O-067 records as a general concern, now with invisible characters on a new display path.
- **Spec:** `Docs/protocol/agent-card.md:20`, "no control characters" (Cf is not excluded).
- **Fix direction:** `termSafe` names in `printStatusTeam`, as O-100 proposes for the other lists.
- **Related:** O-067, O-100, O-142

### C28-05 · Info · confirmed-read
- **Where:** `cmd/agentnet/doctor.go:511-522` (`probeServiceWindows`)
- **What goes wrong:** "running" is `strings.Contains(schtasks /V output, "Running")`, and "matches" is a raw `Contains` of `exe`/`home` in the task XML. On a non-English Windows the status column is localised, so a running task reads as "installed but not running" (`fail`). A path containing `&`, `<` or `'` is XML-escaped in `/XML` output, so "matches" is false (`warn`). This matters only when IPC is unreachable (`up=false`), which already fails the `socket` check.
- **Scenario:** A German Windows user with a hung daemon gets "the service is installed but not running" instead of the true state. This is diagnostic only.
- **Spec:** `Docs/cli/doctor.md` (service row)
- **Fix direction:** Use `/FO CSV /NH` with a column index, or `Get-ScheduledTask` state codes. XML-unescape before comparing.
- **Related:** none

## Assumptions and contracts

- `status` assumes `relayclient.State().LastError` is content-free, fixed-vocabulary text (`internal/daemon/status.go:41`). **Checked: false**, see C28-01 (`internal/relayclient/relayclient.go:225`).
- `status`/`doctor` assume `State().MinClient` is already a release string (`status.go:43`). **Checked:** `validMinClient` (`relayclient.go:260,325`), and doctor re-parses it (`doctor.go:225`).
- `RunWithOptions` assumes `ipc.Listen` fails with `ErrAlreadyRunning` when another daemon owns the endpoint and removes only a stale Unix socket (`daemon.go:283`). **Checked** at the call site (`transport_unix.go:19-24`, `transport_windows.go:21-32`); the ACLs themselves were not checked (IPC chunk).
- `StopWait` assumes `ipc.Dial` returns `ErrNotRunning` once the listener closes (`stop.go:45`). **Checked** (`transport_unix.go:43`, `transport_windows.go:46`); but see C28-02.
- `startRelay` assumes `relayclient.Client.Run` never calls `OnEnvelope`/`OnReady` before `Run` starts, so `handleMail` is set in time (`daemon.go:731-790`). **Checked:** callbacks only fire from `session` inside `Run`.
- The shutdown order assumes `startMail`'s stop func drains or safely drops queued envelopes after the relay stops (`daemon.go:803`). **Unchecked** (C-mail; O-057 already records drops).
- The `status` handler assumes `outbox.Counts`, `presenceSender.HumanPresent` and `statusTeam` are bounded and fast (the 1.5 s CLI budget). **Unchecked** (presence/team chunks).
- `doctor` assumes `identity.NewKeystoreFromEnv(p.Dir).Load()` reads without creating a key (`doctor.go:298-302`). **Unchecked** (keystore chunk).
- `doctor` assumes `relayclient.CheckURL` gives the same verdict as `cmd/agentnetd` (`doctor.go:347`). **Unchecked** (O-023 context).
- `loadIdentity` assumes `identity.LoadOrCreate` never returns the private key in `rep.Detail` (`daemon.go:693`). **Unchecked** (identity chunk; ipc.md:425-427 promises it).

## Checked and fine

- The listener is closed on every early-error return after `ipc.Listen` (`daemon.go:291, 306, 311, 318, 328, 345, 375, 423, 429, 436, 560`).
- `daemon.start` is written only by the endpoint winner (`daemon.go:282-293`). `daemon.stop` uses a fresh 5 s context after ctx is cancelled (`:294-301`). `daemon.stop_requested` is written with actor `cli` and no detail (`:612-618`), matching ipc.md:124-127.
- The `shutdown` response precedes teardown (a 50 ms `AfterFunc`), as ipc.md says.
- `identity` returns card, signature, backend and fingerprint only; no key (`daemon.go:622-629`).
- `status` rejects malformed params with `bad_request` (`daemon.go:636-639`). `relay` is nil when no relay is configured (`status.go:32-34`), matching status.md:98.
- Presence goodbye runs before `stopRelay`, so the relay is still connected (`daemon.go:572-576` vs `:563`), and the relay client outlives ctx by design (`:794`).
- Every subsystem goroutine with a done channel is awaited: webhook, helper, debate sweep, outbox, presence and relay.
- `status`/`identity`/`stop` CLI exit codes 0/1/2/3 match `Docs/cli/status.md` and `stop.md`. The `stop` JSON error codes (`daemon_not_running`, `stop_timeout`, `daemon_error`, `usage`) match `stop.md`.
- `doctor` never authenticates (R50 M4). With the daemon up it trusts IPC state, and with it down it only reads the challenge (`doctor.go:159-170`, `probe.go`). The exit code is 1 only on `fail`.
- `mail` is unknown without `DORYLINAE_DEBUG=1` (`main.go:118-122`), as `Docs/cli/mail.md` requires.
- O-032 is still present: `internal/protocol/doc.go` and `internal/transport/doc.go` are empty placeholders with no behaviour. They are not a defect.
- `internal/testutil` is not imported by production code; see Q5.

## Leads for other chunks

- `internal/relayclient/relayclient.go:228`: the same relay-controlled `err` (up to 1 MiB) is logged at each reconnect. With `--log-file` rotating at 1 MiB (`cmd/agentnetd/main.go:59`), one such line rotates out all earlier log history.
- `internal/relayclient/wire.go:28-32`: `ErrorFrame` from the handshake is not length- or charset-bounded, and `session`'s error propagates into `lastErr`. The fix belongs there (C28-01 root).
- `cmd/agentnetd/install.go:180`: `store.Open` (migrations) runs while a daemon of another version may be live, the same pattern as C28-03 (R43 M9 area).
- `internal/ipc/ipc.go:141`: the server-side `json.NewEncoder` HTML-escapes, multiplying `<>&` by 6. No response size is checked against the client's 1 MiB `maxLine`. O-178 is the listing variant.
- `internal/agentcard/agentcard.go:116`: `checkText` allows Cf (bidi, zero-width) in name, harness and skills. This is a spec-level decision for agent-card.md.
