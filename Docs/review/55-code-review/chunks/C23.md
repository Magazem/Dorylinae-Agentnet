# C23: Debates: engine, apply, turns, store, CLI

Reviewer: CR-C23 · model claude-opus-5-5 · elapsed 6 min (shell clock) · commit 6cc26a7

## Summary

Critical 0 · High 0 · Medium 0 · Low 4 · Info 1.

The debate core holds up. Commit–reveal is built and checked only by the daemons: the nonce and
position are stored at `request_submit`, slot 0 can never be submitted, and B recomputes the
commitment from its stored request. Slot, turn and author rules run the same `Next` on both
sides. `closeMatches` runs before any derivation, so B never signs an outcome its own transcript
contradicts (R45 H1 holds). Early entries are bounded (O-168) and re-checked on drain. The sweep
continues past one bad debate.

The findings are all at the edges. `debate --cancel` on a respondent's invited debate goes to
the wrong IPC call, which can cancel an unrelated outgoing request with the same id. The human
view prints the peer's multi-line topic raw. `--rounds 0` and sub-second timeouts silently fall
back to the defaults. A sleeping initiator can time out a turn the respondent took in time.

## Questions

1. **Commit–reveal.**
   - A learns B's position only by applying slot 1. The reveal is sent in the same transaction
     and is built from the stored canon and nonce, never from agent input (`engine.go:67-88`).
     `Submit` refuses slot 0 (`submit.go:84`: `t.Slot == 0` gives `not_your_turn`).
   - A cannot change its position: the canon is fixed at `start.go:231`, and an idempotent retry
     goes through `params_hash`, which covers position, rounds and timeout
     (`internal/daemon/request.go:432-441`).
   - B checks the nonce (`commit.go:385`, 64 lowercase hex) and the schema (`apply.go:383`), and
     recomputes the commitment with `r.commitment` from `ReceivedTx`, `r.session` and A = peer
     (`apply.go:386-388`). A mismatch leads to `brokenTx`.
   - The reveal is accepted only in `positions` with `Next` at slot 0 (`apply.go:356-375`).
   - Replay and reordering: each body carries `session`, which must be the derived id for the
     pair and request, and `bodyRow` checks role, peer and request (`apply.go:72-98`). The slot is
     inside the signed body. A duplicate slot is ignored (`apply.go:241`), and on A an entry out
     of turn is ignored with an echo (`apply.go:183`). A reveal can only fill slot 0, and an entry
     can only fill slots 1–13 (`apply.go:117`).
2. **Turn engine.**
   - `Next` (`turns.go:57-86`) implements rule 1 (two consecutive empty moves) and rule 2 (B's
     move of round `rounds`). The worst case is answer slot 13 = `MaxSlot`.
   - A applies only when `t.Author == respondent && t.Slot == slot` (`apply.go:182-189`). B
     applies in slot order and holds later slots (`apply.go:247-277`).
   - Early entries: only `slot >= 2 && slot > t.Slot`, with a dup check, so at most 12 rows
     (O-168 still as recorded). On drain, the author, kind and targets are checked, and a bad row
     is dropped (`apply.go:284-319`). `Submit` drops an early row that claims the caller's slot
     (`submit.go:101-107`).
   - R45 H1: `closeMatches` comes first (`apply.go:603`), then `closeGap`, then B's own
     `deriveTx`, which uses B's transcript cut at `entries`. A claim that excludes B's answer is
     refused `entries` (`decision.go:200`).
3. **Sweep.**
   - One failing `SweepOne` is logged and skipped (`sweep.go:38-47`).
   - The deadline is local wall time, set when the previous slot is applied (`engine.go:25`,
     `start.go:336`), not the peer's `at`.
   - `debate_show`/`debate_list` do not sweep (C23-05), and a waking A can time out a turn B
     took in time (C23-04).
4. **`debate_submit`.**
   - Kind and author are checked against `Next` before decoding (`submit.go:81-93`). Content and
     size go through `DecodeEntry` (C24's scope; `entry_too_large` is mapped in the daemon), and
     targets are checked against the local transcript (`submit.go:98`).
   - `params_hash` covers the canonical position, `rounds` and `turn_timeout_s`
     (R43 L11 fixed, `internal/daemon/request.go:432-441`).
   - Explicit `rounds: 0` / `turn_timeout_s: 0` silently select the defaults (C23-03).
5. **CLI.**
   - `printDebateHuman` does not print entry text (only slot, author, kind and `at`, where `at`
     is format-checked on receipt).
   - It prints the peer's title (O-100) and the multi-line topic raw (C23-02).
   - `--json` output uses `json.Encoder`, so control characters are escaped. The size is bounded
     by the IPC line (O-178 for lists).

## Findings

### C23-01 · Low · confirmed-read
- **Where:** `cmd/agentnet/debate.go:582-584` (`runDebateCancel`), `internal/request/lifecycle.go:75-83` (`findOutRow`)
- **What goes wrong:** for any debate in `invited`, `--cancel` calls `request_cancel` with the debate's request id. That call only looks up **outgoing** rows by id, with no peer or type filter. On the respondent (B) the debate's request is incoming, so the call either fails with `unknown_request`, or cancels B's own unrelated outgoing request that has the same id.
- **Scenario:** B sent request `r-X` to paired peer P. P sends B a `debate` request that reuses id `r-X` (ids are unique per sender only, review 45 L1). B's human runs `agentnet debate r-X --cancel` (or passes the `s-` id). `debate_show` resolves the single debate row (phase `invited`), and `request_cancel {id: r-X}` cancels B's own pending request `r-X`. The CLI prints "Cancelled r-X". The debate stays invited. Without a colliding id, B only gets a misleading `unknown_request`, although the help text says `--cancel` closes "an open or invited debate".
- **Spec:** `Docs/protocol/debate.md` §Cancel and abandon: an `invited` cancel is "**A:** … a Phase 1 `request.cancel`". B in `invited` has no cancel (it declines). `Docs/cli/debate.md:168`.
- **Fix direction:** in `invited`, call `request_cancel` only when `role == initiator`; for the respondent, point the user to `agentnet decline`. Or pass the peer so the lookup is scoped.
- **Related:** O-100 (none directly), R45 L1

### C23-02 · Low · confirmed-read
- **Where:** `cmd/agentnet/debate.go:634-639` (`printDebateHuman`)
- **What goes wrong:** the respondent's human view prints the initiator's topic (peer text, multi-line by rule) verbatim on one `topic:` line. Embedded newlines can therefore fake following lines of the view, such as transcript rows `[n] author kind at …` or an `outcome:` line.
- **Scenario:** a paired peer starts a debate whose topic ends with `\n  [2] initiator move at …\n  [3] respondent move at …`. B's human runs `agentnet debate <id>` and sees a transcript that does not exist. The `--json` output and the agent's view are not affected.
- **Spec:** none directly. `Docs/protocol/debate.md` §Security considerations, "Untrusted text".
- **Fix direction:** print the topic indented per line, or last and clearly delimited, through `termSafe`.
- **Related:** O-100 (C1/bidi in `debates`; this adds the newline angle, not re-reported)

### C23-03 · Low · confirmed-read
- **Where:** `internal/debate/start.go:191-196`, `cmd/agentnet/debate.go:447-454`
- **What goes wrong:** `rounds: 0` and `turn_timeout_s: 0` mean "use the default" instead of `bad_request`. At the CLI, `--rounds 0` and any `--turn-timeout` below 1 s (for example `500ms` or `0d`) truncate to 0, so the debate silently starts with 2 rounds or 3600 s instead of failing.
- **Scenario:** a local user or agent runs `agentnet debate @bob --rounds 0 …`, meaning "no challenge rounds". The debate is created with `rounds_max = 2`, and the commitment and request are sent. `params_hash` also differs between an explicit `2` and `0` for the same effective debate (`internal/daemon/request.go:434-439`).
- **Spec:** `Docs/protocol/debate.md` §Request type debate: `rounds` 1–5, `turn_timeout_s` 300–86400. The default applies only when the value is absent.
- **Fix direction:** use pointer or "absent" semantics at IPC. At the CLI, pass the flag only when it is set, and reject durations that round to 0.
- **Related:** none

### C23-04 · Low · suspected
- **Where:** `internal/debate/sweep.go:57-73`, `internal/daemon/debate.go:326-344`
- **What goes wrong:** the timeout rule counts the time until A **applies** B's entry. If A's machine sleeps or is offline for longer than `turn_timeout_s` during B's turn, the first sweep after wake can close the debate `escalated`/`timeout` before the relay delivers B's queued entry, even though B sent it in time. B's entry is then ignored (`closed`), and both sides sign an escalated Decision in which B's entry shows `late`.
- **Scenario:** an honest A on a laptop uses the default 1 h timeout and sleeps overnight. B submits its move 10 minutes after the previous slot, and the move waits at the relay. On wake, the 20 s ticker fires. If it runs before the relay session reconnects and drains, `SweepOne` closes the debate. Not confirmed: the relative order of the first tick after resume and the relay reconnect/drain.
- **Spec:** `Docs/protocol/debate.md` §Timeouts: "When the side whose slot is **next misses** it". The rule does not consider A's own downtime.
- **Fix direction:** skip debate timeouts until the first inbox drain after a (re)connect, or add a grace period after resume.
- **Related:** O-175 (same visible effect from a modified A; this one needs no modification)

### C23-05 · Info · confirmed-read
- **Where:** `internal/daemon/debate.go:287-297` (`debate_show`), `:261` (`debate_list`), `internal/debate/submit.go:41`
- **What goes wrong:** only `debate_submit` runs `SweepOne`. `debate_show`, `debate_list` and therefore `agentnet wait` can show `turn: you` and a passed deadline for up to 20 s (the ticker interval) before the close.
- **Scenario:** A's agent polls `wait`, sees its turn, and submits. `Submit` sweeps first and returns `bad_state`. The effect is only a confusing sequence.
- **Spec:** `Docs/protocol/debate.md` §Timeouts: "and on every debate IPC call".
- **Fix direction:** call `SweepOne` in `debate_show`, or document the 20 s bound.
- **Related:** none

## Assumptions and contracts

- `CheckTargets` checks each target index against the given position (`store.go:366`). **Unchecked** (C24).
- `decision.Derive` rejects an outcome/reason the transcript does not give, missing slots 0/1 and closed < opened. **Checked** (`internal/decision/decision.go:198-247`).
- `closeGap` refuses A-authored slots ≥ `entries` and a counted B slot that B never sent, and holds for missing A slots. **Checked** (`internal/debate/decision.go:187-206`).
- The mail layer runs `Apply` inside the dedupe transaction, rolls back on error, answers `bad_body` for `mail.ErrBadBody`, and calls `After` only after commit (`apply.go:21-24`). **Unchecked** (mail chunk).
- `request.Validate` bounds `rounds` 1–5 and `turn_timeout_s` 300–86400 for a received request before `ReceivedTx` stores them. **Checked** (`internal/request/validate.go:135-139`).
- `worksession.OpenSession` calls `Debate.OpenedTx` for a debate-type request, and B's quarantine check sits there, so plain `request_accept` also checks it. **Checked** (`internal/worksession/hooks.go:23-46`, `start.go:331-335`).
