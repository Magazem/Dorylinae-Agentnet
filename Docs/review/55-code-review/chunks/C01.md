## Summary

| Critical | High | Medium | Low | Info |
|---|---|---|---|---|
| 0 | 2 | 0 | 2 | 2 |

Verdict: authentication, sender binding, per-key and per-prefix limiters, and the charge/uncharge
bookkeeping in `conn.go` are sound. Two relay-wide availability defects remain in the memory-bound
design of R-4.0 H1 / review 50 M2, both confirmed with tests. First, (C01-01) presence frames are
charged to the shared `--max-inflight` budget but never refused by it. So about 3 prefixes of
free keys, sending presence to their own non-reading connections, push every direct mail on the
relay into the queue and stall all queue drains. Second, (C01-02) the read budget has no per-frame
timeout and no fairness. About 46 connections from **one /24** that each start a 1 MiB frame and
never finish it make the relay close **every other connection that sends any frame**, with 1013,
indefinitely. Both are "a cheap unauthenticated attacker takes the hosted relay down for
everyone" (rubric §2 High).

## Questions

1. **Pre-auth cost.** `ServeHTTP` runs `admitUpgrade` (`limits.go:221`) before `websocket.Accept`
   (`relay.go:468`), covering the failed-auth window, the upgrade bucket (30/min, burst 60), 64
   connections per prefix and 256 unauthenticated relay-wide. `authenticate` holds one goroutine,
   the hijacked bufio buffers, one context timer (TTL 10 s, `relay.go:589`) and a read of at most
   `MaxAuthFrameBytes` = 4 KiB (`relay.go:474`, `envelope.go:19`). It never touches SQLite. A
   client that never answers is cut at the TTL and counted as a failure (`relay.go:604-605`). A
   client that closes early is not counted (O-025, still as recorded). Open/close loops are bounded
   by the upgrade bucket. Compression is off (coder/websocket v1.8.15 zero value
   `CompressionDisabled`), so there is no inflate amplification. The pre-handler TLS/HTTP phase is
   bounded only by `cmd/relay` server timeouts, which are outside this chunk (Leads).
   Unauthenticated cost is bounded. The authenticated read phase is **not** fairly bounded (C01-02).
2. **Auth replay/forwarding/downgrade.** The nonce is 32 random bytes per connection
   (`relay.go:584`), and both versions sign it (`frames.go:206`, `authv2.go:36`). v2 also binds a
   length-prefixed origin under its own domain string and is accepted only for this relay's
   canonical origins (`authv2.go:73-78`), so a challenge forwarded from relay X is refused by Y. A
   v1 frame is verified and then refused with `ErrAuthV1Refused` when `!authV1` (`auth.go:64-71`).
   `authV1 = !Public || AllowAuthV1` (`auth.go:37`). Whether the no-downgrade rule holds behind a
   proxy depends only on `cmd/relay` computing `Public` (`transport.go:94-97`, which sets it for
   non-loopback listen or any TLS/proxy/origin mode). An unknown `V` is refused. Late answers are
   refused by the ctx and `time.Since` checks (`relay.go:609`, wall clock: O-002 still open). No
   replay path found.
3. **Sending as another key.** Every envelope, ephemeral ones included, checks
   `h.From != sender.key` before any routing (`relay.go:760`). Queue accounting uses `h.From`,
   which is therefore the authenticated key. `ack` deletes only rows with `to_key = c.key`
   (`pairing.go:157`, `queue.go:365`), so a key cannot ack or delete another key's frames.
   Pairing and account ops are in C02/C03. `Classify`/`ParseHeader` use `encoding/json`
   (case-insensitive, last duplicate wins), but the relay uses one parser consistently and the
   daemon verifies signatures, so this is not a bypass.
4. **Budget charge/uncharge.** Traced every path. Direct sends use `sendCappedLocked` (tryAdd,
   `conn.go:211`). Drains use `reserve`, then `sendReserved`, and a deferred return of the unused
   part (`relay.go:886-890`, `conn.go:148-200`). `written` skips the uncount once `dead`, and
   `release` uncounts `outBytes` (`conn.go:220-252`). This is correct under the writeLoop/release
   race. The read budget is uncharged on every exit of `readFrame` and after `route`
   (`relay.go:706-727`, `680`, `675`). There are two gaps. `send` (control **and ephemeral**)
   charges without a check (`conn.go:109-121`), which leads to C01-01. The outbound budget counts
   `len(frame)` while the retained read buffer can be twice that (C01-03). `c.release()` is not
   deferred (C01-06). No charge-without-uncharge path otherwise.
5. **Replacement.** `register` swaps the map entry under `s.mu` and kicks the old connection
   asynchronously (`relay.go:950-951`, `639`). `unregister` deletes only its own entry
   (`relay.go:967`). The old connection can go on sending as its own key until its close
   handshake ends (≤ 10 s), which is harmless. Frames in the old `out` that are not yet written
   are lost (O-001). The old connection's drain and the new one's drain (cursor 0) can send the
   same queued rows twice. Delivery is at-least-once until `ack`, and daemons dedupe. The
   goroutines end with the old ctx (`relay.go:625-626`, `reserve`/`sendReserved` watch `ctx`).
   There is no leak. `admit` lets a replacing key skip `MaxConns` (`relay.go:528`), which is
   bounded by 20 reconnects/min/key. No finding.
6. **Limiter maps / prefix spoofing.** `bucketSet` prunes full buckets once a minute past 1024
   entries (`limits.go:374-381`). `control` prunes past 1024 (`limits.go:318`). `authFails`
   prunes ended windows (`pairing.go:489`). The ephemeral windows are pruned every minute
   (`ephemeral.go:52`). `logSeen` is pruned past 1024. All are bounded by the rate at which
   prefixes and keys can be created. The header is honoured only when `public && ipHeader &&
   TCP peer ∈ trusted` (`limits.go:446-456`). It takes the last value's last comma entry, strips
   the zone and unmaps. `Open` refuses a header without trusted proxies (`relay.go:290`). A header
   from an untrusted peer is ignored (`TestLimitSpoofedClientIPHeaderIgnored`). Residual: O-029,
   O-019.

## Findings

### C01-01 · High · confirmed-test
- **Where:** `internal/relay/conn.go:97-121` (`directEphemeral` → `send` → `charge`), `internal/relay/ephemeral.go:95`; effect at `conn.go:211` (`sendCappedLocked` tryAdd) and `conn.go:156` (`reserve`)
- **What goes wrong:** Presence frames are charged to the relay-wide `--max-inflight` budget with `add` (never refused), up to 33 frames × 8 KiB per recipient connection. Once they spend the budget, `tryAdd` fails for **every** mail direct send on the relay (→ `directBusy`, queued) and for every queue drain's `reserve`. All mail delivery between honest online peers stops for as long as the attacker keeps its connections slow.
- **Scenario:** Stranger with free keys: ~180 recipient keys (3 prefixes × 64 keys) connect and read very slowly, just enough to keep each 10 s write alive. A few sender keys send each recipient ~33 presence envelopes of ≤ 8 KiB (well under 600/min/key; the relay checks only routing fields and `from`). In-flight exceeds 48 MiB (hosted flag) with no mail at all. Every honest mail then gets `queued` instead of being forwarded, and no drain can reserve its batch. Test: the honest mail between two online, reading peers gets `queued` and is not delivered within 2 s. At default flags (256 MiB) ~16 prefixes are needed. The same frames also pin heap outside any refusal: at 2000 conns about 33 × 16 KiB backing (see C01-03) ≈ 1 GiB, above `GOMEMLIMIT=400MiB`.
- **Spec:** `presence.md` §Relay: "a presence flood from many senders cannot push a recipient's mail into the queue path"; `relay-hosted.md` §2 memory bound ("past it direct sends take the queue path"); `envelope.md` §Forwarding step 4.
- **Fix direction:** Make ephemeral (and ideally control) pushes use `tryAdd` and drop presence when the budget or the connection's byte cap is spent, or give them a separate small budget so they never consume mail's.
- **Related:** O-072, O-009 (ephemeral limits), R52 H1 / R50 M2 (budget design), C01-02.

### C01-02 · High · confirmed-test
- **Where:** `internal/relay/relay.go:700-730` (`readFrame`, no per-frame deadline), `relay.go:663-668` (closes the *reader that asked*), `limits.go:422-433`
- **What goes wrong:** The read budget is first-come. After auth there is no read or idle deadline, so connections that start maximum-size frames and never finish them can hold the whole budget forever. Every other connection's next frame then needs its first 4 KiB chunk, fails `tryAdd`, and is closed with 1013. The attacker's connections are never evicted.
- **Scenario:** Stranger, **one /24**, 46 fresh keys (the cap is 64 keys/conns per prefix, and the upgrade burst is 60). Each authenticates, opens a text message and sends ~1 MiB of it without the final fragment. That is a one-time 48 MiB upload, charged ≈1 MiB each (`relay.go:711`), filling the hosted 48 MiB budget. Then every honest daemon on the relay is closed 1013 on its next mail, ack or presence, including right after it reconnects. Test (scaled: 64 KiB budget, 16 attacker connections × 4 KiB): the victim's 200-byte mail closes it 1013, twice in a row. The R52 H1 note rejected waiting for budget because of deadlock, but did not consider that closing the *new* reader hands the budget to whoever took it first.
- **Spec:** `envelope.md` §Forwarding: "Errors on a single envelope never close the connection"; `relay-hosted.md` §2 threat "exhaust relay memory …/lock out … for others".
- **Fix direction:** Add a per-frame completion deadline (a frame must finish within N s of its first byte), and a per-prefix or per-connection share of the read budget (or a small unconditional first chunk). Past the budget, evict the largest or oldest holder rather than the newcomer.
- **Related:** R52 H1 (reopens its "close the reader" choice), O-025, O-024.

### C01-03 · Low · confirmed-read
- **Where:** `internal/relay/relay.go:709-721` (grow-before-EOF), `conn.go:204-216` (charges `len(frame)`)
- **What goes wrong:** `readFrame` grows the buffer whenever `len == cap`, before it sees EOF, so a frame whose length is a power of two ≥ 4 KiB keeps a backing array of twice its length. In general, cap ∈ [len, 2·len]. The routed frame is retained in `out`, but the outbound budget counts only `len`. Real outbound heap can therefore reach 2 × `--max-inflight`, and the R52 memory bound (≈ 2 × max-inflight + idle cost) is ≈ 3 × in practice.
- **Scenario:** Stranger sends mail frames sized just over a power of two to its own non-reading recipients until the outbound budget is full. The heap holds up to ~96 MiB against a 48 MiB flag. It is bounded, which is why it is Low.
- **Spec:** `relay-hosted.md` §2 memory bound.
- **Fix direction:** Charge `cap(frame)` or trim/copy to `len` before handing the frame to `out`.
- **Related:** C01-01, R52 H1.

### C01-04 · Low · confirmed-read
- **Where:** `internal/relay/relay.go:735-763` (bad_envelope / bad_sender paths), `ephemeral.go:86`
- **What goes wrong:** Frames that fail `Classify`/`ParseHeader`, carry the wrong `from`, or are oversized presence frames are fully read (≤ 1 MiB), JSON-decoded twice and answered, but never charged to the per-key or per-prefix byte and envelope limits. Only the ephemeral count (600/min) applies to presence.
- **Scenario:** An authenticated stranger key streams 1 MiB invalid frames. The relay spends two full JSON decodes per MiB and queues one error frame each, limited only by the attacker's upload bandwidth, not by the 32 MiB/min key cap. Mostly CPU. No state grows.
- **Spec:** `relay-hosted.md` §2 (byte limits "non-ephemeral envelopes"); `envelope.md` Forwarding step 3.
- **Fix direction:** Charge the byte buckets for every frame read after auth, before parsing.
- **Related:** O-010 (the ephemeral subset).

### C01-05 · Info · confirmed-read
- **Where:** `internal/relay/limits_test.go` `TestLimitMaxInflightRelayWide` ("Control frames … counted but never refused, hence the slack")
- **What goes wrong:** No test sends presence to non-reading recipients. The 64 KiB slack accepts unrefused bytes, which is how C01-01 escaped the 4.0b load tests.
- **Scenario:** n/a (test gap).
- **Spec:** `relay-hosted.md` §2 "The 4.0b load test sends maximum-size frames to non-reading recipients".
- **Fix direction:** Add a presence-flood-to-non-reading-recipients case to the memory tests.
- **Related:** C01-01.

### C01-06 · Info · suspected
- **Where:** `internal/relay/relay.go:509-510`
- **What goes wrong:** `c.release()` runs after `serve` returns but is not deferred. If `route` ever panicked, net/http would recover the handler goroutine and the connection's `outBytes` would stay charged to `--max-inflight` forever. `dismiss`, `unregister` and `lim.release` are deferred, so they would still run.
- **Scenario:** Needs a panic on peer input; I found none (`Classify`/`ParseHeader` are plain `encoding/json`).
- **Spec:** none.
- **Fix direction:** `defer c.release()` right after `admit` succeeds.
- **Related:** none.

## Assumptions and contracts

- `Public` is true for every non-loopback or proxied deployment (`cmd/relay/transport.go:94-97`). v2-only enforcement relies on it. **checked** (read; O-019 is the known residual).
- `http.Server` has `ReadHeaderTimeout` 10 s, `IdleTimeout` 60 s and `MaxHeaderBytes` 8 KiB to bound the pre-`ServeHTTP` phase (`cmd/relay/transport.go:21-38`). **checked** (values present). A TLS-handshake flood before `ServeHTTP` is not counted by any per-prefix limit (Leads).
- `envelope.Header.Validate` rejects malformed `to`/`from`/`id`/`type`, so `h.To` is a well-formed key before the map lookup and SQLite insert (`envelope.go:118-123`). **unchecked** in detail (C05).
- `envelope.VerifyAuthV2` binds nonce and canonical origin with domain separation from v1 (`authv2.go:36-48, 65-80`). **checked**.
- `queue.add`/`next`/`ack` bound their SQLite time with `queueOpTimeout` and scope `ack` to `to_key` (`queue.go:264-378`). **checked** for `ack`; the rest belongs to C02.
- `handleControl` (`pairing.go:141-165`) returns false for any op not allowed after auth, which makes `serve` kick with 1008. **checked**.
- `accountRoutes`/`accountAllows`/`register`'s account state (`accounts.go`) are consistent with `s.mu`. **unchecked** (C03).
- coder/websocket `Conn.Write` closes the connection when its ctx expires (10 s `writeTimeout`), which is what ends a non-reading recipient. **unchecked** in the library source.

## Checked and fine

- Sender binding for every envelope type, ephemeral included (`relay.go:760`). `ack` scoped to the authenticated recipient (`queue.go:365`).
- Auth: fresh 32-byte nonce per connection, TTL enforced twice, unknown `V` refused, v1 refused on a public relay unless `AllowAuthV1`, a v1-refused answer not counted as a lockout failure (`relay.go:477`, `auth.go:57-76`).
- Admission bookkeeping: `admitUpgrade`/`authDone`/`release` pair on every path, including `Accept` failure (`relay.go:467-471`). `admit`/`dismiss` pair (`relay.go:497-506`).
- Outbound and drain accounting: no double-charge or leak across `sendReserved`/`release`/`written` races (`conn.go:148-252`). R52 H1(b) holds: the drain reserves before `q.next` (`relay.go:886-892`).
- Ordering: the empty-queue check and `draining=false` sit under `c.mu`, and `enqueue` re-arms after insert (`relay.go:824-829, 899-902`).
- `Close`: `drainWG.Add` only under `mu` while not closing (`relay.go:859-866`). Drains bounded by 10 s, then per-connection `drainClose` in the background.
- `clientAddr`: zone stripped (R52 L1 fix present, `limits.go:469`), IPv4-mapped unmapped, `clientPrefix` masks /24 and /48 (`relay.go:562-575`).
- Limit logging carries only limit name plus prefix or 8-char key, never ids or payload (`limits.go:183-207`). Route logs carry ids and sizes but no payload (the envelope.md logging rule).
- Open findings touched, still as recorded: O-001, O-002 (`relay.go:588` still `time.Now()`), O-009, O-010, O-012, O-013 (no `to == from` check in `routeEphemeral`), O-025, O-027 (`diskfree_*`), O-028, O-029.

## Leads for other chunks

- `cmd/relay/transport.go:31-40`: no listener connection cap (`netutil.LimitListener`) before `ServeHTTP`. TLS handshakes and slow headers from many IPs are not per-prefix limited (C04).
- `internal/relay/accounts.go:540` `touchAccountKey`: a SQLite write per authentication on the single connection. Check its rate against the reconnect limit (C03).
- `internal/relay/queue.go:264` `add`: every `directBusy` caused by C01-01 turns into a SQLite write under `q.mu`, which amplifies C01-01 into queue and disk load (C02).
- `internal/envelope/frames.go:188` `Classify`: case-insensitive `encoding/json` field matching (`"OP"`, `"From"`). The relay and daemon must agree on one parser. Check that the daemon uses `ParseStrict` for envelopes (C05).
