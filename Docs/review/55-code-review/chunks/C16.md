# C16: Local daemon install, service, IPC transport, paths, log file

Reviewer: CR-C16 · model claude-opus-5-5 · elapsed ~25 min · commit 6cc26a7

## Summary

| Critical | High | Medium | Low | Info |
|---|---|---|---|---|
| 0 | 1 | 1 | 4 | 2 |

The service definitions are escaped carefully for their formats (XML, systemd quoting,
CommandLineToArgvW), the argv of every service command is fixed, the IPC framing is bounded
before allocation and errors never leak handler text. The weak spot is the **Windows named
pipe**: its name is a predictable global name and neither the daemon nor the client checks
who owns the pipe, so another OS user who creates it first both keeps the real daemon from
starting and receives every CLI/agent request (content) and answers them (C16-01, confirmed
by test). Secondarily, on macOS the unrotated launchd log lets a hostile relay grow the
user's disk without bound (C16-02).

## Questions

1. **IPC access by another OS user; bounds; slow clients.**
   - Unix: the socket is in the config dir, which `paths.Ensure` forces to 0700 on every start,
     even for an existing or custom dir (`internal/paths/paths.go:57-64`, called at
     `internal/daemon/daemon.go:269` before `ipc.Listen` at :282); the socket is created
     under umask 0177 (`internal/ipc/transport_unix.go:28-31`). Another user cannot reach it.
   - Windows: the pipe DACL is `D:P(A;;GA;;;<user SID>)` (`transport_windows.go:26-27`), go-winio
     sets `FILE_PIPE_REJECT_REMOTE_CLIENTS` and creates the first instance exclusively, and
     the client dials at `SECURITY_ANONYMOUS` (go-winio v0.6.2 `DialPipeAccess`), so a
     squatter cannot impersonate the client's token. **But** the name
     `\\.\pipe\dorylinae-<sha256(dir)[:8]>` (`paths.go:69-72`) is computable by anyone who
     knows the user name, and the global pipe namespace lets any user create it first:
     **C16-01 (High)**. The name is also case-sensitive on a case-insensitive FS: **C16-05**.
   - Size: `readLine` stops at 1 MiB + one 4 KiB chunk before returning (`ipc.go:210-225`);
     an oversized line gets `bad_request` and the conn is closed (`ipc.go:146-149`).
   - Blocking: each connection has its own goroutine; a read deadline of 30 s per line and a
     write deadline per response (`ipc.go:143,152`). One slow client cannot stall others.
     There is no cap on concurrent connections (a local agent could open many, each ≤ ~1 MiB
     buffered); a local-agent DoS of its own daemon, noted only.
   - Malformed JSON, empty method, unknown method: fixed error responses (`ipc.go:161-172`);
     non-`*Error` handler errors are reduced to `internal error` (`ipc.go:182`). No panic path
     seen in the transport (a handler panic is outside scope: lead).
2. **Service files.** Plist: every value through `xml.EscapeText` (`launchd.go:210-227`,
   `env.go:61-65`). Task XML: user, command, arguments and working dir through `xmlEscape`
   after `windowsQuote` (`schtasks.go:58-62,105`), and `windowsQuote` implements the
   CommandLineToArgvW backslash rules (`schtasks.go:110-134`, tested `TestWindowsQuote`).
   systemd: `\`, `"`, `%`, `$` escaped inside double quotes (`systemd.go:72-75`). Two gaps,
   both needing an unusual owner-chosen path: a newline in a Unix home/exe path is not
   rejected or escaped in the unit, and Task Scheduler expands `%VAR%` in `<Arguments>`/
   `<WorkingDirectory>`: **C16-06 (Low)**. Environment: only `DORYLINAE_RELAY_URL` (the
   default for `--relay`, `install.go:66`) and `DORYLINAE_HOME`/`XDG_CONFIG_HOME` affect the
   plan; the relay URL passes the relay URL rule without the insecure escape hatch
   (`install.go:97`); the relay is untrusted anyway, and a hostile environment is "malware as
   the user" (out of scope). The executable is `os.Executable` with symlinks resolved
   (`install.go:37-43`); install does not check who can write it: **C16-04 (Low)**. The
   `service.go` exec argv is fixed: programs are literals (`schtasks.exe`, `launchctl`,
   `systemctl`) and arguments are constants or validated paths (`schtasks.go:37-51`,
   `launchd.go:181-194`, `systemd.go:30-47`); `ExecRunner` uses `exec.CommandContext`
   without a shell (`service.go:119`).
3. **Paths.** Unix: 0700 on creation and re-chmod on every start (`paths.go:57-64`). Windows:
   `MkdirAll` mode is ignored and no DACL is set; the dir inherits its parent's ACL. For the
   default `%APPDATA%\dorylinae` that is the private profile ACL; for a `--home` under a
   drive root it is not (`Authenticated Users:(M)`), which `agentnet doctor` warns about by
   design (Docs/cli/doctor.md:30). Owner-chosen home, so Info at most: **C16-08**.
   `DORYLINAE_HOME` is taken as given and made absolute (`paths.go:31-33,43`). Long socket
   paths: O-203 still open (no length check in `transport_unix.go:24-31` or `paths.go`).
4. **Log file.** Created with 0600 (`logfile.go:40`) inside the private config dir; the
   Windows task passes `<home>\agentnetd.log` (`schtasks.go:62`). Rotation removes
   `<path>.1` and renames `<path>` (`logfile.go:76-81`): `os.Remove` on a symlink removes the
   link, not its target, and both names are in the owner-only dir, so no other user can
   plant a link. The cap holds on Windows (~2 MiB). Two defects: a failed rotation kills
   the log for the process lifetime (**C16-03, Low, confirmed-test**), and on macOS the
   launchd `StandardErrorPath` log is never rotated while a relay can drive log volume
   (**C16-02, Medium**).
5. **Relay URL rule and `relay_ca.pem`.** `run` and `install` both call `checkRelayURL`
   (`main.go:78`, `install.go:97`); install never honours `DORYLINAE_ALLOW_INSECURE_RELAY`.
   `relayRoots` fails closed (exit 2) on an unreadable or certificate-less stored CA
   (`relayurl.go:56-65`). Beyond O-017/O-018/O-023: `os.WriteFile(caPath, …, 0o600)` keeps
   the mode of an existing file (`install.go:148`), harmless in the 0700 dir. Nothing new.

## Findings

### C16-01 · High · confirmed-test
- **Where:** `internal/ipc/transport_windows.go:21-36` (`Listen`), `:40-50` (`Dial`); name from
  `internal/paths/paths.go:69-72`; also `cmd/agentnetd/main.go:115-121,135-143`, `stop.go:44`
- **What goes wrong:** the Windows pipe name is a predictable name in the machine-global
  pipe namespace, and nobody verifies the pipe's owner: `Listen` treats an existing pipe as
  "already running" and exits, and `Dial`/`Call` talk to whatever process serves the name.
- **Scenario:** another OS user on the same PC (fast user switching, a second account, a
  service running as another user) computes `sha256("C:\Users\<victim>\AppData\Roaming\dorylinae")[:8]`
  and creates `\\.\pipe\dorylinae-<id>` with an Everyone DACL while the victim's daemon is
  not running (before the victim logs on, or after a crash/`stop`). (a) At logon the task's
  `agentnetd run` gets ERROR_ACCESS_DENIED from the exclusive first-instance create, prints
  "already running" (with a PID the squatter supplies via `runningPID`) and exits 3, every
  time: the victim has no daemon. (b) The victim's `agentnet` CLI and local agents connect
  to the squatter, which reads every request (`mail_submit` bodies, request/debate text,
  peer names) and returns forged results (fake `inbox` content to prompt-inject the agent,
  fake `status: running`, fake `stop` success). Test: squatter pipe → `Listen` returns
  `ErrAlreadyRunning`, `Call("mail_submit", {"body":"secret content"})` succeeds and the
  squatter logs the body. Client token impersonation is **not** possible (anonymous level).
- **Spec:** `Docs/protocol/ipc.md` §Endpoint, "Pipe DACL grants access to the current user's
  SID only"; rubric threat model: another local OS user must never read the IPC endpoint.
- **Fix direction:** client checks the pipe server's owner/SID (e.g. `GetNamedPipeServerProcessId`
  + process token user, or the pipe's owner SID from `GetSecurityInfo`) equals its own before
  sending; include the user SID in the pipe name and, on `Listen` failure, report "pipe held
  by another user" instead of "already running".
- **Related:** O-203 (Unix analogue: none, the 0700 dir protects the socket); D24.

### C16-02 · Medium · confirmed-read
- **Where:** `internal/service/launchd.go:200,224-227` (stdout/stderr → `<home>/agentnetd.log`,
  no `--log-file`), `internal/relayclient/relayclient.go:442,462` (unlimited Warn per bad frame)
- **What goes wrong:** on macOS the daemon's log is the launchd-redirected stderr file, never
  rotated, and the relay can make the daemon write one log line per frame without any rate
  limit, so relay input grows the user's disk without bound.
- **Scenario:** a hostile or compromised relay sends a stream of 1-byte malformed WebSocket
  frames; each yields `ignoring malformed frame from relay` (~100 bytes, ~50× amplification);
  invalid envelopes also log the parse error. At a few MB/s the file grows by GBs per hour
  until the disk fills. Windows (1 MiB rotation) and Linux (journald rate limits and caps)
  are bounded; macOS is not.
- **Spec:** `Docs/cli/agentnetd-install.md` §Logs, "(not rotated)" chose this without the relay
  as an actor; rubric §1: the relay must never "grow its memory/disk without bound".
  Reopens the §Logs choice.
- **Fix direction:** pass `--log-file <home>/agentnetd.log` in the plist too (rotating writer),
  and/or rate-limit per-frame relay warnings.
- **Related:** O-051 (log volume of mail rejects; this adds the unbounded-disk impact on macOS
  and a second, unlimited log site); lead for relayclient.

### C16-03 · Low · confirmed-test
- **Where:** `internal/logfile/logfile.go:72-85` (`rotate`), `:62-64` (`Write` after `f == nil`)
- **What goes wrong:** `rotate` sets `w.f = nil` before removing/renaming; if the rename (or
  remove, or reopen) fails once, every later write returns `os.ErrClosed` and the daemon logs
  nothing for the rest of its life, silently (slog drops write errors).
- **Scenario:** on Windows, any process holding `agentnetd.log` open without
  `FILE_SHARE_DELETE` at the moment of rotation (a log viewer, `Get-Content -Wait`, an AV
  scanner, a local agent reading the log) makes `os.Rename` fail with a sharing violation;
  the log stays dead after the viewer closes. Test output: "write during viewer: rotate log
  file: rename … being used by another process; write after viewer closed: file already
  closed".
- **Spec:** `Docs/cli/agentnetd.md:21` (log rotates and continues)
- **Fix direction:** on rotation failure reopen the current path in append mode (or retry at the
  next write) instead of leaving `f` nil.
- **Related:** none

### C16-04 · Low · confirmed-read
- **Where:** `cmd/agentnetd/install.go:37-44,122`; `internal/service/schtasks.go:99`,
  `launchd.go:210`, `systemd.go:20`
- **What goes wrong:** install bakes the running binary's path into a service that runs at
  every logon as the user, without checking that the binary and its directories are writable
  only by the user (or admins/root), as D24 requires for scope programs.
- **Scenario:** the owner unpacks `agentnetd.exe` to `C:\tools\` (a drive-root folder inherits
  `Authenticated Users:(M)`) and runs `agentnetd install`; another OS user replaces the
  binary; at the victim's next logon it runs as the victim (keys, DB, approval). Needs the
  owner's choice of an unsafe folder, hence Low.
- **Spec:** none for the daemon binary (D24 / device.md §program checks cover scope programs only)
- **Fix direction:** reuse the `internal/device` program-ownership check at install and warn or
  refuse; `doctor` could check it too.
- **Related:** D24, O-161

### C16-05 · Low · confirmed-read
- **Where:** `internal/paths/paths.go:43,69-72`
- **What goes wrong:** on Windows the pipe name hashes the path string exactly as given
  (after `filepath.Abs`), so two spellings of the same directory (case, 8.3 short name,
  `subst` drive, junction) give two pipe names and two daemons can run on one config dir.
- **Scenario:** the task runs `agentnetd run --home C:\Users\Yazan\…\dorylinae`; the user (or a
  script with `DORYLINAE_HOME=c:\users\yazan\…`) runs a second `agentnetd run`; the "second
  daemon refuses to start" rule does not fire; both open the same DB and keys and connect
  to the relay as the same identity (connection flapping, duplicate outbox sends, two
  approval stores). The CLI with one spelling cannot see the other daemon.
- **Spec:** `Docs/protocol/ipc.md` §Endpoint, "A second daemon on the same endpoint refuses to start."
- **Fix direction:** canonicalise the dir before hashing (`GetFinalPathNameByHandle` on the
  opened dir, lower-cased), or add a lock file in the dir.
- **Related:** none

### C16-06 · Low · suspected
- **Where:** `internal/service/systemd.go:20-24,72-75`; `internal/service/schtasks.go:58-62,99-101`
- **What goes wrong:** service definitions do not reject control characters: a `\n` in a
  Unix exe/home path passes `systemdQuote` unchanged and ends the `ExecStart=` line
  (the rest becomes new unit directives); on Windows Task Scheduler expands `%VAR%` in
  `<Arguments>` and `<WorkingDirectory>`, so a home path containing `%…%` is rewritten.
- **Scenario:** only with an owner-chosen home or binary path containing a newline or a
  `%NAME%` pair; no remote actor controls these paths. Unconfirmed: I did not register a
  task to verify the expansion.
- **Spec:** none
- **Fix direction:** reject control characters (and on Windows `%`) in `Spec` paths in
  `Install`, as `checkUnix`/`isWindowsAbs` already reject relative paths.
- **Related:** none

### C16-07 · Info · confirmed-read
- **Where:** `internal/ipc/ipc_test.go`
- **What goes wrong:** no test covers the 1 MiB request line limit (`errLineTooLong` response)
  or the 30 s idle close; `TestSecondListenerRefused` covers a same-user second listener only,
  not a pipe owned by another principal (C16-01).
- **Scenario:** a regression in `readLine` would go unnoticed.
- **Spec:** `Docs/protocol/ipc.md` §Framing
- **Fix direction:** add a test with a 1 MiB + 1 line.
- **Related:** O-178

### C16-08 · Info · confirmed-read
- **Where:** `internal/paths/paths.go:56-66`, `internal/logfile/logfile.go:40`
- **What goes wrong:** on Windows the config dir and the log file get no DACL (mode bits are
  ignored); they inherit the parent's ACL. `Docs/cli/agentnetd.md:21` says the log is
  "created with owner-only permissions", true only under a private parent such as `%APPDATA%`.
- **Scenario:** `--home D:\agentnet` → DB and log readable/modifiable by `Authenticated Users`.
  Owner-chosen path; `doctor` warns (doctor.md:30); keys have their own DACL.
- **Spec:** `Docs/cli/agentnetd.md:21`; ipc.md §Endpoint ("Config dir is 0700", Unix only)
- **Fix direction:** set a protected owner-only DACL in `Ensure` on first creation, or fix the doc.
- **Related:** O-030

## Assumptions and contracts

- `relayclient.CheckURL` enforces https/wss except explicit loopback and returns `insecure`
  only when `allowInsecure` is set (`cmd/agentnetd/relayurl.go:29`). **Unchecked** (C-relayclient; O-023).
- `relayclient.LoadRoots` returns an error when the PEM holds no certificate and adds to the
  system roots (`relayurl.go:47`). **Unchecked** (O-017 records the "adds" part).
- `daemon.RunWithOptions` calls `p.Ensure()` before `ipc.Listen`, so the socket's parent is
  0700 when the socket is created. **Checked**: `internal/daemon/daemon.go:269,282`.
- The daemon registers IPC handlers that return `*ipc.Error` only with messages safe to show
  and never block forever on the server ctx (`ipc.go:176`; handlers get the server ctx, not a
  per-connection ctx, so a client disconnect does not cancel them). **Unchecked**.
- A panicking handler is recovered somewhere: `serveConn`/`dispatch` have no `recover`
  (`ipc.go:138-189`), so a handler panic would crash the daemon. **Unchecked** (lead).
- `audit.Append` detail for `service.install` holds no paths (`install.go:159`). **Checked**:
  `serviceAuditDetail` has only platform/custom_home/changed (`install.go:50-54`).
- `store.Open` in `recordAudit` runs after the service started the daemon (O-169). **Checked**, known.
- `daemon.StopWait` uses `ipc.Call` against the same endpoint (`stop.go:44`); inherits C16-01.

## Checked and fine

- IPC error responses never carry handler error text except `*ipc.Error` (`ipc.go:176-187`).
- Results encoded with HTML escaping off, as ipc.md §Framing requires (`ipc.go:197-205`).
- Unix `Listen` removes only a socket nothing answers on and creates it under umask 0177
  (`transport_unix.go:17-35`); the umask is restored immediately.
- Windows pipe: owner-SID-only protected DACL, remote clients rejected, anonymous client
  impersonation level (go-winio v0.6.2 `pipe.go:237-279,372`).
- `Plan.Apply` stops at the first failure and still removes the Task XML (`service.go:124-172`,
  `schtasks.go:38`); the XML (holding only paths/user) is written 0600 in the config dir.
- `windowsQuote` doubles backslashes before quotes and at the end (`schtasks.go:110-134`).
- `systemdQuote` escapes `%` and `$` against specifier/variable expansion (`systemd.go:72-75`).
- Install refuses remote `ws://` without an escape hatch (`install.go:95-100`); a bad
  `--relay-ca` exits 2 before anything is written (`install.go:101-109`).
- `--dry-run` writes nothing, not even the config dir (`install.go:134-141` before `Ensure`).
- Install/uninstall audit detail is path-free (R44 L4 closed; `install.go:47-54`).
- `logfile` never splits one write across files and caps at about 2× limit (`logfile.go:55-68`).
- O-203 still open (no socket path length check).
- `internal/config` is still an empty placeholder (`internal/config/doc.go`; O-032).

## Notes

- `syscall.Umask(0o177)` is process-wide; any goroutine creating a directory during that
  window gets mode 0600 (no x bit). Nothing seems to run concurrently at that point today.
- Unix `Listen`: if a live daemon's accept backlog is full, the probe dial fails and the live
  socket is removed (two daemons). Needs a flood by the same user; not reported.
